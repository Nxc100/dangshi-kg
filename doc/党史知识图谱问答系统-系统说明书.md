## 一、系统概述

### 1.1 系统目的

本系统面向高校学生与党员学习者的党史学习教育场景，将分散于权威文献中的党史知识（重大事件、重要会议、党史人物、组织沿革、经典文献、历史时期）组织为结构化知识图谱，并在其上提供自然语言智能问答、知识图谱可视化浏览、大事记时间轴、实体百科、自动知识测验、每日学习等功能，构成"问—学—练—测"的完整学习闭环。

系统的三点核心价值主张：

1. **答案权威可靠**：全部知识来自权威公开出版物与官方网站（人民网、共产党员网、中央党史和文献研究院等），核心知识池经人工校验并逐条回原文交叉复核；系统不做生成式编造，图谱未收录的问题以权威资料原文段落回应并标注出处。
2. **答案可解释、可溯源**：每条答案附带"知识溯源"局部子图与可点击的实体链接，用户可看到答案在知识网络中的位置并继续探索。
3. **知识可持续运营**：管理员可在线维护图谱（实体与关系的增删改），后台修改前台即时生效，所有写操作留痕审计。

### 1.2 系统类型与能力边界

本系统为**限定领域模板式知识图谱问答系统（KBQA）**，能力边界 = "15 类意图模板 × 图谱收录知识"：

- 边界内：15 类意图覆盖的党史事实性问题（问时间、地点、内容、意义、领导人、参会者、作者、作品、人物事迹、时期事件、组织沿革、职务、实体介绍，以及两类固定模式的两跳问题）。
- 边界外：开放域自由问答、观点评价、多于两跳的复杂推理。此类输入由 F9 返回权威资料原文段落；在 AI 增强开启时，由受约束的大模型基于这些段落生成回答并经忠实度校验。
- 系统不生成图谱与语料之外的任何内容；图谱命中的答案永不经大模型改写。

### 1.3 用户角色

| 角色 | 编码 | 定义 | 获得方式 |
|---|---|---|---|
| 游客 | R1 | 未登录访问者，可浏览、提问、试做测验，不可保存个人数据 | 直接访问 |
| 注册用户 | R2 | 登录学习者，R1 全部能力 + 提问历史、收藏夹、测验记录、资料/头像/密码管理 | 注册，`role=user` |
| 管理员 | R3 | R2 全部能力 + 后台知识管理、操作日志、用户管理、问答日志、热点统计、AI 模型配置 | 初始化脚本预置 `admin`；后续由管理员授予 |

三角色逐级包含。权限在服务端由 JWT 载荷中的 `role` 与每请求重载的用户状态共同判定，前端仅按角色渲染入口。

### 1.4 功能模块总览

```
党史学习智能问答系统
├── 前台（学习者）
│   ├── F1 智能问答          —— 自然语言提问，结构化、可溯源地回答（核心）
│   ├── F2 知识图谱可视化    —— AntV G6 力导向图交互浏览
│   ├── F3 党史大事记时间轴  —— 按七个历史时期纵览事件
│   ├── F4 实体百科页        —— 实体的结构化"数字名片"，各功能统一跳转落点
```

### 2.2 选型决策与理由（论文"技术选型"素材）

| 事项 | 决策 | 理由 |
|---|---|---|
| 用户数据库 | SQLite | Python 内置零安装；SQLAlchemy ORM 保持数据库无关设计 |
| 动态页面爬取 | 不用 Playwright/Selenium 作为采集手段 | 数据源全部为静态 HTML；开发期仅允许用浏览器工具**观察**页面结构定位问题，结论回写 `data/sources.md` 并由 requests 复现 |
| 意图分类 | 主线为规则法；朴素贝叶斯与线性 SVM 仅作离线对比实验 | 限定领域、封闭意图集，规则可解释可控；实验完整性由 sklearn 对比满足 |
| 实体识别 | 领域词典 + jieba 自定义词典 + 三级降级链接，不用 BiLSTM-CRF / BERT | 实体集封闭（千级），结果可控可解释；论文中与序列标注方法做原理性对比 |
| 精确匹配 | 最长匹配扫描 + 哈希查找，不用 AC 自动机 | 千级实体无需自动机，减少依赖 |
| "时期"建模 | 独立实体节点 Period | 时期列举问答与测验干扰项均落为标准图查询 |
| "组织"实体 | 纳入本体第二类实体 | 对齐任务书五类核心实体要求，支撑组织沿革问答与测验 |
| 图谱可视化库 | AntV G6 v5（原 ECharts） | 图数据专用：d3-force 布局、邻接聚焦、标签分级、拖拽钉住；ECharts 保留做统计图表 |
| LLM 增强 | 可选、可降级、可物理移除的独立包 | 全项目唯一外部依赖；关闭态行为与原方案逐字节一致，断网可完整演示 |

### 3.2 分层设计原理

**（1）前后端分离。** 前端为 Vue 3 单页应用，通过 Vite 代理将 `/api` 与 `/static` 转发至 Flask；生产态可静态打包部署。前后端契约为统一返回体 `{code, msg, data}`，HTTP 状态码与 `code` 同步。

**（2）后端三层：蓝图 → 服务 → 数据。** 蓝图层只做鉴权装饰、入参校验与透传；服务层承载全部业务逻辑与数据访问；`common/` 提供横切能力。任何 Cypher 与 SQL 不得出现在蓝图层。

**（3）问答引擎独立成包。** `qa/` 不依赖 Flask 请求上下文，只依赖 `backend.extensions` 的图连接与 `graph_service` 的子图组装；命令行版 `python -m qa.cli` 与接口 `POST /api/qa` 共用唯一入口 `qa.pipeline.answer()`，保证评测与线上行为一致。

**（4）双存储各司其职。** 知识（实体、关系、属性）只存 Neo4j；用户与运行数据（账号、收藏、日志、测验、配置）只存 SQLite。两者通过实体主名（`name`）与 `qa_log.id` 弱引用，无跨库外键。后台知识写操作采用"SQLite 写日志 flush → Neo4j 事务提交 → SQLite 提交"的写序保证审计日志与图谱状态一致。

**（5）单一来源原则（Single Source of Truth）。** 本体常量（`backend/common/ontology.py`，前端 `ontology.js` 由脚本生成）、约束索引（`kg/importer/schema.cypher`）、表结构（`backend/models.py`）、数据源入口（`data/sources.md`）、统计口径（`stats_service`）、知识写入口（`kg_admin_service`）、子图结构（`graph_service`）、LLM 配置写入口（`llm_admin_service`）各自唯一。

**（6）常驻资源一次加载。** 实体词典（含 jieba 用户词典）、TF-IDF 矩阵、意图规则表、Cypher 模板在 `create_app()` 加载一次常驻内存；词典以"构建新表 → 原子替换引用"方式热刷新，读方无锁。

**（7）可降级设计。** Neo4j 未连接不阻断启动（首页、时间轴、统计等有降级路径，问答走兜底）；LLM 五类失败（未配置 / 用户关闭 / 超时 / 报错 / 校验不过）一律无感回落到原路径；问答日志写入失败不影响答案返回。

**（8）答案零编造。** `answer_text` 只能由第⑧步模板基于第⑦步图查询结果生成；F9 只展示原文段落；LLM 生成必须通过年份、实体、引用三项程序化校验，且图谱命中的答案永不经 LLM。

### 3.3 核心数据流

**问答请求数据流：**

```
用户输入 → 前端 questionError 校验 → POST /api/qa {question, use_llm, prev_q, prev_a}
→ validate_question(非空/≤100/非纯符号) → optional_user 识别登录态
→ qa.pipeline.answer(question, ctx)
    → ①~⑧（命中）→ answer_text + entities + subgraph，answer_source=kg
    → 未命中 → fallback.retrieve → 段落（answer_source=passage）
                → 三条件满足 → llm.generator → checker → answer_source=llm
→ strip_meta → qalog_service.write_log（每问必写，游客 user_id=NULL）
→ 返回 {answer_text, intent, entities, subgraph, fallback, log_id, candidates, clarify,
        rewritten_from, answer_source, fallback_passages, llm}
```

**知识运营数据流（后台改前台即时生效）：**

```
管理员表单 → POST/PUT/DELETE /api/admin/entity|triple → @admin_required
→ 本体校验（必填 / 枚举 / 头尾约束 / 跨标签唯一）→ timeparse 派生 time_sort
→ kg_admin_service._write：op_log flush → Neo4j execute_write → SQLite commit
→ dictionary.reload()（新增 / 改名 / 删除）
→ 前台问答 / 百科 / 图谱下一次请求即为最新值（图谱数据无应用层缓存）
```

**数据链路（离线）：**

```
kg/crawler（6 源，留档 data/raw/）→ kg/extract（clean / timeparse / parse_events / parse_ttd /
build_corpus / build_entities / build_relations）→ data/clean/*.csv
→ db/merge_sources（种子 → DR-11 确认 → 核心池 → 自动池 四层合并）→ db/build_seed → data/excel 七表 + alias.xlsx
→ kg/importer/import_all --schema --prune → Neo4j → kg/importer/verify（七项验收）
```

## 五、本体模型与 Neo4j 知识图谱设计

### 5.1 实体类型（7 类节点标签）

节点标签用英文，属性值为中文。`*` 必填，`†` 由后端自动派生（表单不填）。

| 标签 | 中文 | 颜色 | 属性 | 示例 |
|---|---|---|---|---|
| Person | 人物 | `#C0392B` | name*、alias、birth_year、death_year、birthplace、intro*、source* | 毛泽东 |
| Organization | 组织 | `#E67E22` | name*、alias、found_time_text、time_sort†、org_type*（政党/军队/群团/机构）、intro*、source* | 八路军 |
| Event | 事件 | `#2E86C1` | name*、alias、time_text*、time_sort*†、time_precision*†（day/month/year）、content、meaning、intro*、source* | 秋收起义 |
| Meeting | 会议 | `#8E44AD` | 与 Event 相同的 9 个属性 | 遵义会议 |
| Location | 地点 | `#27AE60` | name*、alias、modern_name、source | 瑞金 |
| Document | 文献 | `#B7950B` | name*、alias、pub_time_text、time_sort†、doc_type（著作/报告/决议/宣言/章程）、intro、source* | 《论持久战》 |
| Period | 时期 | `#7F8C8D` | name*、start_year*、end_year、order*（1–7） | 土地革命战争时期 |

系统维护属性：`checked`（0/1，核心池标记，测验出题与每日推荐只取 1）、`updated_at`（最近更新时间）。

**设计说明（答辩问点）：**
- 会议从事件中独立建类：其属性结构与问答/测验模板（问时间、地点、参会者、形成文献）高频且专属。
- 时期建为实体而非属性："某时期有哪些大事"类列举查询与测验干扰项均落为标准图查询，消除属性/实体两种表述并存。
- 人物出生地保留为属性而非关系，控制图谱复杂度。
- 实体主名跨标签全局唯一：`name` 是百科 URL、词典、子图 `id`、收藏 `ref_id` 的唯一键，导入与后台新增均校验跨标签重名。

### 5.4 时间三字段制

| 字段 | 含义 | 规则 | 示例 |
|---|---|---|---|
| time_text | 原文时间表述 | 逐字保留 | 1935年1月15日至17日 |
| time_sort | 8 位排序键（字符串） | 取起始日 `YYYYMMDD`；仅到月补 `99`；仅到年补 `9999` | 19350115 / 19350199 / 19359999 |
| time_precision | 精度 | day / month / year | day |

补位规则保证"仅年/仅月条目排在当年/当月末尾"且字符串比较无歧义；`time_sort` 禁止存整数或日期类型（每日学习依赖 `substring(time_sort, 4, 4)` 取月日）。唯一实现在 `kg/extract/timeparse.py`，支持中文数字（"一九二一年七月二十三日"）与 ISO 格式。

### 5.5 Neo4j 约束与索引（`kg/importer/schema.cypher` 全文）

```cypher
// 七类实体主名唯一约束（自动附带索引，保证 name 点查毫秒级）
CREATE CONSTRAINT person_name   IF NOT EXISTS FOR (n:Person)       REQUIRE n.name IS UNIQUE;
CREATE CONSTRAINT org_name      IF NOT EXISTS FOR (n:Organization) REQUIRE n.name IS UNIQUE;
CREATE CONSTRAINT event_name    IF NOT EXISTS FOR (n:Event)        REQUIRE n.name IS UNIQUE;
CREATE CONSTRAINT meeting_name  IF NOT EXISTS FOR (n:Meeting)      REQUIRE n.name IS UNIQUE;
CREATE CONSTRAINT location_name IF NOT EXISTS FOR (n:Location)     REQUIRE n.name IS UNIQUE;
CREATE CONSTRAINT document_name IF NOT EXISTS FOR (n:Document)     REQUIRE n.name IS UNIQUE;
CREATE CONSTRAINT period_name   IF NOT EXISTS FOR (n:Period)       REQUIRE n.name IS UNIQUE;

// 时间排序索引（时间轴按 time_sort 升序、每日学习按 MMDD 筛选）
CREATE INDEX event_time   IF NOT EXISTS FOR (n:Event)   ON (n.time_sort);
CREATE INDEX meeting_time IF NOT EXISTS FOR (n:Meeting) ON (n.time_sort);

// 核心池标记索引（测验出题与每日推荐一律 WHERE n.checked = 1）
CREATE INDEX event_checked    IF NOT EXISTS FOR (n:Event)        ON (n.checked);
CREATE INDEX meeting_checked  IF NOT EXISTS FOR (n:Meeting)      ON (n.checked);
CREATE INDEX person_checked   IF NOT EXISTS FOR (n:Person)       ON (n.checked);
CREATE INDEX org_checked      IF NOT EXISTS FOR (n:Organization) ON (n.checked);
CREATE INDEX document_checked IF NOT EXISTS FOR (n:Document)     ON (n.checked);
CREATE INDEX location_checked IF NOT EXISTS FOR (n:Location)     ON (n.checked);
CREATE INDEX period_checked   IF NOT EXISTS FOR (n:Period)       ON (n.checked);
```

实测：7 个唯一约束 + 18 个索引（7 个约束附带的 name RANGE 索引、2 个 time_sort、7 个 checked、2 个系统 LOOKUP），全部 ONLINE。

采集纪律：只采权威官方公开静态页；请求间隔 ≥ 2 秒（`MIN_INTERVAL=2.0`）、常规浏览器 UA；原始 HTML 全量留档 `data/raw/`（解析可离线重跑）；断点续爬 `done.txt`；只留档 HTTP 200；编码以页面 `meta charset` 为准、域名规则兜底（`detect_encoding()` 唯一实现）；每条入库知识记 `source`。

### 6.2 采集脚本要点（`kg/crawler/`）

- `common.py`：`fetch()` 已留档则读本地不再抓取；留档文件名 `<host>_<md5(url)[:12]>.html`；`raise_for_status()`；`write_csv` 统一 `utf-8-sig`。
- `dsj_crawler.py`：单页全文，备用求是网镜像。
- `jianshi_crawler.py`：目录页 `<a>` 文本匹配 `第[一二三…十]+章` 枚举 10 章。
- `meeting_crawler.py`：`<a>` 文本匹配 `第X次全国代表大会|党的X大` 枚举 20 页。
- `person_crawler.py`：href 匹配 `/GB/69112/\d+/`，下钻"生平简介/大事年表"子页。
- `ttd_crawler.py`：首页 href `^/GB/434461/(4344[6-7]\d)/(\d+)/index\.html$`，月 = 栏目 ID − 434462 + 1；正文在裸 `<div>`（滚动容器）。
- `check_sources.py`：DR-06 逐入口探测可达性、编码、结构，留档 `data/raw/dr06/`。

### 6.3 清洗与标准化（`kg/extract/clean.py`、`timeparse.py`、`period_assign.py`）

1. 文本清洗：去 HTML 标签与零宽字符，全角数字/字母/部分标点归一为半角（保留中文引号书名号），空白归一；`split_paragraphs` 滤除 < 30 字段落。
2. 时间标准化：三字段制（5.4 节）。
3. 时期归属：`assign(time_sort)` 按 `PERIODS.start_sort` 升序取最后一个 ≤ 的时期；早于 1921-07-01 返回 None 不挂边。
4. 实体名规范：以权威来源全称为主名，简称/俗称/旧称进别名表 `alias.xlsx`；别名一对多歧义拒绝入库。

### 6.4 编年条目解析（`parse_events.py`、`parse_ttd.py`）

- 大事记：`YEAR_LINE ^(1[89]\d{2}|20\d{2})\s*年$` 驱动年份上下文；`DATE_HEAD` 匹配 `M月D日(－至D日)? | M月 | 本年 | 春夏秋冬`；描述 ≥ 8 字；输出 `events_raw.csv`（年份、日期原文、条目正文、来源 URL、time_sort、time_precision、所属时期）。
- 天天读：三板块（重要论述 / 党史回眸 / 历史瞬间）按容器直接子节点"标记块 + 正文块"成对读取；按（年，日期，正文）去重；输出 `ttd_raw.csv` 3,531 条（重要论述 2,022 / 党史回眸 1,253 / 历史瞬间 256）。

### 6.5 F9 语料构建（`build_corpus.py`）

来源优先级（重复段保留先者）：简史 `<p>` 正文（章节标题从页面标题提取）→ 人物页 → 党代会页 → 天天读（复用已解析条目 + 叶子 `<div>` 补收未覆盖段，避免同一史实出现两份）→ 大事记条目（拼为"YYYY年M月D日，正文"）。噪声正则过滤（上一篇/下一篇/责任编辑/版权所有…）。产出 `data/corpus/paragraphs.csv`（列 `text, chapter, source`）**6,496 段**：天天读 3,397 + 天天读补收 1,341 + 大事记 1,015 + 简史 679 + 党代会 60 + 人物 4；出处 100%。

### 6.6 自动实体构建（DR-13，`lexicon.py` + `build_entities.py`）

**命名闸门（`lexicon.py` 唯一定义）——名称要么逐字完整、要么按后缀可判定，绝不靠猜边界：**

| 类型 | 规则 |
|---|---|
| 事件 / 会议 | **整句成名**：反复剥离日期/时段前缀后取首句（按 `[。！？；]` 切）为名，8–50 字；含冒号、状语连词开头、助词收尾、书名号括号不配对 → 整条弃用，不在句中截取片段（弃用条目仍作 F9 语料） |
| 组织 | 只收以机构后缀收尾的完整词：`ORG_TAIL_LONG`（委员会/办公厅/指挥部/司令部/方面军/纵队/军区/国务院/党校/大学…）3 字起，`ORG_TAIL_SHORT`（党/团/军/师/旅/政府/部/局/署/厅/司/处/院/社/盟）4 字起；`NOT_ORG` 同形普通词黑名单；且须在 ≥ 2 条独立条目中出现 |
| 地点 | `PLACE_TAIL`（省/市/县/区/镇/州/旗/自治区/边区/苏区/根据地/解放区/山/岭/江/河/湖/岛/湾/关/桥/港）3 字起；两字地名只认 `KNOWN_PLACES` 人工登记表（约 190 项） |
| 文献 | 只收书名号内 4–40 字完整跨度；排除文种通名（决议/决定/通知…）、报刊名、含空格/逗号者；`doc_type_of` 后缀规则 → 宣言/章程/决议/报告，默认著作 |
| 人物 | **不做自动识别**（jieba 把"文明""宣言"标 nr、"周恩来"标 t，正反两类错误无法稳定滤除），一律人工登记 |

自动池实体的 `intro`/`content` 逐字引用原文（前 900 字）并记 `source`，`checked=0`。输入两份编年条目 4,574 条，产出 `entities_auto.csv` **4,063** 个（Event 2,400 / Document 1,257 / Location 220 / Organization 186）。

### 6.7 自动关系构建（DR-14，`build_relations.py`）

关系必须由原文中的**显式触发词**支撑，不做共现推断；以事件为头的关系只在**条目首句**取证。名录 = 种子 + DR-11 确认 + 核心池 + 自动池（含别名→主名），编译长词优先的交替正则，`GAP=14`。七条规则：

```
OCCURRED_IN      在{loc}[^，。；]{0,14}?(召开|举行|成立|爆发|…|逝世|签署|发射|阅兵)     ；"在京…" → 北京
FOUNDED          (宣告成立|正式成立|成立|建立|组建|设立|创建|创办)(了)?{org}(?!的|领导|所属|系统)
AUTHORED         {per}…(发表|撰写|起草|写|作|发布|签发)…《{doc}》
HELD_POSITION    {per}(当选为|当选|被任命为|被选为|兼任|任){org}(总书记|书记|主席|…|总司令)
PARTICIPATED_IN  {per}…(出席|参加|列席)…{meet}
PRODUCED         {meet}…(通过|制定|公布|审议通过|批准|颁布|发布)…《{doc}》
LED              ^{per|org}(领导|指挥|发动|率领|发起|主持)(?!机构|机关|班子…)   ← 只在事件名开头
```

产出 `relations_auto.csv` **506 条**（OCCURRED_IN 299 / AUTHORED 146 / LED 38 / FOUNDED 8 / HELD_POSITION 6 / PRODUCED 6 / PARTICIPATED_IN 3）。BELONGS_TO 由导入自动归属；REORGANIZED_TO、任职等编年条目中多为名词短语的关系类型由人工整理（`db/seed_data/core_relations*.py`，共 524 条）。

## 八、问答引擎算法设计（八步管道）

### 8.1 总体流程

问答引擎为独立包 `qa/`，唯一入口 `pipeline.answer(question, ctx)`，`ctx = {use_llm, prev_q, prev_a, user_id}`。第①–④步构成任务书要求的**问句理解模块**（分词 → 词性标注 → 命名实体识别 → 意图分类），第⑤–⑥步为**查询构建模块**，第⑦–⑧步为**答案生成模块**。

```
tokens   = tokenizer.cut(question)                                  # ① 分词
feats    = pos_tagger.features(pos_tagger.tag(question), question)  # ② 词性特征
entities = entity_linker.link(question, tokens)                     # ③ 实体识别与链接（三级降级）
  └ 三级全未中 ∧ 允许改写 ∧ LLM 三条件 ∧ 携带 prev_q → ⓪ 追问改写 → 以改写句重走 ①–⑧（仅一次）
intent   = intent_classifier.classify(question, feats, entities)    # ④ 意图分类
  └ 无实体 → candidates = entity_linker.suggest(question) → 兜底
clarify  = slot_checker.check(intent, entities)                     # ⑤ 槽位校验 → 不符即返回澄清（不查询）
  └ intent == UNKNOWN → 兜底
entity   = slot_checker.pick_entity(intent, entities)
cypher, params = cypher_builder.build(intent, entity)               # ⑥ Cypher 构建（参数化模板）
rows     = graph_query.query(cypher, params)                        # ⑦ 图查询（只读事务）
built    = answer_builder.build(intent, entity, rows)               # ⑧ 答案模板 + 溯源子图
  └ 属性为空 / 查询为空 → "该信息暂未收录" + 兜底段落（keep_text）
```

降级判定：只有"图库不可用"类异常（`Neo4jUnavailable / ServiceUnavailable / SessionExpired / AuthError`）才转兜底；Cypher 语法错误等照常抛 500，不伪装成兜底。

**返回结构（V3 6.3 六字段 + FRS 边界字段 + LLM 增量）：**

```json
{
  "answer_text": "遵义会议召开于1935年1月15日至17日。",
  "intent": "I1",
  "entities": [{"id": "Meeting:遵义会议", "name": "遵义会议", "type": "Meeting"}],
  "subgraph": {"nodes": [...], "links": [...]},
  "fallback": false, "log_id": 1024,
  "candidates": [], "clarify": null, "rewritten_from": null,
  "answer_source": "kg", "fallback_passages": [], "llm": null
}
```

三类边界（未识别实体 → `candidates`；属性缺失 → 固定文案 + 百科入口；槽位不符 → `clarify`）均为 `code=0` 的业务响应，不是错误。内部 `_meta.linked_entities`（第③步主名）是 `qa_log.matched_entity` 的唯一来源，避免溯源子图邻居节点污染高频实体统计。

### 8.2 ① 分词与领域词典

- `jieba.lcut` 精确模式。
- 自定义词典 `qa/resources/userdict.txt` 由 `dictionary.load()` 在启动时从 Neo4j 生成：加载七类标签全部 `name` 与 `alias`（Cypher：`MATCH (n) WHERE labels(n)[0] IN $labels RETURN labels(n)[0], n.name, n.alias`），每行 `词条 1000 nz`，规模 ≈ 4,419 主名 + 160 别名。
- 词典结构 `EntityDict`：`term_map{词条→(主名,类型)}`、`type_by_name`、`names_by_type`、`aliases_by_name`、按长度分桶的词条表、懒构建拼音索引（pypinyin `lazy_pinyin`，无声调）。
- 冲突处理：主名跨标签重复 → 警告跳过；别名与他实体主名同名 → 主名优先；别名一对多 → 剔除。
- 热刷新 `reload()`：构建新表 → 写 userdict → `jieba.load_userdict` → 原子替换引用。五处复用：实体链接、图谱搜索联想、测验干扰项排除、后台联想、LLM 忠实度校验。

### 8.3 ② 词性标注与特征

`jieba.posseg.cut` 输出词/词性序列。提取：
- 疑问词：词性以 `r` 开头且含疑问字（哪/谁/什么/何/几/怎/多少/吗），为空时退化为文本直接出现的疑问字；
- 触发动词：词性 `v` 且在 19 词表内（领导、参加、召开、写、发动、指挥、出席、创作、担任、改编、成立、创建、发生、举行、撰写、通过、任职、介绍…）；
- `has_question` 用于"无疑问词仅实体 → I13 实体介绍"的判定；也是对比实验的附加特征。

### 8.4 ③ 命名实体识别与链接（基于领域词典的三级降级）

论文表述："基于领域词典的命名实体识别与实体链接"，选型理由为实体集封闭、结果可控可解释。输出 `[{name(主名), type, method, matched}]`。

**第一级 精确匹配（两遍）：**
1. **最长匹配优先扫描**（maximal munch）：从每个起点由长到短试子串查词典，命中即"吃掉"该跨度。动机：图谱中两千多个整句式事件名超过 4 个 token，不做此遍会错链到嵌在其中的短实体（如"毛泽东作《改造我们的学习》报告的举办城市"会链成人物"毛泽东"）。
2. 分词结果补漏：单 token 及相邻 2/3/4 token 拼接查词典，位置未被更长命中覆盖时才产出。
   别名命中自动回链主名。

**第二级 模糊纠错：** 对词典中每个词条长度 L（2–16），取问句所有长度 L 的滑动窗口，候选池 = 长度 L−1/L/L+1 的词条，`rapidfuzz.process.extractOne(sub, pool, scorer=fuzz.ratio, score_cutoff=85)`，全局取最高分。容错"尊义会议 → 遵义会议"。

**第三级 同音纠错：** 滑动窗口子串转无声调拼音串，与拼音索引精确比对，首个命中返回。容错同音错字（评测集"遵→尊、会→汇、中→忠"）。

**候选建议 `suggest()`：** 三级全未中时，`process.extract(question, terms, scorer=fuzz.partial_ratio, limit=9)`，过滤 score < 50，按主名去重取前 3，作为"你是不是想问"候选按钮。

### 8.7 ⑥ Cypher 构建（15 模板与注入防护）

实体名一律以 `$name` 参数传入；标签与关系名只从 `ontology.LABELS/RELATIONS` 白名单常量拼入（Cypher 不支持标签参数化）；禁止字符串拼接用户输入。I1 按实体类型分流。模板全文（`INTENT_CYPHER`）：

```cypher
-- I1 问时间（按类型分流）
MATCH (n:Meeting {name:$name})      RETURN n.name AS name, n.time_text AS value
MATCH (n:Event {name:$name})        RETURN n.name AS name, n.time_text AS value
MATCH (n:Organization {name:$name}) RETURN n.name AS name, n.found_time_text AS value
MATCH (n:Document {name:$name})     RETURN n.name AS name, n.pub_time_text AS value
-- I2 问地点
MATCH (n:Meeting {name:$name})-[r:HELD_IN]->(m:Location)     RETURN n.name AS name, m.name AS other, labels(m)[0] AS other_type, properties(r) AS rprops
MATCH (n:Event {name:$name})-[r:OCCURRED_IN]->(m:Location)   RETURN ...
-- I3 问内容 / I4 问意义（Meeting / Event）
MATCH (n:Meeting {name:$name}) RETURN n.name AS name, n.content AS value
MATCH (n:Meeting {name:$name}) RETURN n.name AS name, n.meaning AS value
-- I5 问领导人 / I6 问参会者 / I7 问作者（反向）
MATCH (m)-[r:LED]->(n:Event {name:$name})                     RETURN n.name AS name, m.name AS other, labels(m)[0] AS other_type, properties(r) AS rprops
MATCH (m:Person)-[r:PARTICIPATED_IN]->(n:Meeting {name:$name}) RETURN ...
MATCH (m:Person)-[r:AUTHORED]->(n:Document {name:$name})       RETURN ...
-- I8 问作品 / I9 问人物事迹 / I12 问职务（正向）
MATCH (n:Person {name:$name})-[r:AUTHORED]->(m:Document)       RETURN ... ORDER BY m.time_sort
MATCH (n:Person {name:$name})-[r:LED]->(m:Event)               RETURN ... ORDER BY m.time_sort
MATCH (n:Person {name:$name})-[r:HELD_POSITION]->(m:Organization) RETURN ...
-- I10 时期事件列举
MATCH (m)-[r:BELONGS_TO]->(n:Period {name:$name})              RETURN ... ORDER BY m.time_sort
-- I11 组织沿革（双向，带方向标记）
MATCH (n:Organization {name:$name})-[r:REORGANIZED_TO]-(m:Organization)
RETURN n.name AS name, m.name AS other, labels(m)[0] AS other_type, properties(r) AS rprops,
       CASE WHEN startNode(r) = n THEN 'out' ELSE 'in' END AS direction
-- I13 实体介绍（7 类各一条）
MATCH (n:Label {name:$name}) RETURN n.name AS name, properties(n) AS props
-- I14 两跳：参加 X 会议的人还领导过哪些事件
MATCH (p:Person)-[:PARTICIPATED_IN]->(n:Meeting {name:$name}) OPTIONAL MATCH (p)-[:LED]->(e:Event)
RETURN n.name AS name, p.name AS mid, collect(e.name) AS others ORDER BY mid
-- I15 两跳：《X》的作者担任过什么职务
MATCH (p:Person)-[:AUTHORED]->(n:Document {name:$name}) OPTIONAL MATCH (p)-[r:HELD_POSITION]->(o:Organization)
RETURN n.name AS name, p.name AS mid, collect({org: o.name, position: r.position}) AS others ORDER BY mid
```

`INTENT_RELATION` 记录每意图涉及的（关系，方向）供第⑧步组装溯源子图的边。注入样例 `遵义会议'}) DETACH DELETE (n) //` 作为参数传入不产生任何破坏（`eval/selfcheck_qa.py` 用例）。

列表类答案 ≤ 10 项（`ANSWER_LIST_MAX`），超出显示前 10 并注明"……（共 N 项，显示前 10 项）"；属性为空 → `answer_text = "该信息暂未收录"`，`entities` 携带该实体供百科入口，并附兜底段落。

```
属性类  I1: Meeting "{name}召开于{value}。" / Event "{name}发生于{value}。" / Organization "{name}成立于{value}。" / Document "{name}发表于{value}。"
        I3: "{name}的主要内容：{value}"      I4: "{name}的历史意义：{value}"
```

## 九、权威资料检索兜底（F9）与 AI 增强模块（LLM）

### 9.1 F9 兜底检索算法（`qa/fallback.py`）

- **构建（启动一次，常驻内存）：** 读取 `data/corpus/paragraphs.csv`（text / chapter / source），过滤 < 30 字段落；`TfidfVectorizer(tokenizer=jieba 分词, ngram_range=(1,2))` 构建 TF-IDF 矩阵。实测 6,496 段，词表 229,540。
- **检索：** 问句向量化后 `sims = matrix @ vec.T`（行向量 L2 归一化，点积即余弦相似度），取 top3（`FALLBACK_TOPK`）且 `score ≥ 0.05`（`FALLBACK_THRESHOLD`），返回 `[{text, chapter, source, score}]`。
- **界面：** 固定顶栏"以下为权威资料原文节选，供学习参考"，每段附章节出处与"查看原文"外链；均低于阈值 → 引导语 + 3 条示例问句。断网可用，零外部依赖。

### 9.2 AI 增强模块定位与双层开关

`llm/` 为独立包，不反向 import backend；`qa/` 仅在四处以 `try: from llm import ...` 引用，导入失败即视为系统层关闭。删除 `llm/` 目录 + 还原 `.env` 即**物理回退**到原方案（已实测）。

| 层级 | 开关 | 控制者 | 载体 | 默认 |
|---|---|---|---|---|
| 系统层 | `enabled` + 端点/密钥/模型齐全 | 管理员 | `llm_config` 表（后台"AI 增强"页）▶ 优先；`.env` 五项 ▶ 兜底 | 关 |
| 用户层 | "AI 增强回答"开关 | 每个用户（含游客） | localStorage `llm_pref` | 关 |

`GET /api/config` 只返回 `{llm_available}`（= enabled ∧ key ∧ base_url ∧ model），不回传配置明文；前端仅在 `true` 时渲染开关。

**行为矩阵：**

| 系统开关 | 用户开关 | 命中图谱 | 未命中（兜底） | 追问补全 |
|---|---|---|---|---|
| 关 | （不显示） | 原模板答案 | 权威段落 | 不启用 |
| 开 | 关 | 原模板答案 | 权威段落 | 不启用 |
| 开 | 开 | **原模板答案（不变）** | LLM 生成 + 段落可展开；失败降级为段落 | 启用；改写失败按原句 |

### 9.3 配置注入与客户端

- `llm/config.py`：优先级 宿主注入 `set_override(cfg)`（后台保存配置或启动时 `llm_admin_service.load_into_runtime()` 推入）> `.env` 的 `LLM_ENABLED / LLM_BASE_URL / LLM_API_KEY / LLM_MODEL / LLM_TIMEOUT`（默认 5 秒）；`rewrite_timeout() = min(3, timeout)`；`snapshot()` 脱敏快照。
- `llm/client.py` 唯一外呼 `chat(messages, timeout, max_tokens=300, temperature=0.1)`：requests POST `base_url + "/chat/completions"`（OpenAI 兼容），Bearer 头；网络异常、非 200、超时、解析失败、空文本**一律返回 None** 并记录原因——降级判断收敛于"是否为 None"一处。
- 厂商预设 `backend/common/llm_providers.py`（不含密钥）：通义千问（`dashscope.aliyuncs.com/compatible-mode/v1`）、智谱 GLM、DeepSeek、Kimi、自定义端点。

### 9.4 FR-L02 兜底受约束生成（`generator.py`）

流程：取前 3 段 → `_clean()`（归一空白、去注入短语正则 `忽略(以上|上述|前面)…(指令|要求|规则)|ignore (the )?(above|previous)|system[:：]|assistant[:：]`、截 500 字）→ 编号拼入提示词 → `chat(max_tokens=300)` → 回答 > 300 字直接降级（截断会切掉末尾引用）→ `checker` → 通过则 `answer_source=llm`，响应附 `llm:{text, cited, latency_ms}`。`detail.degraded_reason ∈ {no_passage, client_none, too_long, check:<原因>}` 写入 `qa_log.llm_detail` 供审计。

**系统提示词定稿（`prompts.py`）：**
```
你是党史学习系统的辅助回答助手。严格遵守以下规则：
1. 只能依据下面给出的编号资料作答，不得使用资料之外的任何知识；
2. 资料未涉及或无法确定时，只输出："根据现有资料无法回答该问题。"；
3. 不得编造或推测任何年份、人物、地点、数字；
4. 用简体中文回答，不超过150字，语言平实准确；
5. 回答末尾用方括号标注所依据的资料编号，如[1][2]。
【资料】[1] 段落（出处：…）[2] … [3] …
【问题】{用户问句}
```
进入提示词的只有三类受控文本：本地权威语料段落、用户问句（≤ 100 字）、上一轮问答摘要；不拼接任何网页实时内容。

### 9.5 FR-L03 追问改写（`rewrite.py`）

触发：第③步三级全未中（有实体即不触发）且请求携带 `prev_q`；指代词表（它/他/她/这/那/这次/那次/该会议/该事件/此人…）仅用于日志分类。`prev_a` 截 200 字，`max_tokens=120`，超时 `min(3, LLM_TIMEOUT)`。`_sanitize`：去引号书名号、取首行、多句取第一句、非空且 ≤ 100 字，否则失败按原句继续。改写成功后以改写句重走 ①–⑧（仅一次），响应附 `rewritten_from`，**答案仍由图谱产出**。

提示词：
```
你是问句改写助手。根据上一轮对话，把用户的新问题改写成一句不依赖上下文、指代明确、语义完整的独立问句。
只输出改写后的问句本身，不输出任何解释；若新问题本身已完整或与上一轮无关，原样输出新问题。
【上一轮问题】{prev_q}【上一轮回答】{prev_a}【新问题】{cur_q}
```

### 9.6 忠实度后校验（`checker.py`，程序化闸门）

三项任一不过整体降级：
1. **引用校验**：`\[(\d)\]` 提取，至少一个 n ∈ [1, 段落数]；
2. **年份/日期校验**：`\d{3,4}\s*年` 与 `\d{1,2}\s*[月日]` 的每个 token 须出现在**所引段落**原文中；
3. **实体校验**：遍历实体词典 ≥ 2 字词条，出现在回答但主名与别名均不在所引段落 → 失败（词典不可用时进程内告警一次并跳过）。
固定拒答句"根据现有资料无法回答该问题。"免检放行。校验将"提示词约束"升级为"可验证约束"，保证上屏的年份与实体均有原文支撑——党史领域接入生成式能力的合规底线。

### 9.7 五类降级

无 key / 用户关闭 / 超时 / 报错 / 校验不过 → 一律无感回落为原路径的段落展示，**不弹错误**。`qa_log` 记录 `answer_source`、`llm_latency_ms`（含失败尝试耗时）、`llm_detail`；"是否经过降级" = `answer_source='passage' ∧ llm_latency_ms IS NOT NULL`。

## 十、其他核心算法设计

### 10.1 测验自动出题算法（`quiz_service.py`，F7）

六个出题模板，**只从 `checked=1` 核心池取三元组**：

| 模板 key | 三元组（subject → answer） | 题干 | 干扰项来源 |
|---|---|---|---|
| meeting_time | Meeting.time_text | {会议}召开于____ | 其他核心会议的 time_text |
| meeting_place | Meeting-[:HELD_IN]->Location | {会议}的召开地是____ | 其他核心地点 |
| event_leader | Person-[:LED]->Event | ____领导了{事件} | 其他核心人物 |
| document_author | Person-[:AUTHORED]->Document | {文献}的作者是____ | 其他核心人物 |
| event_period | Event-[:BELONGS_TO]->Period | {事件}发生于____ | 其他 Period |
| org_reorganize | Org-[:REORGANIZED_TO]->Org | {组织}由____改编而来 | 其他核心组织 |

出题流程 `generate(n, entities)`：
1. 六模板各执行一次三元组查询（如 `MATCH (m:Meeting)-[:HELD_IN]->(l:Location) WHERE m.checked = 1 RETURN m.name AS subject, l.name AS answer`），结果洗牌缓存；
2. `entities` 非空（"针对错题再练"）时构造优先列表，先出这些实体的题；
3. 循环至凑满 n 题或尝试 60 次：随机选模板弹出候选，模板耗尽即移除（自动切换其余模板）；
4. `_make_question`：**答案唯一性校验**（如 `MATCH (m:Meeting {name:$subject})-[:HELD_IN]->(l) RETURN count(DISTINCT l)` = 1 才出题）→ 干扰项池排除正确答案及其**主名与全部别名**（取自词典）→ 池 < 3 放弃 → 抽 3 个干扰项 + 正确答案洗牌 → `answer_key` A–D；附 `explanation`（对应图谱事实一句话）与 `entity` 供百科复习；
5. 不足 n 题返回 500 说明（不静默少发；数据验收后不会发生）。

判分 `submit()`：题目数与作答数一致；逐题 `chosen == answer_key` 计分，**后端复算，不信任前端得分**；`detail_json` 存逐题详情与用时。数据支撑度实测六题型可出题数：65 / 65 / 32 / 50 / 160 / 8。

### 10.2 每日学习算法（`daily_service.py`，F8）

- **今日推荐**：`seed = int(YYYYMMDD)`，`random.Random(seed).choice(核心池按 name 排序列表)`——全站当日一致、跨日 0 点变化、确定性可复现；核心池为空时回落全部实体前 500。
- **历史上的今天**：`MATCH (e) WHERE labels(e)[0] IN ['Event','Meeting'] AND e.time_precision = 'day' AND substring(e.time_sort, 4, 4) = $mmdd ... ORDER BY e.time_sort`；无匹配时前端整栏隐藏，以运行时逻辑消除数据稀疏风险。
- Neo4j 不可用返回 `degraded: true`，首页降级为固定引导语 + 示例问句。

### 10.3 图谱子图与搜索联想（`graph_service.py`，F2）

- **子图契约**：`{nodes:[{id,name,type}], links:[{source,target,relation,label}], truncated, center}`，`id = "{label}:{name}"`；图谱页 2 跳、百科 1 跳、问答溯源三处同构。
- **2 跳子图**：`MATCH (c:Label {name:$name})-[rs*1..2]-() UNWIND rs AS r WITH DISTINCT r, c MATCH (a)-[r]->(b) WITH ..., CASE WHEN a = c OR b = c THEN 0 ELSE 1 END AS hop ORDER BY hop, a.name, b.name RETURN ... LIMIT $edge_limit`（一跳优先，`edge_limit = limit × 4`）；节点超过 100 上限时 `truncated=true` 并丢弃后续节点；孤立节点返回仅含自身的 nodes 与空 links。
- **邻居增量**：`neighbors(name) = subgraph(hops=1)`，前端合并去重后追加，总节点仍受 100 约束。
- **搜索联想**：基于词典词条三级排序——前缀匹配 → 包含匹配 → `rapidfuzz.partial_ratio ≥ 60` 模糊；别名命中回链主名去重，返回 ≤ 10 条 `{name, type}`。
- 图谱数据不做应用层缓存，后台改动下一次请求即最新。

### 10.4 百科页聚合（`entity_service.py`，F4）

按七标签 UNION ALL 查找主名（不存在 → 404）→ 1 跳邻居查询（`MATCH (n)-[r]-(m) RETURN type(r), labels(m)[0], m.name, CASE WHEN startNode(r) = n THEN 'out' ELSE 'in' END AS direction, properties(r)`）→ 按（关系，方向）分组，标题取映射表（如 LED/in = "领导者"、LED/out = "领导的事件"、PARTICIPATED_IN/in = "出席人物"、HELD_POSITION/in = "任职人员"、REORGANIZED_TO/in = "前身"、BELONGS_TO/out = "所属时期"，共 20 项），HELD_POSITION 附 `position`；同时组装 1 跳子图；`props` 只含非空本体属性；登录用户附 `favorited`。

### 10.5 时间轴（`timeline_service.py`，F3）

- `MATCH (p:Period) RETURN ... ORDER BY p.order`（图中无 Period 或未连接时回落本体七时期，页签恒可用）；
- `MATCH (e)-[:BELONGS_TO]->(p:Period {name:$period}) WHERE labels(e)[0] IN ['Event','Meeting'] RETURN ... ORDER BY e.time_sort`；
- 每条附 `brief`（`intro` 按 `[。！？；]` 取首句 ≤ 60 字）；无参一次返回时期列表 + 首时期事件（冷启动一次请求）；仅年/仅月条目由补位规则自然排末尾。
- 前端年份定位：`start_year ≤ year ≤ end_year` 定位页签，滚动到 `time_sort` 前四位 ≥ year 的首条。

### 10.6 热点统计口径（`stats_service.py`，F10）

全部来自 `qa_log` 聚合（不看 `user_visible`）与 Neo4j 计数，无缓存：高频问句 Top10（`GROUP BY question`）；高频实体 Top10（`matched_entity` 按 `|` 拆分计数）；意图分布（`GROUP BY intent`，NULL 显示 UNKNOWN）；近 30 天趋势（按日分组，无记录日期补零）；兜底率 = `fallback=1 ÷ 总数`；LLM 三指标（近 30 天）：调用次数 = `llm_latency_ms IS NOT NULL`，成功率 = `answer_source='llm' ÷ 调用次数`，平均时延 = `AVG(llm_latency_ms)`。后台总览四数字：实体总数、关系总数（Neo4j count）、注册用户数、今日问答量。

### 10.7 后台知识写链路（`kg_admin_service.py`，F6）

**实体：**
- 新增：跨标签主名唯一（已存在 → 422 "实体已存在，是否前往编辑？" + `data.exists_type`）；表单只填时间文本，后端 `timeparse` 派生 `time_sort`/`time_precision`（失败 → 422 "时间格式无法识别，请按「1935 年 1 月 15 日」格式填写"）；`MERGE (n:Label {name:$name}) SET n += $props`，`checked=0`、`updated_at=now`；Event/Meeting 按 `period_assign` 自动 `MERGE (n)-[:BELONGS_TO]->(p:Period)`；`dictionary.reload()`。
- 编辑：`SET n += $props`；改名校验新名全局唯一；`checked` 可置 1；时间变更后先 `DELETE` 旧 BELONGS_TO 再 MERGE 新的。
- 删除：关系数 `MATCH (n)-[r]-() RETURN count(r)` **实时查询**；`≥ 20` 且 `confirm_name ≠ name` → 422 "高连接度实体需输入名称确认"；`DETACH DELETE`；刷新词典。

**三元组：** 头尾不同；`ontology.is_allowed(head_type, rel, tail_type)` 后端复校（与前端三级联动同一份本体数据）；头尾实体存在且类型相符；HELD_POSITION.position 必填；重复 → 422 "该关系已存在"；`MATCH (h) MATCH (t) MERGE (h)-[r:REL]->(t) SET r += $props`。

**双库写序 `_write()`：** SQLite `add(op_log)` + `flush`（不提交）→ Neo4j `execute_write` → SQLite `commit`；Neo4j 失败即 SQLite 回滚；op_log 与知识写操作 1:1。op_log 只可查不可删。

## 十二、后端设计与接口清单

### 12.1 应用工厂与启动（`backend/app.py`）

`create_app(load_resources=True)`：项目根插入 `sys.path` → `Flask(static_folder=backend/static)` → `Config` → 日志（噪声 logger 压到 INFO）→ CORS（`/api/*`、`/static/*`）→ JWT 与错误回调 → `init_db`（SQLAlchemy engine，`PRAGMA foreign_keys=ON`，每请求 scoped_session，teardown 释放）→ `init_neo4j`（driver 单例，`connection_timeout=5`，`verify_connectivity`，失败不阻断启动）→ 全局错误处理 → 16 个蓝图统一 `url_prefix="/api"` → `/api/health` → 常驻资源（`dictionary.load()`、`fallback.build()`、`llm_admin_service.load_into_runtime()`）。`load_resources=False` 供建表/导入脚本使用。`main()` 以 `use_reloader=False` 运行避免资源加载两次。

### 12.2 配置（`backend/config.py`）

自实现 `.env` 解析（系统环境变量优先）。关键项：`JWT_ACCESS_TOKEN_EXPIRES=7200`、`JWT_TOKEN_LOCATION=headers`、`NEO4J_URI=bolt://127.0.0.1:7687`（用 127.0.0.1 避免 Windows 上 localhost 先解析 IPv6 回退超时）、`MAX_CONTENT_LENGTH=2MB+64KB`；业务常量：`QUESTION_MAX_LEN=100`、`KW_MAX_LEN=30`、`SUBGRAPH_LIMIT=100`、`FALLBACK_TOPK=3`、`FALLBACK_THRESHOLD=0.05`、`ANSWER_LIST_MAX=10`、`LOGIN_MAX_FAIL=5`、`LOGIN_LOCK_SECONDS=600`、`PAGE_SIZE_DEFAULT=10`、`PAGE_SIZE_MAX=50`、`HIGH_DEGREE_THRESHOLD=20`、`QUIZ_SIZES=(5,10)`。

### 12.3 鉴权三档（`common/auth.py`）

| 档位 | 实现 | 行为 |
|---|---|---|
| 游客可用（可选识别） | `optional_user()` | `verify_jwt_in_request(optional=True)`；无 token / 无效 / 禁用一律返回 None 不抛错 |
| 需登录 | `@login_required` | `_load_current_user()`：每请求重载用户 → 不存在 401 → `status≠1` 401 "账号已被禁用"（禁用后下一次请求即拒）→ `must_change_pwd=1` 且端点不在白名单（仅 `get_profile`、`change_password`）→ 422 "请先修改密码" |
| 需管理员 | `@admin_required` | 上述 + `role == admin`，否则 403；`/api/stats/overview` 不在 `/admin` 前缀下也显式加此装饰器，禁止只靠前缀判断 |

JWT：`identity = str(user.id)`，附加声明 `role / nickname / avatar` 仅供前端即时渲染，权限判断始终以库中重载用户为准；三类回调（未登录 / 无效 / 过期）统一 401。

### 12.4 错误码体系（`common/errors.py`）

HTTP 状态码即业务码，不另设四位码：`0` 成功、`401` 未登录/过期/禁用、`403` 无权限、`404` 不存在、`422` 参数校验失败或业务规则不允许、`500` 服务异常。异常类 `BadRequest(422, errors={字段:提示})`、`Unauthorized`、`Forbidden`、`NotFound`、`ServiceError`；werkzeug HTTP 异常映射（400→422、405→404、413→422 "上传文件过大"）；未捕获异常记录堆栈返回 500 "服务暂时不可用"，不泄露堆栈。`data` 结构化补充：`errors`、`exists_type`、`reason ∈ {disabled, must_change_pwd, locked}`、`degree / require_confirm`。

### 12.5 统一返回体与分页

`{"code": 0, "msg": "ok", "data": {}}`；分页 `{"list": [], "page": 1, "size": 10, "total": 0}`；登录 `data = {token, user:{user_id, username, role, nickname, avatar_url, must_change_pwd}}`。

### 12.6 入参校验（`common/validators.py`，与前端一致）

问句非空 ≤ 100 字非纯符号；`prev_q ≤ 100`、`prev_a ≤ 200` 截断；用户名 `^[A-Za-z0-9_]{3,20}$`；密码 8–20 位含字母与数字；昵称 1–16；`kw ≤ 30`；`hops ∈ {1,2}`；`limit ≤ 100`；`period ∈ 七时期`；`n ∈ {5,10}`；`entities ≤ 20`；分页越界纠正；实体类型 ∈ 七标签、关系 ∈ 十关系（同时是 Cypher 白名单）；实体属性按本体（必填、枚举、整数、Period.order 1–7）；`status ∈ {0,1}`、`role ∈ {user, admin}`。

## 十三、前端设计

### 13.1 工程与入口

Vite 开发服务器 `127.0.0.1:5173`（占用自动顺延），代理 `/api`、`/static` → `127.0.0.1:5000`；别名 `@ → src`。`main.js`：Element Plus（zh-cn）+ 全量图标全局注册 + Pinia（先于 router，守卫中使用 store）+ 样式。`App.vue` 仅 `<router-view/>`，三种布局由路由嵌套渲染。

### 13.2 路由与守卫（`router/index.js`）

- 前台 `/`（MainLayout）：`/`、`/qa`、`/graph`、`/timeline`、`/entity/:name`、`/entity-not-found`、`/quiz`、`/login`；个人中心 `/user/*`（`requiresAuth`，嵌套在 MainLayout 下，UserCenterLayout）：profile / security / history / favorites / quiz-records；后台 `/admin/*`（`requiresAuth + requiresAdmin`，AdminLayout）：overview / entities / triples / oplog / users / qalog / stats / llm；兜底重定向 `/`。
- 全局守卫优先级：**首登强制改密**（`must_change_pwd=1` 只放行账号安全页与登录页）> `requiresAuth`（跳登录携带 `redirect`）> `requiresAdmin`（提示无权限跳首页）。
- `afterEach` 设置页面标题；所有组件懒加载。

### 13.3 状态管理（Pinia）

- `user`：`{token, user_id, username, role, nickname, avatar_url, must_change_pwd}` 持久化 `localStorage['dangshi_user']`；getters `isLogin / isAdmin`；`setUser` 以接口返回值更新（不解析 token 载荷）；`logout` 清理。
- `llmPref`：`llm_available`（`GET /api/config`）、`enabled`（`localStorage['llm_pref']`，不可用时内存退化）；`useLlm = llm_available ∧ enabled` 即请求体 `use_llm`。

### 13.4 请求封装（`utils/request.js`）

`axios.create({baseURL:'/api', timeout:10000})`；请求拦截器注入 `Authorization: Bearer`；响应拦截器 `code=0` 直接返回 `data`；401 → 清态跳登录（带 redirect）；403 → 提示跳首页；404/422 不弹全局提示由页面处理；无响应 / 5xx → "服务暂时不可用"；对幂等 GET 在无响应或 502/503/504 时最多重试 2 次（业务错误不重试）。

### 13.5 API 层

13 个文件一一封装第 12.7 节接口（auth / qa / graph / entity / timeline / daily / quiz / user / stats / adminKg / adminLog / adminUser / adminLlm），CSV 导出用 `responseType: 'blob'`。

### 13.6 布局

- `MainLayout`：吸顶导航（毛玻璃白底 + 红色底边线）、五个菜单、登录/注册或头像下拉（个人中心、后台管理（admin）、退出）、主体 `min-width:0` 防横向溢出、`SiteFooter`。

- `AdminLayout`：可折叠深色侧栏（八菜单，sticky）+ 白色顶栏（面包屑、返回前台、退出）。

## 十四、安全设计与非功能性设计

### 14.1 安全设计

| 类别 | 措施 |
|---|---|
| 密码 | werkzeug 加盐哈希；任何环节不落明文、不写日志；重置密码随机 8 位仅响应一次 |
| 鉴权 | JWT 2 小时；每请求重载用户校验 `status`；admin 显式装饰器；个人数据接口以 JWT `user_id` 为准，禁止前端传 user_id；后台用户管理不能操作自己、至少保留 1 个 admin |
| 首登强制改密 | `must_change_pwd=1` 前端守卫 + 后端端点白名单双重拦截 |
| 登录锁定 | 连续 5 次错误锁 10 分钟（内存字典，单进程） |
| 注入防护 | Cypher 全参数化，标签/关系名白名单常量；SQL 经 ORM；问句长度与字符校验 |
| 文件上传 | 仅头像一处：扩展名白名单 + 文件头魔数（`FF D8 FF` / `89 50 4E 47`）+ ≤ 2MB；文件名由 user_id 生成防路径注入；`MAX_CONTENT_LENGTH` 硬限 |
| 密钥 | Neo4j 密码与 LLM key 只存 `.env` / `app.db`（均不入 Git）；接口一律掩码；日志不打印；`doc/模型配置/` 与 `*models.json` 已加入 `.gitignore` |
| LLM 合规 | 提示词封闭输入 + 注入短语清理 + 忠实度三项校验 + 固定拒答句；图谱命中永不经 LLM |
| 不信任前端 | `use_llm` 后端再判；测验得分后端复算；三元组头尾约束后端复校；所有校验规则后端重校 |
| 审计 | op_log 只增不删，与知识写操作 1:1；qa_log 每问必写 |

### 14.2 非功能性指标

| 类别 | 指标 | 实现手段 |
|---|---|---|
| 性能 | 问答 < 1s；图谱/百科接口 < 300ms（接口本身实测 18–38ms） | 唯一约束索引、子图 LIMIT、词典/TF-IDF/规则/模板常驻内存 |
| 内容准确 | 核心知识零差错；每条知识可溯源 | 权威来源 + 核心池人工校验 + 交叉复核 + 测验/推荐只用核心池 + F9 只展示原文 |
| 可维护性 | 知识在线增改即时生效 | F6 直写 Neo4j，无应用层缓存，词典热刷新 |
| 易用性 | 零基础可上手，全站中文 | 示例问句、候选/澄清、加载/空/错误三态、二次确认、Element Plus 栅格 |
| 可演示性 | 断网单机完整运行 | 无外部 API 依赖（LLM 可选可降级）、轮播图片本地打包 |
| 一致性 | 双库写序、幂等约定 | op_log flush → Neo4j → commit；收藏/三元组/实体重复幂等；测验提交前端置灰 |
| 并发 | 单机 Flask 多线程 | SQLite 单写者串行化；Neo4j driver 单例、session 每请求 |

### 15.3 实验一：意图分类对比（`eval/intent_experiment.py`）

- 数据集 `intent900.csv`：15 意图 × 60 = 900（模板 40 + 改写 20，改写句刻意绕开规则关键词），固定种子 20260916，7:3 分层切分（训练 630 / 测试 270）。
- 方法：规则法（主线，仅看训练集错例调规则，测试集不参与调参）；朴素贝叶斯与线性 SVM（特征 = 字符 2–3 元 TF-IDF + 词 1–2 元 TF-IDF + 疑问词/触发词二值特征）。

| 方法 | 总准确率 | 宏 F1 |
|---|---|---|
| 规则法（主线） | **98.9%** | 0.932 |
| 朴素贝叶斯 | 84.1% | 0.829 |
| 线性 SVM | 93.7% | **0.936** |

规则法首轮仅 66.7%（改写句打在召回盲区），扩充 exclude 与口语化关键词后 98.9%；除 I13（83.3%，3 例判为 UNKNOWN）外全部 100%。NB 最弱在 I13 27.8%、I4 61.1%；SVM 弱在 I13 66.7%、I4 77.8%。结论：领域规则准确率胜出，SVM 宏 F1 略高说明其在样本少的意图上更均衡。错例与报告见 `eval/datasets/intent_experiment_report.md`。

### 15.4 实验二：200 条端到端问答评测（`eval/run_qa200.py`）

- 数据集 `qa200.csv`：8 大类 × 25（问时间 / 问地点 / 问内容意义 / 关系列举 / 反向关系 / 时期列举 / 两跳 / 实体介绍），主语实体从核心池随机取不按"答得出"筛选，10% 同音干扰（实得 16 条）；冻结后只回补数据不改题。
- 判定：实体链接正确 ∧ 意图正确 ∧ 答案含图谱期望值（评测时现取）。
- 固定在 LLM 关闭态执行。

| 轮次 | 总准确率 | 说明 |
|---|---|---|
| 基线 | 66.5% | 建集后首评（157 名核心人物中 89 人孤立） |
| 回补一轮 | 75.0% | 补任职/参会/创作核心关系 + 修实体链接长名不可达缺陷 |
| 回补两轮 | 76.0% | 补英模与科技文教界任职、扩"发生于"触发词、补全国名 |
| 回补三轮 | **81.0%** | 补孤立核心人物任职、多人并列句漏掉的领导关系、20 次党代会意义与召开地、有公开文集者的作者关系 |

分类准确率：问时间 100%、时期列举 100%、实体介绍 96%、两跳 92%、反向关系 76%、问地点 64%、关系列举 64%、问内容意义 56%。错误归因 38 条：图谱知识缺失 30、实体未识别 7、意图误判 1、**答案不符 0**——意图、查询、模板三步无误，准确率完全由数据覆盖决定。回补纪律：按类别系统性补，不照评测题填答案。仍未消除的缺失主要为 `meaning` 属性（评价性属性只对里程碑事件填写，不生成原文之外表述）与"雷锋写了哪些著作"类本无正确答案的均匀抽样题目。报告见 `eval/datasets/qa200_report.md`。

### 15.5 实验三：自动抽取准确率（`eval/extraction_accuracy.py`）

总体 4,063 实体 + 506 关系按占比分配 200 名额（实体 178：事件 112 / 文献 50 / 组织 10 / 地点 6；关系 22），固定种子无放回抽样，逐条人工判定（`data/clean/extraction_sample.csv`）。结果 **193/200 = 96.5%**（实体 96.6%、关系 95.5%）。7 个错例：指代不明事件名、讲话论述片段被当事件（3）、图注短语、"纽约联合国总部"判为组织、(周恩来)-[创作]->(政府工作报告) 尾实体为文种通名。

### 15.6 安全用例

注入（Cypher/SQL 各 3 条）、越权（游客 / user 访问 `/api/admin` 与 `/api/stats`）、伪造头像文件（改名文本文件被魔数拦截、GIF 被拒）、登录锁定，全部按预期拒绝。LLM 忠实度校验直验：段落外年份 / 段落外实体 / 缺引用 / 引用越界四类均被拦截。

## 十六、部署与运行

### 16.1 环境

Windows 10/11 64 位；Python 3.12；Node.js 18+；Neo4j Desktop（本地 DBMS，Bolt 7687）；内存 ≥ 8 GB。固定端口：Neo4j 7474/7687、Flask 5000（`FLASK_PORT` 可改）、Vite 5173。

### 16.2 新机器启动

```powershell
git clone <仓库> dangshi-kg && cd dangshi-kg
python -m venv venv && venv\Scripts\activate && pip install -r requirements.txt
copy backend\.env.example backend\.env      # 填 NEO4J_PASSWORD、ADMIN_INIT_PASSWORD
# 启动 Neo4j Desktop 的本地 DBMS
python -m db.init_all                        # 建 SQLite → 建约束索引 → 导入图谱 → 七项验收
python -m backend.app                        # http://127.0.0.1:5000
cd frontend && npm install && npm run dev    # http://localhost:5173
```

初始管理员 `admin`，密码取 `.env` 的 `ADMIN_INIT_PASSWORD`（未设则生成随机密码打印一次），`must_change_pwd=1` 首登只能改密。图谱数据来自随仓库提交的 `data/excel/`，不需联网重新采集。

### 16.3 日常命令

```powershell
python -m qa.cli                              # 命令行问答
python -m backend.common.export_ontology      # 本体变更后重生成前端镜像
python -m db.build_seed                       # seed_data → data/excel 七表
python -m eval.core_check --emit              # 核心池交叉复核并生成待补源名单
python -m kg.importer.import_all --prune      # 重导并使图谱与 Excel 一致
python -m kg.importer.verify                  # 七项验收
python -m eval.selfcheck_frs                  # FRS 全量自检
python -m eval.intent_experiment              # 意图分类对比实验
python -m eval.run_qa200                      # 200 条端到端评测
```

### 16.4 未连接 Neo4j 时的行为

系统仍可启动：首页与时间轴降级为空态与七个时期页签，问答走 F9 兜底，账号与后台用户/日志功能不受影响；实体百科、图谱可视化、测验返回"图数据库未连接"。

### 16.5 AI 增强配置

后台"AI 增强"页选择厂商预设（通义千问 / 智谱 / DeepSeek / Kimi / 自定义）、填端点密钥模型、测试连通性、保存即时生效；或在 `.env` 配置 `LLM_*` 五项作为兜底。删除 `llm/` 目录即物理回退。
