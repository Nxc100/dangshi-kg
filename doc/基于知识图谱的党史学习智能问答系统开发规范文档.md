## 0. 项目范围与技术栈约束（不可偏离）

* **前端**：Vue 3 + Vite + Element Plus + ECharts 5 + axios（SPA 单页应用；路由 vue-router 4；状态管理 Pinia，不混用 Vuex；全站中文，桌面优先）
  - 三类角色同一前端工程，路由层级区分：前台挂根路径 `/`（`/qa`、`/graph`、`/timeline`、`/entity/:name`、`/quiz`、`/login`），个人中心 `/user/*`（需登录），后台 `/admin/*`（需 admin）
  - **无独立后台登录页**：admin 走同一登录页，登录后导航栏出现"后台管理"入口（FRS FR-A01）
* **后端**：Python 3.11（64 位）+ Flask + flask-cors + flask-jwt-extended；SQLAlchemy ORM + **SQLite**（`backend/app.db`，共 5 张表：user / favorite / qa_log / quiz_record / op_log，以 `backend/models.py` 为唯一可信结构来源；不换 MySQL）
* **图数据库**：Neo4j 5.x（Neo4j Desktop，`bolt://localhost:7687`）+ neo4j 官方 Python driver；7 类实体标签、10 类关系，唯一约束与索引以 `kg/importer/schema.cypher` 为唯一可信来源
* **问答引擎**：独立 Python 包 `qa/`，八步管道（①分词 ②词性标注 ③实体识别链接 ④意图分类 ⑤槽位校验 ⑥Cypher 构建 ⑦图谱查询 ⑧答案生成），15 类意图 ↔ 15 个参数化 Cypher 模板一一对应；先命令行版 `python -m qa.cli`（中期检查材料）再由 Flask 封装为 `POST /api/qa`
* **中文处理**：jieba（分词 + posseg 词性标注 + 自定义词典）、rapidfuzz（模糊纠错，`ratio ≥ 85`）、pypinyin（同音纠错）；**不引入 pyahocorasick、BiLSTM-CRF、BERT/rbt3 等**
* **意图分类**：主线为"关键词 + 词性 + 实体类型"规则表（15 类 + UNKNOWN）；sklearn 朴素贝叶斯 / 线性 SVM 与 LLM zero-shot **仅用于离线对比实验**，不进运行链路
* **兜底检索（F9）**：sklearn TfidfVectorizer + 余弦相似度，本地语料 `data/corpus/paragraphs.csv`（≥ 2000 段，含章节出处），服务启动时构建常驻内存；断网可用
* **数据采集**：requests + BeautifulSoup4 + lxml，只采 DR-01~DR-05 五个权威官方**静态页**；**不安装 Playwright/Selenium**，不用 OwnThink 等开放知识图谱
* **Excel 整理**：pandas + openpyxl，`data/excel/` 七张表（六实体 + 一关系）+ `alias.xlsx` 为人工校验载体，入 Git
* **Python 依赖固定 14 个包**（V3 2.3 Step 2 清单，`requirements.txt` 固化，**不再新增**）：requests、beautifulsoup4、lxml、jieba、pandas、flask、flask-cors、flask-jwt-extended、sqlalchemy、neo4j、scikit-learn、rapidfuzz、pypinyin、openpyxl；LLM 模块用 requests 直调 OpenAI 兼容接口，零新增依赖
* **鉴权**：JWT（flask-jwt-extended；载荷 `user_id` / `role` / `nickname` / `avatar`，有效期 2 小时，前端存 localStorage，axios 拦截器携带 `Authorization: Bearer <token>`）；三角色 R1 游客 / R2 user / R3 admin 逐级包含；`/api/admin/*` 与 `/api/stats/*` 服务端强制 `role=admin`
* **密码**：werkzeug `generate_password_hash` / `check_password_hash` 加盐哈希；禁止明文、禁止无盐 MD5、任何环节不写日志
* **文件存储**：全项目仅头像一处上传，本地目录 `backend/static/avatars/{user_id}.jpg`（每用户一张，同名覆盖，无清理负担），Flask 静态资源对外访问；不用 OSS
* **LLM 增强（全项目唯一可选外部服务，P1）**：独立包 `llm/`，OpenAI 兼容 `/chat/completions` 由 requests 直调（无 SDK）；配置只走后端 `.env` 五项 `LLM_ENABLED / LLM_BASE_URL / LLM_API_KEY / LLM_MODEL / LLM_TIMEOUT`；**双层开关（系统层 `.env` + 用户层 localStorage 键 `llm_pref`）、恒可降级**；只接兜底生成（FR-L02）与追问改写（FR-L03）两处，**图谱命中的答案永不经 LLM**；厂商在第 14 周按"免费额度充足 / P95 时延 < 5 秒 / 内容稳定"实测 2 家择一，结论登记 `data/sources.md`，换厂商只改 `.env` 三行；`llm/` 目录删除 + `.env` 还原即物理回退到原方案
* **端口与环境**：Neo4j 7474/7687、Flask 5000、Vite 5173；项目路径 `D:\graduation\dangshi-kg`（纯英文、无空格，不放 Program Files / 桌面 / OneDrive）；所有 Python 文件读写显式 `encoding='utf-8'`，导出给 Excel 的 CSV 用 `utf-8-sig`；pip 清华镜像、npm npmmirror；Neo4j 密码与 LLM key **只存 `.env`，不入 Git**
* **数据红线**：核心池 500 实体（人物 120 / 会议 60 / 事件 150 / 组织 40 / 文献 60 / 地点 63 / 时期 7）`checked=1` 且交叉复核零错误；实体 ≥ 1500、关系 ≥ 2500、属性三元组 ≥ 8000、`source` 覆盖 100%、F9 语料 ≥ 2000 段；**测验出题与每日推荐只从 `checked=1` 核心池取数**
* **毕设边界**：限定领域模板式 KBQA，能力边界 = 15 类意图 × 图谱收录知识（V3 1.4，写入开题报告）；边界外统一走 F9 权威原文段落（开启态为受约束 LLM 生成 + 段落可展开）；不做开放域自由问答、观点评价、> 2 跳推理；不生成图谱与语料之外任何内容；登录锁定为内存计数；无短信 / 邮件 / 第三方登录；用户偏好不跨设备同步；200 条端到端评测**固定在 LLM 关闭态执行**
* **核心闭环必须可演示**（FRS 第五章 12 条 + LLM-Design 增补 2 条）：
  * 账号生命周期：注册 → 自动登录 → 使用 → 退出 → 再登录 → 改密 → 新密登录（库中始终无明文密码）
  * 头像闭环：上传 → 全站显示 → 再次更换覆盖 → 退出重登仍显示
  * 问答学习闭环：提问 → 答案实体链接 → 百科 → 关联标签 → 图谱 / 时间轴 → 再提问
  * 兜底闭环：图谱外问题 → F9 段落 + 出处 → 仍可继续提问 → qa_log `fallback=1`（**断网状态执行**）
  * 历史闭环：登录后提问 → 历史即现 → 一键重问 → 新记录；删除 / 清空仅影响个人视图（管理员日志计数不变）
  * 收藏闭环：百科 / 答案气泡收藏 → 收藏夹两页签回访 → 跳转 → 取消 → 按钮态一致
  * 学练测闭环：试做 → 保存成绩 → 测验记录 → 错题 → 百科复习 → 针对错题再练
  * 知识运营闭环：后台改会议地点 → 前台问答 / 百科即时变化 → 改回 → op_log 两条留痕（**答辩高光环节，脚本固化**）
  * 关系运营闭环：新增三元组 → 前台百科标签 / 图谱边 / 问答三处出现 → 删除 → 消失
  * 治理闭环：禁用用户 → 登录被拒 → 启用恢复；重置密码 → 随机密码仅显示一次 → 新密登录 → 引导改密
  * 度量闭环：问答产生日志 → 明细（FR-A06）与看板（FR-A07）总分一致 → 兜底率指导补录
  * 每日学习闭环：首页今日推荐 / 历史上的今天 → 百科 → 示例问句 → 问答
  * LLM 降级闭环：开启态拔网线提问图谱外问题 → 自动回落段落展示 → 恢复网络再问 → 生成回答（附录 B 加演）
  * LLM 开关闭环：开 → 行为增强 → 关 → 行为 = 原方案（关闭态回归对照，一票否决项）

## 1. 界面设计与交互规范（Vue 3 + Element Plus）

### 1.1 视觉规范（庄重党史 + 学习工具）

* 两套基调通过 CSS 变量统一管理（`styles/variables.css`）：
  - **前台**：庄重红为主色（`--color-primary: #C7000B`），米白 / 浅灰底色，金色仅作强调；以卡片与文本为主，问答页气泡区留白充足，不做"营销站"式大图与动效
  - **后台**：经典管理后台（左侧深色折叠菜单：知识管理-实体 / 知识管理-关系 / 操作日志 / 用户管理 / 问答日志 / 热点统计；顶部：面包屑 / 头像昵称 / 返回前台 / 退出登录），信息密度优先
* 统一圆角 8px、卡片内边距 16px，通过 CSS 变量管理
* **实体类型七色映射为全站唯一来源**：`frontend/src/utils/ontology.js` 由 `backend/common/ontology.py` 经脚本导出生成（不得手改），图谱着色、类型徽标、搜索联想、百科头部、时间轴、后台表格一律引用：

| 标签 | 中文名 | 色值 |
| --- | --- | --- |
| Person | 人物 | `#C0392B` |
| Organization | 组织 | `#E67E22` |
| Event | 事件 | `#2E86C1` |
| Meeting | 会议 | `#8E44AD` |
| Location | 地点 | `#27AE60` |
| Document | 文献 | `#B7950B` |
| Period | 时期 | `#7F8C8D` |

* 关系边一律显示中文名（LED 领导 / PARTICIPATED_IN 参加 / AUTHORED 创作 / HELD_POSITION 任职 / HELD_IN 召开于 / OCCURRED_IN 发生于 / PRODUCED 形成 / FOUNDED 创建 / REORGANIZED_TO 改编为 / BELONGS_TO 属于时期），映射同样来自 `ontology.js`，禁止页面内硬编码英文关系名或另写一份中文名
* 特色组件要求：
  - 问答气泡区分角色（用户右 / 系统左）；答案文本中的实体渲染为带类型色的可点击链接（跳百科）；气泡底部固定两个操作："查看知识来源"（展开溯源局部子图，复用 `KgGraph`）与"收藏"（游客点击弹登录引导）
  - 未识别实体：候选以按钮组渲染"你是不是想问：遵义会议？"，点击即以纠正后问句重发；属性缺失：固定文案"该信息暂未收录" + "查看词条"入口按钮；槽位不符：澄清文案 + 该实体支持的问法示例（按钮，点击即发送）
  - 兜底区固定顶栏文案"以下为权威资料原文节选，供学习参考"，段落卡（正文 + 章节出处 + source 链接）；无相关段落时显示引导语 + 3 条示例问句
  - LLM 开启态：答案气泡顶部固定徽标"**AI 生成，仅供参考**"，正文 ≤ 150 字且末尾含 `[1][2]` 编号引用，下方"查看所引权威资料原文"折叠区（编号与正文引用一一对应）；发生改写时气泡上方浅色小字"已按'{改写后问句}'为你查询"；等待期显示"AI 生成中…"加载态；开关为问答页右上角 `el-switch` + 信息图标气泡（文案："开启后，知识库未收录的问题将由 AI 基于权威资料生成参考回答，并明确标注；可随时关闭"）；`llm_available=false` 时**该控件整体不渲染**
  - 图谱画布：ECharts 力导向图（`series.type='graph'`，`layout='force'`），七色节点 + 图例，边标中文关系名；单击节点右侧 `el-drawer` 显示属性摘要 + "展开邻居"按钮（增量追加）；双击跳百科；工具栏：类型筛选 `el-checkbox-group` / 缩放 / 重置视图；节点 > 100 顶部提示"节点较多，请使用类型筛选"
  - 时间轴：顶部七个时期 `el-tabs`（按 `Period.order`），`el-timeline` 事件卡（time_text / 事件名 / 一句话简介）；页内"年份定位"输入框
  - 百科页自上而下：头部（名称 / 类型徽标 / 别名 tag）→ 属性表（`el-descriptions`，仅渲染非空字段，时间显示 `time_text`）→ 简介段（段末"来源：xxx" + source 链接）→ 关联实体分组标签区（按"关系 × 邻居类型"分组，如会议页"出席人物 / 形成文献 / 召开地点"）→ 局部 1 跳关系图（复用 `KgGraph`）→ 右上角收藏按钮
  - 测验：点选即判分，选项标绿（对）/ 标红（错，同时标出正确项），下方展开解析文本（即图谱事实）+ "去百科页复习"链接；成绩页得分 / 用时 / 逐题回顾 + "保存成绩" / "再来一组"
  - 首页："今日推荐"卡（实体名 / 类型徽标 / 两行简介 / "查看详情"）；"历史上的今天"事件卡列表（时间 / 名称 / 一句话简介），**无匹配整栏隐藏，不出现空态**；问答入口框 + 8 条示例问句（点击直达问答页并自动发送）
  - 后台总览四个数字卡（实体总数 / 关系总数 / 注册用户数 / 今日问答量）；热点统计五图（高频问句 Top10 柱状 / 高频实体 Top10 柱状 / 意图类型分布饼图 / 近 30 天问答量折线 / 兜底率数字卡 + 环形图）+ LLM 一行三指标卡（近 30 天调用次数 / 生成成功率 / 平均时延）；**所有统计数值只能由 ECharts / DOM 渲染后端聚合值**，前端不自行计算

### 1.2 交互反馈规范（禁止原始弹窗）

* 禁止使用浏览器 `alert` / `confirm` / `prompt` 等阻塞弹窗
* 反馈优先级：
  1. 页面内即时状态变化（收藏按钮实心 / 空心切换、昵称与导航栏同步、图谱增量追加节点、测验即时标色、AI 开关切换即时生效无需刷新）
  2. `ElMessage`（保存成功、已收藏、已取消收藏、已复制等轻提示，3 秒消失）
  3. `ElMessageBox.confirm`（删除 / 清空历史、取消收藏、删除实体、删除关系、禁用用户、重置密码、取消管理员等二次确认；删除实体弹窗内必须显示实时查询的"将级联删除该实体的 n 条关系"）
  4. `ElMessageBox.prompt` 输入名称确认（**关系数 ≥ 20 的高连接度实体删除**：红色强提示 + 输入实体名与目标一致方可提交，后端同样校验 `confirm_name`）
  5. `ElNotification`（重置密码结果——8 位随机密码**仅显示一次**并提示"请复制发送给用户"；LLM 连通异常等需停留阅读的反馈）
* 关键拦截反馈规范：
  - 游客点收藏 / 保存成绩 → 登录引导弹窗（"登录后可保存成绩并查看历史错题"），登录成功回跳原页并恢复上下文（成绩暂存前端不丢失）
  - 401 → "登录已过期"→ 清态 → 跳 `/login?redirect=<原地址>`；403 → "无权限访问"→ 跳首页；422 → 逐字段红字显示后端返回的中文校验信息；500 → "服务暂时不可用，请稍后重试"，问答输入内容**保留在输入框**
  - 实体不存在 → 友好 404 页（"未找到该词条" + 搜索框 + 热门实体入口）
  - 三元组约束不符 → "该类型组合不允许此关系"；头 / 尾实体不存在 → "实体不存在，请先新增实体"并附跳转；自指关系 → "头尾实体不能相同"；重复新增 → "该关系已存在"
  - 实体新增重名 → "实体已存在，是否前往编辑？"（确认后直接打开编辑表单并回填）
  - admin 首登未改密（`must_change_pwd=1`）→ 仅可访问"账号安全"页，其余路由跳转并提示"请先修改初始密码"
* 空状态必须有：Icon + 引导文案 + 操作按钮（"暂无提问，去问一个？"→ 问答页；收藏夹实体 / 问答两页签各自引导语与入口；测验记录空态 → 去测验；后台列表筛选无结果 → "清空筛选"）；**唯一例外**：首页"历史上的今天"无匹配时整栏隐藏，不显示空态
* 错误态必须有：提示 + "重试"按钮（时间轴、图谱、测验出题、看板、每日学习加载失败；首页接口异常时降级显示固定引导语与示例问句，不白屏）
* 加载态：所有异步区域骨架屏或 `v-loading`；问答发送后按钮置灰 + 气泡区加载态
* 写按钮提交期间置灰（loading）+ 防抖 300ms，防重复提交

### 1.3 适配与可用性

* 列表页必须支持：分页（`el-pagination`，`page` 默认 1、`size` 默认 10、上限 50）、筛选区、加载态
* 表单必须支持：必填标识（*）、实时校验规则、禁用重复提交；后台实体表单**按类型动态渲染**（切换类型即重建字段，必填项按 `ontology` 定义标星）；三元组表单三级联动（头实体联想 → 关系类型仅列出与头类型匹配项 → 尾实体联想仅列出允许类型）
* 输入限制（前端拦截，后端复校）：问句非空 ≤ 100 字且非纯符号 / 纯空白；图谱搜索词非空 ≤ 30 字；年份仅 1921–2021 四位数字；题量仅 5 / 10；昵称 1–16 字符（过滤首尾空白）；用户名 3–20 位字母 / 数字 / 下划线；密码 8–20 位且同时含字母与数字
* 头像上传：`accept="image/jpeg,image/png"`，前端校验类型 + ≤ 2MB，canvas 中心裁剪正方形并压缩为 256×256 JPEG（质量 0.85），圆形预览 + "确认上传 / 取消"，失败保留原头像；从未上传显示系统默认头像（本地资源）
* 图谱画布：单画布节点上限 100；子图接口 `limit=100`；孤立节点仅显示自身并提示"暂无关联知识"
* 分辨率：桌面优先，适配 1366×768 及以上；基于 Element Plus 栅格（`el-row/el-col` 响应式属性）做基本自适应，**答辩以桌面演示为准**，不做移动端专项适配；唯一断点常量 `--bp-md: 992px` 定义在 `styles/variables.css`，图谱 / 时间轴 / 百科在窄屏改为单列
* 性能口径：问答响应 < 1s；图谱 / 百科 / 时间轴接口 < 300ms；LLM 兜底生成 5 秒硬超时、改写 3 秒硬超时

## 3. 代码融合性与兼容性保证（禁止破坏既有流程）

**检查要点**：
* 路由路径不冲突：前台 `/`、个人中心 `/user/*`、后台 `/admin/*` 严格隔离；导航守卫按 `meta.requiresAuth / meta.requiresAdmin` 统一鉴权；`must_change_pwd` 守卫优先级最高；`/login` 与 `/entity/:name` 404 页不受守卫拦截
* 本体不破坏：新增 / 变更标签、关系、头尾约束、必填属性必须**只改 `ontology.py`**，再重新生成前端 `ontology.js`、同步 `schema.cypher` 与 V3 第四章；禁止在页面、Cypher 模板、出题模板中另写一份
* 枚举不破坏：SQLite 枚举值或列变更必须明确迁移路径（`ALTER TABLE ADD COLUMN` + 默认值，旧记录取默认），并同步 FRS 1.4 / V3 7.5 / LLM-Design 4.6
* 公共组件改动需全量回归：`KgGraph`（图谱页 2 跳 / 百科 1 跳 / 问答溯源三处复用）、`TypeBadge`、`EmptyState`、`ErrorRetry`、`AvatarUpload`、`EntityForm` / `TripleForm`、图表封装组件、`ChatBubble` 系列
* 接口响应结构一致：前端不得"按感觉取字段"，必须对齐 8.2 的返回体与问答响应结构；`subgraph` 三处（图谱 / 百科 / 溯源）结构完全相同，节点 `id` 生成规则唯一
* 实体词典口径不破坏：jieba 词典、实体链接、测验干扰项排除、后台联想、图谱搜索联想五处**只认 `qa/dictionary.py`** 加载的（主名 + 别名 → 主名 / 类型）表；后台实体新增 / 改名 / 改别名 / 删除后必须 `dictionary.reload()`，禁止各处自建词表
* 溯源口径不破坏：任何答案文本只能由第⑧步模板基于第⑦步查询结果生成，`entities` 与 `subgraph` 只含本次查询实际涉及的节点与边；禁止在接口层或前端拼接图谱以外的事实
* LLM 隔离不破坏：`qa/` 只在"第⓪步追问改写"与"兜底分支"两处 `try: from llm import …`，导入失败即视为系统层关闭；`llm/` 目录删除 + `.env` 还原后系统行为必须与原方案逐字节一致；**任何改动不得让图谱命中的答案经过 `llm/`**
* 统计口径不破坏：后台总览四数字、看板五图 + LLM 三指标只能来自 `stats_service`，与问答日志明细互为总分；用户删除历史（`user_visible=0`）不参与任何聚合条件
* 查询口径不破坏：图谱数据**不做任何应用层缓存**（保证"后台改前台即时生效"），只有实体词典与 TF-IDF 矩阵常驻内存

## 6. 核心业务逻辑开发规范（必须严格遵守）

### 6.1 角色与权限（JWT RBAC）

* 三角色：`R1 游客`（无 token）/ `R2 user` / `R3 admin`，逐级包含（admin 拥有 user 全部能力）
* 后端必须做权限校验（`common/auth.py` 的 `@login_required` / `@admin_required` 装饰器解析 JWT + 重载用户校验 `status=1`），不能只靠前端路由守卫隐藏页面
* 接口鉴权三档（与 FRS 2.2 / V3 7.12 一致）：
  * 游客可用：`/api/qa`、`/api/config`、`/api/graph/*`、`/api/timeline`、`/api/entity/*`、`/api/daily`、`GET /api/quiz`、`/api/auth/*`
  * 需登录：`/api/user/*`、`POST /api/quiz/submit`、`GET /api/quiz/records*`
  * 需 admin：`/api/admin/*`、`GET /api/stats/overview`——**`/api/stats/overview` 不在 `/api/admin` 前缀下（FRS 7.12 定稿路径），必须显式加 `@admin_required`，禁止只靠前缀判断**
* 关键限制：
  * `user`：只能操作本人的 history / favorite / profile / avatar / password / quiz_record；所有个人数据接口后端强制以 JWT `user_id` 过滤，**禁止**前端传 user_id 决定数据范围；删除历史 / 取消收藏必须校验记录归属
  * `admin`：可管理图谱知识、全部用户、全部问答日志与统计；**不代替用户注册、不代替用户提问、不修改他人收藏与历史**
  * 后台用户管理（FR-A05）是**全项目唯一**从请求路径接收目标 `user_id` 的写接口族，集中隔离在 `user_admin_service`，不污染 `user_service`"操作对象一律是当前登录人"的契约；每个写方法服务端重载目标用户并逐条校验：目标存在（404）、不能操作当前登录账号（422，前端按钮同步置灰）、取消管理员时系统至少保留 1 个 admin（422）
  * **角色授予（规范决策，依据 FRS 2.1"后续管理员由现有管理员在用户管理中授予"）**：`POST /api/admin/users/<id>/role` 传目标角色 `user|admin`；不能改自己；不进 op_log（op_log 仅记知识操作），以应用日志留痕
  * 游客调需登录接口 → 401；普通用户 token 调 `/api/admin/*` 或 `/api/stats/*` → 403；前端 403 提示"无权限访问"并跳首页
* 预置管理员：`init_db.py` 种入 1 个 `role=admin` 账号（用户名 `admin`），初始密码从环境变量 `ADMIN_INIT_PASSWORD` 读取、未设置则生成随机密码打印终端一次；`must_change_pwd=1`，首登仅可访问改密页；**页面不作任何初始密码提示**
* JWT 载荷中的 `nickname` / `avatar` 仅供登录即时渲染；资料更新后前端以接口返回值更新 Pinia store，不以 token 载荷为准
* token 过期 / 非法：后端统一 401，前端弹"登录已过期"→ 清理状态 → 跳 `/login?redirect=`；登录成功回跳原页

### 6.2 账户与登录规范

* 注册：用户名 3–20 位字母 / 数字 / 下划线且全局唯一（失焦异步预检 `GET /api/auth/check?username=`）、密码 8–20 位且同时含字母与数字、确认密码一致；后端重复全部校验；成功后**自动登录**（签发 JWT）并跳转来源页或首页；默认昵称 = 用户名
* 登录：用户名 + 密码；错误提示统一"用户名或密码错误"（不区分具体项）；账号禁用 → "账号已被禁用，请联系管理员"
* 登录锁定：连续 5 次密码错误锁定 10 分钟，提示"尝试次数过多，请稍后再试"；**内存字典实现**（`{username: (fail_count, lock_until)}`，单进程、重启即清，FRS 明示的毕设简化），成功登录清零；不新增表
* 昵称：1–16 字符，过滤首尾空白；成功后导航栏与个人中心即时同步
* 修改密码：校验原密码哈希匹配、新密码规则同注册、新旧不同；成功后清 `must_change_pwd`，前端清除 token 强制重新登录
* 重置密码（FR-A05）：`secrets` 生成 8 位含字母数字的随机密码，仅在响应中返回一次（前端 `ElNotification` 显示并提示复制），库中只存哈希，置 `must_change_pwd=1`；关闭弹窗后不可再查
* 禁用 / 启用：`user.status` 由后台维护；`@login_required` 每次请求重载用户校验 `status=1`，**禁用后下一次请求即被拒（401 "账号已被禁用"）**，无需等 token 过期；不做主动吊销 token 的过度设计
* `must_change_pwd=1`（首登 admin / 被重置密码用户）：登录响应携带该标记，前端守卫只放行"账号安全"页；后端 `@login_required` 对非改密接口返回 422 "请先修改密码"（规范决策，防止绕过前端）
* 退出登录：前端清除 token 与用户态跳首页；退出后访问个人接口返回 401

### 6.3 问答管道核心规则（唯一真相：答案由图谱产出）

**问答链路**：
```
前端 POST /api/qa {question, use_llm?, prev_q?, prev_a?}
→ 入参校验：非空 / ≤100 字 / 非纯符号纯空白（不通过 → 422）
→ qa.pipeline.answer(question, ctx)（单一入口，CLI 与接口共用）：
    ⓪（仅 LLM 三条件满足 ∧ 触发条件成立）追问改写 → 改写句重走 ①~⑧，响应附 rewritten_from
    ① 分词：jieba 加载 dictionary 生成的 userdict（"八七会议""三湾改编"等专名不切碎）
    ② 词性标注：posseg 输出词/词性；提取疑问词（r：哪/谁/什么）与动词触发词（领导/参加/召开/写）
    ③ 实体识别与链接：精确匹配（主名 + 别名哈希，别名回链主名）→ rapidfuzz ratio ≥ 85 取最高 → pypinyin 拼音精确比对
       三级全未中 → 返回 candidates（相似度 Top3，可为空）并转兜底
    ④ 意图分类：规则表按优先级 I14/I15 > I1–I12 > I13，同级按规则表书写顺序；全未中 → UNKNOWN
    ⑤ 槽位校验：意图所需实体类型 ≠ ③ 输出类型 → 返回澄清提示 + 该实体支持的问法示例，不查询
    ⑥ INTENT_CYPHER[intent] 参数化模板，实体名以 $name 传入；I1 按实体类型分流到 time_text / found_time_text / pub_time_text
    ⑦ Neo4j 只读查询（driver session，读事务）
    ⑧ 答案模板（如 I1"{name}召开于{time_text}。"）+ 溯源子图 {nodes,links} + entities[{id,name,type}]
       列表类 ≤10 项，超出显示前 10 并注明总数；属性为空 → answer_text 固定"该信息暂未收录"，entities 携带该实体供百科入口
→ 未命中（无实体 / UNKNOWN / 属性缺失 / 查询为空）→ fallback=true → qa.fallback.retrieve(question)
    → 有效段落 ≥1 且 LLM 三条件满足 → llm.generator → checker → 通过：answer_source=llm；否则 answer_source=passage
    → 无有效段落 → 引导语 + 3 条示例问句，不调用 LLM
→ 写 qa_log（user_id / question / intent / matched_entity / answer / fallback / answer_source / llm_latency_ms / llm_detail / user_visible=1）
→ 返回 8.2 定义的响应结构（含 log_id）
```

**强制规则**：
* **答案零编造**：`answer_text` 只能由第⑧步模板基于第⑦步返回值生成；`entities` 与 `subgraph` 只含本次查询实际涉及的节点与边；**图谱命中的答案不经 LLM 改写、润色或转述**（三条红线之一）
* **Cypher 全参数化**：实体名、属性值、分页参数一律 `$param`；标签与关系类型只允许取自 `ontology.py` 白名单常量；禁止 f-string / `%` / `+` 拼接用户输入；注入样例 `遵义会议'}) DETACH DELETE (n) //` 作为参数传入不产生任何破坏（6.2 注入测试）
* **词典唯一**：`dictionary.py` 启动时从 Neo4j 加载七类标签全部 `name` 与 `alias`（别名一对多歧义在 `build_alias.py` 阶段拒绝入库），生成 `userdict.txt`（每行 `词条 频次 nz`）并 `jieba.load_userdict`；`reload()` 以"新建表 → 原子替换引用"方式热刷新，线程安全
* **意图规则表独立配置**（`qa/intent_rules.py`）：每条规则 = 关键词集 ∧ 词性特征 ∧ 实体类型 → 意图；改规则不改管道代码；规则表变更必须复跑 900 条数据集的测试集（准确率 ≥ 90%）
* **三类边界响应均为 `code=0` 业务响应**（不是错误）：未识别实体 → `candidates`；属性缺失 → 固定文案 + 百科入口；槽位不符 → `clarify`；只有参数校验失败返回 422、服务异常返回 500
* **qa_log 每问必写**：游客 `user_id=NULL`；`matched_entity` 存链接到的主名（多实体以 `|` 分隔）；`answer` 存面向用户的答案文本；落库放在答案组装之后、返回之前，**写入失败单独捕获并 logging，不影响答案返回**
* **性能**：词典、jieba、TF-IDF 矩阵、规则表、Cypher 模板全部在 `create_app()` 加载一次常驻；禁止每请求重建；问答 < 1s、子图 < 300ms（各接口实测 20 次取均值）
* CLI（`python -m qa.cli`）与 API 共用 `pipeline.answer()`；CLI 是第 9 周中期检查材料，接口封装后不得删除

### 6.4 F9 兜底与 LLM 增强规范（全项目唯一可选外部依赖）

**兜底原路径**：
```
fallback.retrieve(question)：
    jieba 分词 → TF-IDF（词 1–2 元，启动时对 paragraphs.csv 构建）→ 余弦相似度
    → top3 且相似度 ≥ 0.05 → [{text, chapter, source, score}]（前端固定顶栏"以下为权威资料原文节选，供学习参考"）
    → 均低于阈值 → [] → 前端显示引导语 + 3 条示例问句
```

**LLM 增强链路（仅在原方案已定义的兜底区与追问场景内）**：
```
三条件门（后端判定，缺一即走原路径）：llm.config.available()（LLM_ENABLED ∧ key 非空）∧ 请求 use_llm=true ∧ （触发兜底 ∨ 追问触发）
兜底生成（FR-L02）：
    段落 ≥1 → 每段截断 500 字 + 编号 + 注入清理 → prompts.FALLBACK（4.4 全文）→ client.chat(timeout=LLM_TIMEOUT, max_tokens=300, temperature=0.1)
    → None → 降级 passage；文本 → checker（年份 / 实体 / 引用三项）→ 不过 → 降级 passage；通过 → answer_source=llm，响应附 llm:{text, cited, latency_ms}
追问改写（FR-L03）：
    触发：a. ③ 三级全未中；或 b. 问句命中指代词表（它/他/她/这/那/这次/那次/该会议/此人…）且未识别出实体；且请求携带 prev_q
    → prev_a 截断 200 字 → prompts.REWRITE → client.chat(timeout=min(3, LLM_TIMEOUT))
    → 安全校验：非空 / ≤100 字 / 无换行；多句取第一句并去引号，仍不合规视为失败
    → 通过 → 以改写句重走 ①~⑧，响应附 rewritten_from；失败 → 按原始问句继续原流程
```

**强制规则**：
* `llm/client.chat()` 是**唯一外呼出口**：requests 直接 POST OpenAI 兼容格式，不引入 SDK；网络异常、非 200、超时、响应解析失败**全部捕获返回 `None`** 并 logging 原因；降级判断收敛于"是否为 None"一处
* 后端不信任前端：系统层关闭时即便收到 `use_llm=true` 也不产生任何外部请求（抓包验证）；`use_llm` 缺省按 false
* `GET /api/config` 只返回 `{llm_available}`，**不回传任何配置明文**；前端仅在 `llm_available=true` 时渲染开关；用户偏好存 localStorage 键 `llm_pref`，不可用时退化为内存状态，不入库
* 提示词只存放于 `llm/prompts.py`（4.4 定稿全文），修改提示词 = 修改该文件 + 回写 LLM-Design 4.4；进入提示词的只有三类受控文本：本地权威语料段落、用户问句（≤100 字）、上一轮问答摘要；不拼接任何网页实时内容
* 忠实度后校验 `checker.py` 三项：① 文本中所有"三或四位数字 + 年"与日期字符串必须出现在所引段落原文；② 用实体词典（含别名）匹配到的每个实体名必须出现在所引段落；③ 末尾至少含一个 `[n]`，n ∈ 1–3 且对应段落存在；固定拒答句"根据现有资料无法回答该问题。"免检放行。**任一不过整体降级**，保证上屏的年份与实体均有原文支撑
* 五类降级（无 key / 用户关闭 / 超时 / 报错 / 校验不过）一律无感回落为原路径：界面即原方案的段落展示，**不弹错误**，用户最多感知"这次是原文段落"
* 图谱命中永不经 LLM；LLM 改写只产出问句，答案仍由图谱产出；行为矩阵（LLM-Design 2.2）六格中"命中图谱"列三格全为原模板答案
* qa_log 记录：`answer_source`（kg / passage / llm）、`llm_latency_ms`（含失败尝试的耗时，未尝试为 NULL）、`llm_detail`（**规范决策**：JSON `{text, cited, passages:[{idx,text,chapter,source}], check_passed, degraded_reason}`，仅 LLM 尝试过时非空，供 FR-A04 记录展开与审计）；"是否经过降级" = `answer_source='passage' ∧ llm_latency_ms IS NOT NULL`
* `.env` 中的 key 不入 Git、不回显、不写日志；演示机与开发机各自配置
* 物理回退：删除 `llm/` 目录 + 还原 `.env`，`qa/` 的 try-import 失败即视为系统层关闭，全系统按原方案运行（验收必测）
* 评测口径：200 条端到端评测固定关闭态执行；LLM 专项（50 条兜底增强 / 10 组追问 / 四方法意图对比 / 拦截有效性对照）独立执行，只入论文

### 6.5 图谱可视化、百科页、时间轴与每日学习规范

* **子图数据契约**（`graph_service` 唯一组装）：`{nodes:[{id,name,type}], links:[{source,target,relation,label}]}`；`id = "{label}:{name}"`；`type` 为英文标签，前端按 `ontology.js` 映射中文名与颜色；`relation` 为 Cypher 关系名、`label` 为中文名
* 搜索联想 `GET /api/graph/search?kw=`：基于 `dictionary` 做前缀匹配 + rapidfuzz 模糊候选，返回 ≤ 10 条 `{name,type}`（别名命中回链主名）；无结果时前端下拉显示模糊候选列表
* 2 跳子图 `GET /api/graph/subgraph?name=&hops=2&limit=100`：`hops` 只允许 1 / 2，`limit` 上限 100，超出按邻居度数截断并返回 `truncated=true`（前端提示"节点较多，请使用类型筛选"）；孤立节点返回仅含自身的 nodes 与空 links
* 邻居增量 `GET /api/graph/neighbors?name=`：返回该节点 1 跳（≤ 100），前端合并去重后追加到画布，画布总节点仍受 100 上限约束
* **百科页聚合**（`entity_service`，`GET /api/entity/<name>` 一次返回）：`{entity:{name,type,alias[],props{}}, intro, source, relations:[{relation,label,direction,neighbor_type,items:[{name,type}]}], subgraph(1 跳), favorited}`；`props` 只含非空字段，时间字段展示 `time_text`；按七标签依次 `MATCH {name:$name}` 查找，均不存在 → 404
* **实体主名跨标签全局唯一（规范决策）**：`name` 是百科 URL、词典、子图 `id`、收藏 `ref_id` 的唯一键，导入校验（`verify.py`）与后台新增均校验跨标签重名；同名不同物一律以括号注明（如"井冈山（地点）"由别名表处理）
* 时间轴 `GET /api/timeline?period=`：`period` 为时期名；**无参时返回 `{periods:[{name,order,start_year,end_year}], period, events}`**（规范决策：一次请求完成冷启动）；事件 = `(e)-[:BELONGS_TO]->(p:Period)` 的 Event 与 Meeting，按 `time_sort` 升序（仅年 / 仅月条目由补位规则自然排在末尾）；每条附 `brief`（`intro` 首句 ≤ 60 字，规范决策）
* 年份定位：前端按 `start_year ≤ year ≤ end_year` 定位时期页签，滚动到该年首条（`time_sort` 前四位 = 年份），该年无条目则定位到其后最近一条
* 每日学习 `GET /api/daily`：今日推荐 = `random.Random(int(YYYYMMDD)).choice(核心池按 name 排序列表)`，核心池 = `checked=1` 的七类实体（全站当日一致）；历史上的今天 = `time_precision='day'` 且 `substring(time_sort,4,4) = MMDD` 的 Event / Meeting，`today_events` 为空数组时前端整栏隐藏；接口异常首页降级显示固定引导语 + 示例问句
* 导入脚本必须把 Excel `checked` 列写入节点属性 `checked`（0/1），测验与推荐的 Cypher 一律 `WHERE n.checked = 1`
* 图谱数据不做应用层缓存；后台改动后前台三处（问答 / 百科 / 图谱）下一次请求即为最新值

### 6.6 知识测验规范

* 六出题模板（会议→时间 / 会议→地点 / 事件→领导人 / 文献→作者 / 事件→时期 / 组织→沿革或创建）定义在 `quiz_service`，与 V3 7.7 表一一对应；**只从 `checked=1` 核心池取三元组**
* 出题算法：随机选模板 → 核心池随机取三元组 → **答案唯一性校验**（Cypher 计数该题干正确答案 = 1，否则弃用重取）→ 同类型实体抽 3 个干扰项（**排除正确答案及其全部别名**，别名取自 `dictionary`）→ 选项洗牌；某模板可用三元组不足时自动切换其余模板；单卷生成尝试上限 60 次，六模板均不足才返回 500（数据验收后不会发生）
* `GET /api/quiz?n=5|10&entities=a,b`：一次返回整卷 `[{id, question, options:[{key,text}], answer_key, explanation, entity:{name,type}, template}]`；`answer_key` 与 `explanation` 前端持有但不显示；`entities`（规范决策，供"针对错题再练"）非空时优先以这些实体出题，不足 n 题自动补随机题
* 前端逐题即时判分与标色；`explanation` = 对应图谱事实的一句话（如"遵义会议召开于 1935 年 1 月 15 日至 17 日"）+ 百科链接
* `POST /api/quiz/submit`（需登录）：请求携带整卷与作答；**后端以 `answer_key` 与作答复算 `score` / `total`，不信任前端上报的得分**（规范决策）；`detail_json` 存逐题 `{question, options, answer_key, chosen, correct, entity, template}` 与 `duration_sec`
* `GET /api/quiz/records`（倒序分页）、`GET /api/quiz/records/<id>`（详情，错题标红 + 百科链接）（规范决策，FR-U06 所需）；游客试做不写库，"保存成绩"触发登录引导且成绩暂存前端不丢失
* 验收：连续生成 50 题人工审零错题（题干通顺、答案唯一、干扰项不含正确答案及别名）

### 6.7 后台知识管理规范（核心，"后台改前台即时生效"）

**实体写链路**：
```
POST /api/admin/entity {type, name, props}（或 PUT 编辑 / DELETE 删除）
→ 蓝图：@admin_required + 按 ontology[type] 校验必填属性与枚举值域 + 时间字段 timeparse
→ kg_admin_service（Neo4j 显式写事务 + SQLite op_log）：
    新增：跨标签 MATCH {name:$name} 存在 → 422 "实体已存在"（data.type 供前端跳编辑）；MERGE (n:Label {name:$name}) SET n += $props, n.checked = 0
          Event / Meeting 且含 time_sort → 按 period_assign 自动 MERGE (n)-[:BELONGS_TO]->(Period)（规范决策）
    编辑：MATCH (n:Label {name:$name}) SET n += $props（改名时校验新名全局唯一）
    删除：n = 关系数（实时查询）；n ≥ 20 且 confirm_name ≠ name → 422 "高连接度实体需输入名称确认"；DETACH DELETE
→ op_log(admin_id, action, object_type=entity, object_label=类型, object_name, summary=变更摘要 JSON, created_at)
→ dictionary.reload()（新增 / 改名 / 改别名 / 删除时）
→ 返回；前台问答 / 百科 / 图谱下一次请求即为最新
```

**三元组写链路**：
```
POST /api/admin/triple {head, head_type, rel, tail, tail_type, props?}（DELETE 同结构）
→ 校验：头尾实体均存在（否则 422 "实体不存在，请先新增实体"）；(head_type, rel, tail_type) ∈ ontology 头尾约束表（否则 422 "该类型组合不允许此关系"）；head ≠ tail（422）；HELD_POSITION 必填 position
→ kg_admin_service：MATCH 头, 尾 MERGE (h)-[r:REL]->(t) SET r += $props；MERGE 前 OPTIONAL MATCH 已存在 → 422 "该关系已存在"（幂等提示）
→ op_log(object_type=triple, object_label=REL, object_name="head → tail", summary)
```

**强制规则**：
* 所有写操作只能经 `kg_admin_service`，蓝图层不得出现 Cypher；标签 / 关系名只能从 `ontology.py` 白名单取值拼入，属性值一律参数化
* 前端 `TripleForm` 三级联动过滤（头类型 → 允许关系 → 允许尾类型）**与后端约束复校使用同一份 `ontology` 数据**，不允许仅前端过滤
* 时间字段：表单只填 `time_text`，后端用 `timeparse` 派生 `time_sort` / `time_precision`；解析失败 → 422 "时间格式无法识别，请按'1935 年 1 月 15 日'格式填写"，允许管理员改填后重试
* 后台新增的实体 `checked=0`（不进入测验 / 推荐池），经人工校验后在 Excel 校验表标记并重导，或由编辑表单勾选"已校验"置 1（规范决策）
* 双库写序：**先在 SQLite 会话内写 op_log（flush 不提交）→ 提交 Neo4j 事务 → 提交 SQLite**；Neo4j 提交失败则 SQLite 回滚；SQLite 提交失败（极低概率）记录 ERROR 并重试一次。op_log 与知识写操作必须 1:1
* op_log **只可查不可删**（无 DELETE 接口，模型不提供删除方法），是审计属性
* 级联删除提示中的 n 必须实时查询（`MATCH (n)-[r]-() RETURN count(r)`），不得用列表页缓存值
* 删除实体后：前台搜索联想不可见（词典已刷新）、百科 404、图谱不再出现；删除不存在对象返回 404
* 实体管理列表 `GET /api/admin/entity?kw=&type=&page=&size=`：返回名称 / 类型 / 关系数 / 更新时间（`updated_at` 属性由写操作维护，导入时置导入时间）

### 6.8 日志、用户治理与统计规范

* `qa_log` 是问答日志、提问历史、热点统计、LLM 审计的**唯一数据源**；提问历史 = 本人且 `user_visible=1`；后台日志与统计不看 `user_visible`
* 提问历史删除 / 清空为逻辑删除（`user_visible=0`），校验归属；用户删除后管理员日志计数与看板数值**不变**
* 问答日志 `GET /api/admin/logs?fallback=&source=&from=&to=&kw=&page=&size=`：游客显示"游客"；列出 时间 / 用户 / 问句 / 意图 / 命中实体 / 是否兜底 / 回答来源 / 时延；来源为 llm 的记录可展开 `llm_detail`
* 导出 `GET /api/admin/logs/export`：**与当前筛选条件一致**，`utf-8-sig` 编码 CSV，包含回答来源与时延两列，Excel 直接打开无乱码，行数与筛选一致；导出中按钮 loading
* 热点统计 `GET /api/stats/overview` 一次返回全部（`stats_service` 唯一口径）：
  * 高频问句 Top10 = `GROUP BY question`；高频实体 Top10 = `matched_entity` 拆分后计数；意图分布 = `GROUP BY intent`（含 UNKNOWN）；近 30 天趋势按日 `GROUP BY date(created_at)`，**无记录日期补零**；兜底率 = `fallback=1` ÷ 总数
  * LLM 三指标（近 30 天）：调用次数 = `llm_latency_ms IS NOT NULL`；成功率 = `answer_source='llm'` ÷（`llm` + 降级）；平均时延 = `AVG(llm_latency_ms)`
  * "刷新"重新聚合，无缓存
* 后台总览 `GET /api/admin/overview`：实体总数 / 关系总数（Neo4j `count`）、注册用户数、今日问答量（`date(created_at)=today`）；与各管理页数据一致
* 用户管理 `GET /api/admin/users?kw=&page=&size=`：用户名 / 昵称 / 角色 / 状态 / 注册时间；写操作见 6.1 / 6.2
* 收藏：`favorite` 唯一索引 `(user_id, fav_type, ref_id)` 保证幂等（重复收藏返回既有记录，不报错）；`fav_type=entity` 的 `ref_id` 存实体主名，`fav_type=qa` 存 `qa_log.id`；收藏夹问答项展开完整问答并可"重新提问"；被收藏的实体若被后台删除，收藏项显示"词条已删除"并可移除

## 7. 数据与文件操作规范

### 7.1 头像上传统一规范（全项目唯一文件上传）

* 统一入口：前端 `AvatarUpload.vue` + 后端 `POST /api/user/avatar`（multipart，需登录，只能改本人）
* 限制：大小 ≤ 2MB（恰好 2MB 允许，2.01MB 前端拦截不发请求）；格式仅 JPG / JPEG / PNG；前端 canvas 中心裁剪 256×256 JPEG（质量 0.85）后再上传
* 后端二次校验：扩展名白名单 + **文件头魔数**为 JPEG（`FF D8 FF`）或 PNG（`89 50 4E 47`）+ 大小 ≤ 2MB；改名的文本文件被魔数校验拦截
* 存储：`backend/static/avatars/{user_id}.jpg`（**不采用用户原始文件名**，防路径注入；同名覆盖，每用户恒一张，无清理负担）；`user.avatar_path` 存相对路径；响应返回 `avatar_url?t=<时间戳>` 破缓存
* 未上传显示系统默认头像（`static/default_avatar.png`，前端本地资源兜底）；上传失败保留原头像并提示"上传失败，请重试"
* 头像目录不入 Git（`.gitignore`），演示前由脚本清空

### 7.2 数据一致性与事务

* SQLite：SQLAlchemy 每请求一个 session，写操作显式 `commit`，异常 `rollback`；`favorite` 唯一索引、`user.username` 唯一索引由 `models.py` 定义并兜底
* Neo4j：读用 `session.execute_read`、写用 `session.execute_write` 显式事务；批量导入 `UNWIND` 每 500 行一批；**MERGE 语义保证导入与后台新增幂等**
* 双库写序（后台知识管理）：见 6.7；op_log 与 Neo4j 写操作 1:1，任一失败不得出现"有日志无变更"或"有变更无日志"的稳定状态
* 幂等约定：收藏重复 → 返回既有记录；三元组重复 → 422 "该关系已存在"；实体重复 → 422 "实体已存在"；提交测验重复点击 → 前端置灰 + 后端按（user_id, detail_json 哈希, 60 秒）窗口去重
* 逻辑删除：`qa_log.user_visible`（提问历史）；实体 / 关系为物理删除（DETACH DELETE，Neo4j 无软删需求，op_log 留痕）；`op_log` 只增不删
* 金额 / 浮点无关；`time_sort` 存 8 位字符串，禁止存整数或日期类型（补位规则依赖字符串比较与 `substring`）
* 密码任何环节不落明文、不写日志；`.env`、`app.db`、`data/raw/` 不入 Git
* 图谱知识每条带 `source`（来源 URL），后台新增 / 编辑表单 `source` 必填（Location 按 V3 4.1 可空但建议填写）

### 7.3 数据采集与图谱导入纪律（第 2–7 周，课题关键环节）

* 只采集 DR-01~DR-05 的权威官方**公开静态页**；请求间隔 ≥ 2 秒、常规浏览器 UA；原始 HTML **全量留档** `data/raw/`（解析可离线重跑，不二次抓取）；断点续爬 `done.txt`；数据仅用于本课题研究
* 编码：人民网系页面显式 `resp.encoding='gbk'`；全文统一 UTF-8 落盘；全角数字 / 标点归一为半角（DR-02 老页面"１９２１年"）；去 HTML 残留、空白归一；繁体转简体
* 时间三字段制由 `timeparse.py` 唯一实现：`time_text` 保留原文；`time_sort` 取起始日 `YYYYMMDD`，仅月补 `99`、仅年补 `9999`；`time_precision` day / month / year
* 时期归属由 `period_assign.py` 按 `time_sort` 自动归入七时期（建党初期与大革命时期 / 土地革命战争时期 / 全民族抗日战争时期 / 解放战争时期 / 社会主义革命和建设时期 / 改革开放和社会主义现代化建设新时期 / 中国特色社会主义新时代），边界年份人工校验时逐条确认
* 实体名规范：以权威来源全称为主名；简称 / 俗称 / 旧称进别名表 `alias.xlsx`；**别名一对多歧义拒绝入库并记录**；别名表同时用于 jieba 词典、实体链接、测验干扰项排除
* Excel 七表（六实体 + 一关系）+ `alias.xlsx` 为人工校验载体：字段 = 4.1 属性定义 + `source` + `checked` + 校验日期；核心 500 实体 `checked=1`，交叉复核抽 50 零错误方可导入
* 导入 `import_all.py`：`schema.cypher` 先建约束索引 → 实体 `MERGE (n:Label {name:$name}) SET n += $props` → 关系 `MATCH 头, 尾 MERGE`；写入 `checked` 与 `updated_at`；脚本幂等可重跑；`verify.py` 核对各标签 / 关系计数 = Excel 行数，跨标签重名为 0，七 Period 节点齐备且每时期 `BELONGS_TO` 反查非空
* 语料 `paragraphs.csv`：简史分章正文 + 大事记正文按自然段切分，滤除 < 30 字段落，字段 `text, chapter, source`；≥ 2000 段；语料**不提供在线编辑**，更新走脚本重建 + 重启
* 验收线（V3 3.7）：实体 ≥ 1500、关系 ≥ 2500、属性三元组 ≥ 8000、`source` 100%、核心池 500/500、语料 ≥ 2000、自动抽取准确率已统计（抽 200 条）

### 7.4 防重复与并发控制

* 单机部署，Flask 开发服务器多线程；SQLite 单写者由数据库自身串行化，不引入 Redis / 分布式锁
* 写接口防重：前端按钮 loading + 防抖 300ms；后端按 7.2 幂等约定
* 常驻对象（词典 / TF-IDF / 规则表）在 `create_app()` 加载一次并共享；`dictionary.reload()` 采用"构建新表 → 原子替换引用"，读方无锁；Neo4j driver 单例，session 每请求创建关闭
* 登录锁定内存计数单进程有效；qa_log 写入失败不阻断答案；LLM 外呼超时由 requests `timeout` 硬限制，不允许无超时调用

### 8.2 统一返回结构（必须）

```json
{ "code": 0, "msg": "ok", "data": {} }
```

* `code` 约定（FRS 1.5）：`0` 成功、`401` 未登录或登录过期、`403` 无权限、`404` 资源不存在、`422` 参数校验失败或业务规则不允许、`500` 服务异常；**HTTP 状态码与 `code` 同步**（成功 HTTP 200），前端拦截器按 `code` 统一处理
* `msg` 必须可读可直接提示用户（如"该用户名已被占用"、"该类型组合不允许此关系"、"高连接度实体需输入名称确认"）；422 的 `data.errors` 为 `{字段: 中文提示}` 供逐字段红字显示
* 分页统一：`{ "list": [], "page": 1, "size": 10, "total": 0 }`
* 问答响应 `data`（V3 6.3 六字段 + FRS 边界字段 + LLM-Design 4.6 增量，旧字段原样保留）：

```json
{
  "answer_text": "遵义会议召开于1935年1月15日至17日。",
  "intent": "I1", "entities": [{"id": "Meeting:遵义会议", "name": "遵义会议", "type": "Meeting"}],
  "subgraph": {"nodes": [], "links": []}, "fallback": false, "log_id": 1024,
  "candidates": [], "clarify": null, "rewritten_from": null,
  "answer_source": "kg", "fallback_passages": [], "llm": null
}
```

  - `candidates`：未识别实体时的 `[{name,type}]`；`clarify`：槽位不符时 `{text, examples:[]}`；`fallback_passages`：`[{text,chapter,source}]`；`llm`：`{text,cited,latency_ms}`（仅 `answer_source=llm`）；`rewritten_from`：原始问句（仅发生改写）
* 子图结构、百科聚合结构见 6.5；头像上传 `data` 返回 `{avatar_url}`（带时间戳参数）；登录 `data` 返回 `{token, user:{user_id,role,nickname,avatar_url,must_change_pwd}}`
* 时间字段统一 `yyyy-MM-dd HH:mm:ss`（SQLite 侧）；图谱时间只下发 `time_text`（展示）与 `time_sort`（排序），前端不自行解析历史日期

### 8.3 入参校验与错误码

* 后端必须做参数校验（`common/validators.py`，与前端 `validators.js` 规则一致）：
  * 问句：非空、≤ 100 字、非纯符号 / 纯空白；`use_llm` 布尔缺省 false；`prev_q` ≤ 100 字、`prev_a` ≤ 200 字
  * 图谱：`kw` 非空 ≤ 30 字；`hops` ∈ {1,2}；`limit` ≤ 100；`name` 非空
  * 时间轴：`period` 必须是七时期名之一；年份 1921–2021（前端）
  * 测验：`n` ∈ {5,10}；`entities` ≤ 20 个；submit 的整卷题数 = 作答数
  * 账号：用户名 3–20 位 `[A-Za-z0-9_]`；密码 8–20 位含字母与数字；昵称 1–16 字符；头像 JPG / PNG ≤ 2MB + 魔数
  * 分页：`page ≥ 1`，`size` 1–50，越界按默认 / 上限纠正
  * 后台实体：`type` ∈ 七标签；必填属性按 `ontology`；`org_type` / `doc_type` / `time_precision` 在枚举值域；`Period.order` 1–7；`confirm_name` 在关系数 ≥ 20 时必填且相等
  * 后台三元组：`rel` ∈ 十关系；头尾类型组合 ∈ 约束表；`head ≠ tail`；`HELD_POSITION.position` 非空
  * 用户管理：`status` ∈ {0,1}；`role` ∈ {user, admin}；目标 ≠ 自己
* 错误码即 8.2 的六个 `code`，**不另设四位业务码**（FRS 1.5 定稿）；业务规则冲突一律 `422` + 可读 `msg`，前端以 `msg` 提示；需要前端分支的场景通过 `data` 补充结构化信息（如实体已存在 `data.exists_type`、被禁用 `data.reason='disabled'`、须改密 `data.reason='must_change_pwd'`）

### 9.2 关键边界条件（必须覆盖）

* 时间排序：仅年条目（`19359999`）排在当年末尾、仅月条目（`19350199`）排在当月末尾；跨时期边界年份事件归属与人工确认一致

## 总结

1. **闭环优先**：FRS 第五章 12 条闭环 + LLM 2 条闭环必须完整可演示，任一功能都有出口（问答未命中有兜底、实体不存在有 404 页、LLM 失败有降级），不留死链死状态
2. **图谱控答案、后端控核心逻辑**：实体链接、意图分类、Cypher 构建、答案模板、溯源子图、出题、统计口径、知识写入全部由 `qa/` 与 `backend/services` 完成，前端仅做展示与交互；**答案零编造、每条知识可溯源**——图谱命中的答案永不经 LLM，边界外只展示权威原文或受约束、可校验、显式标注的 AI 生成
3. **唯一实现保证一致性**：词典、本体常量、Cypher 模板、子图组装、知识写入口、兜底检索、出题、统计、时间标准化、LLM 外呼各只有一个实现；后台改动经词典热刷新与"无应用层缓存"保证前台即时生效
4. **文档唯一来源**：只维护 FRS / V3 / LLM-Design 三份文档与 `schema.cypher` / `models.py` / `ontology.py` / `sources.md`，禁止多头文档；本文"规范决策"十项须回写
5. **毕设边界不越线**：核心链路零外部依赖、断网单机全功能可演示；LLM 为唯一可选外呼且恒可降级、独立包可物理移除；SQLite / 本地头像 / 内存锁定 / 静态页采集等简化选型必须保证功能闭环正确完整、可现场演示
