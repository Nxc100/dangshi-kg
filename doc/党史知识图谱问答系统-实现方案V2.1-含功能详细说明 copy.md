# 基于知识图谱的党史学习智能问答系统 —— 实现方案 V2.1(Windows 零环境版 · 含功能详细说明)

> 适用前提:开发机为 **Windows 10/11(64 位)**,当前**未安装任何开发环境**,开发者从零开始。
> 本版对 V1 方案逐环节复核,凡在"Windows + 零基础环境"条件下存在安装/编译/网络风险的选型,一律替换为**免安装、有官方 Windows 安装包、或纯 pip 预编译轮子**的方案。未提及的部分(数据来源、本体设计、问答管道细节、论文建议)沿用 V1 文档,两份配合使用。

## 一、本版相对 V1 的修订点(复核结论先行)

| 环节 | V1 选型 | V2 修订 | 修订原因(Windows/零环境复核结论) |
|---|---|---|---|
| 用户数据库 | MySQL 8 | **默认 SQLite(Python 内置,零安装)**,MySQL 降为可选 | 少装一个服务,少一个 3306 端口/服务管理问题;SQLAlchemy 写法完全一致,若导师要求 MySQL,改一行连接串即可 |
| 图数据库 | Neo4j Community | **Neo4j Desktop(Windows 官方安装包,自带 JDK)** | 免去单独安装/配置 Java 环境这一 Windows 上最常见的卡点 |
| 意图分类对比实验 | BERT(Colab 免费 GPU) | **主线仍为规则;对比实验首选 sklearn SVM/朴素贝叶斯(纯 CPU、秒级训练);小型预训练模型(如 3 层 RoBERTa rbt3)作可选项,CPU 即可微调** | 免费云 GPU 在国内网络下不可靠,不能作为方案依赖项;小数据文本分类用轻量模型在 CPU 上完全可行 |
| 模糊匹配 | 编辑距离(python-Levenshtein) | **rapidfuzz** | rapidfuzz 提供 Windows 预编译 wheel,pip 直装,无需 C++ 编译环境 |
| RAG 向量检索 | text2vec + FAISS | **语料仅数千段落,直接用 sklearn TF-IDF / numpy 余弦相似度**;向量模型作可选项(经国内镜像下载) | 消除 FAISS 与大模型文件下载两个潜在环境风险;检索效果对本规模语料足够 |
| 动态页兜底 | Selenium | **Playwright(`playwright install` 一条命令自动装浏览器)或直接用 Edge + selenium** | 免手动匹配浏览器驱动版本;实际预计用不到(目标站为静态页) |
| Python 包源 / npm 源 / 模型源 | 未细化 | **明确配置清华 pip 镜像、npmmirror、HF 国内镜像** | 零环境 + 国内网络下,不配镜像是最常见的"装不上"原因 |

**复核总结论:V1 的技术路线(图谱 + 模板 KBQA + Flask + Vue)在 Windows 下完全成立,所有组件均有官方 Windows 支持;修订仅为"去掉每一个需要额外配置或依赖境外网络的环节",使零基础环境搭建可在 1–2 天内完成。**

## 二、Windows 开发环境从零搭建方案

### 2.1 硬件与系统要求

| 项 | 要求 | 说明 |
|---|---|---|
| 系统 | Windows 10/11,64 位 | — |
| 内存 | ≥ 8 GB | Neo4j 万级三元组 + Flask + 前端 dev server 同开约占 3–4 GB |
| 磁盘 | ≥ 15 GB 可用 | 各软件 + 数据 |
| 网络 | 普通家庭/校园网 | 已为国内网络配置镜像方案 |
| 其他 | 项目放在**纯英文、无空格路径**,如 `D:\graduation\dangshi-kg` | 规避中文路径导致的各类工具异常(Windows 最高频坑) |

### 2.2 安装清单与顺序(共 5 个必装 + 2 个可选,预计 0.5–1 天)

| 序 | 软件 | 版本 | 获取方式 | 必装? | 用途 |
|---|---|---|---|---|---|
| 1 | VS Code | 最新 | 官网 Windows 安装包 | 必装 | 统一开发编辑器(前后端 + 终端) |
| 2 | Python | 3.10 或 3.11(64-bit) | python.org Windows installer | 必装 | 爬虫/抽取/后端/算法 |
| 3 | Node.js | 20 LTS | nodejs.org Windows .msi | 必装 | Vue3 前端 |
| 4 | Neo4j Desktop | 最新(免费,官网填邮箱获激活码) | neo4j.com 下载中心 | 必装 | 图数据库(自带 JDK 与图形界面) |
| 5 | Git for Windows | 最新 | git-scm.com | 必装 | 版本管理(毕设强烈建议,防丢代码) |

### 2.3 逐步安装与验证(每步给出验证命令与预期结果)

**Step 1:VS Code**
- 安装后,后续所有命令都在 VS Code 内置终端(默认 PowerShell)执行,避免 cmd/PowerShell 混用带来的困惑。
- 建议安装扩展:Python、Volar(Vue)、Chinese 语言包。

**Step 2:Python(关键勾选项)**
- 运行安装包时**务必勾选 "Add python.exe to PATH"**,其余默认。
- 验证:新开终端执行 `python --version` → 显示 `Python 3.11.x`;`pip --version` 正常输出。
- 配置国内镜像(一次性):
  ```
  pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
  ```
- 创建项目虚拟环境并激活:
  ```
  cd D:\graduation\dangshi-kg
  python -m venv venv
  venv\Scripts\activate
  ```
  若 PowerShell 提示"禁止运行脚本",执行一次:
  `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`(选 Y),这是 Windows 零环境第二高频坑。
- 安装本项目全部必需包(均有 Windows 预编译轮子,不会触发本地编译):
  ```
  pip install requests beautifulsoup4 lxml jieba pandas flask flask-cors flask-jwt-extended sqlalchemy neo4j scikit-learn rapidfuzz pypinyin openpyxl
  ```
- 验证:`python -c "import requests,bs4,jieba,flask,neo4j,sklearn,rapidfuzz; print('ok')"` → 输出 `ok`。

**Step 3:Node.js**
- 默认安装(自动进 PATH)。验证:`node -v`(v20.x)、`npm -v`。
- 配置国内镜像:`npm config set registry https://registry.npmmirror.com`
- 验证前端脚手架可用:`npm create vite@latest demo -- --template vue` 能生成项目、`npm install` 无报错、`npm run dev` 能在浏览器打开 localhost:5173 默认页 → 前端链路全通。

**Step 4:Neo4j Desktop**
- 官网下载 Windows 版,安装时会要求粘贴免费激活码(下载页邮件发放)。
- 打开后 New Project → Add Local DBMS(选 5.x 版本)→ 设置密码 → Start。
- 验证:点击 Open(Neo4j Browser),执行:
  ```
  CREATE (a:Person {name:'测试'}) RETURN a
  MATCH (n) RETURN n
  ```
  能看到图形化节点即成功;再在 Python 侧验证驱动连通:
  ```python
  from neo4j import GraphDatabase
  d = GraphDatabase.driver("bolt://localhost:7687", auth=("neo4j","你的密码"))
  print(d.verify_connectivity())
  ```
- 说明:Neo4j Desktop 自带受限 JDK,**无需也不要单独安装 Java**;若个别机器上 Desktop 启动异常,备选方案为"Neo4j Community 5.x zip + Adoptium Temurin JDK17",同为免费官方 Windows 包(此为唯一备用路径,写在这里备查)。

**Step 5:Git**
- 默认安装。验证:`git --version`。项目目录 `git init`,每日提交;可再关联 Gitee(国内访问稳定)做云备份。

**Step 6(可选)MySQL:** 若导师要求,装 MySQL 8 官方 Installer(记住 root 密码),项目中把 SQLAlchemy 连接串从 `sqlite:///app.db` 改为 `mysql+pymysql://...` 并 `pip install pymysql` 即完成切换——代码零改动,这正是默认选 SQLAlchemy 的原因。

### 2.5 Windows 专项避坑清单(写进论文"系统实现"更显工程完整性)

1. **路径与编码:** 项目全程英文路径;所有 Python 文件读写显式 `encoding='utf-8'`;导出给 Excel 看的 CSV 用 `utf-8-sig`,否则中文乱码。
2. **终端编码:** 若在终端打印中文乱码,统一用 VS Code 终端并确保文件为 UTF-8;必要时 `chcp 65001`。
3. **端口占用:** 本项目占用 7474/7687(Neo4j)、5000(Flask)、5173(Vite)。冲突时 `netstat -ano | findstr 5000` 查 PID 处理,或改端口。
4. **防火墙弹窗:** 首次运行 Flask/Vite,Windows 防火墙弹窗选择"允许"。
5. **杀毒软件误报:** 个别安全软件会拦截 venv 内 exe,添加项目目录为信任即可。
6. **长路径/权限:** 不要把项目放在 C:\Program Files 或桌面 OneDrive 同步目录下,避免权限与同步锁文件问题。

**结论:上述每一步只依赖官方 Windows 安装包与国内镜像,单人 0.5–1 天可全部完成;环境层面不存在需要编译源码、手工配环境变量或依赖境外网络的环节。**

## 三、系统功能列表与详细说明(全部高可行)

复核原则:每个功能都必须满足 ① 只依赖第 2 节已装环境;② 有明确的"最小实现路径"(即使按最保守方式做也能完成并可演示);③ 有验证方式;④ 若含任何不可控外部依赖,必须降为"开关式可选"。按此原则,对 V1 功能表逐项复核并微调如下。

### 3.1 功能结构总览(角色 × 模块)

系统分**前台(学习者)**与**后台(管理员)**两类角色,共 10 个编号功能模块及若干附属功能:

```
党史学习智能问答系统
├── 前台(学习者:游客即可浏览与提问,注册用户额外拥有历史/收藏/测验记录)
│   ├── F1 智能问答          —— 系统核心:自然语言问,结构化、可溯源地答
│   ├── F2 知识图谱可视化    —— 力导向图交互浏览党史知识网络
│   ├── F3 党史大事记时间轴  —— 按历史时期纵览重大事件("通史式"学习)
│   ├── F4 实体百科页        —— 人物/会议/事件的结构化"数字名片"
│   ├── F5 用户中心          —— 注册登录、提问历史、收藏夹
│   ├── F7 党史知识测验      —— 图谱自动出题,学练测闭环
│   ├── F8 每日学习          —— 今日推荐 + 历史上的今天
│   └── F9 资料检索与AI增强  —— 图谱未命中时的兜底回应(开关式)
└── 后台(管理员,JWT 角色权限控制)
    ├── F6 知识管理          —— 实体/三元组在线增删改查,知识可维护
    ├── F10 热点统计         —— 问答行为数据看板
    └── 附属:用户管理、问答日志查看与导出(见 3.4)
```

权限设计:接口层通过 JWT 中的 role 字段区分 user/admin;前台核心功能对游客开放(便于答辩现场演示,无需先注册),涉及个人数据的操作(历史、收藏、测验记录)要求登录;/api/admin/* 全部要求 admin 角色。

#### 功能清单速览(角色:功能:说明)

**普通用户(前台)**

### 3.3 逐功能详细说明

以下对每个功能给出:功能描述、使用流程、界面要素、后端处理逻辑、涉及接口与数据表、异常与边界处理、验证要点。接口沿用 V1 第七节的 RESTful 设计,数据表结构统一在 F5 中定义。

#### F1 智能问答(核心功能)

**功能描述:** 用户以自然语言提问党史知识,系统理解意图、查询知识图谱并返回答案;答案附"知识溯源"局部子图与可点击的实体链接,做到**答案可解释、知识可跳转**——这是与"搜索引擎给一堆网页"和"大模型可能编造"的本质区别,也是论文立意所在。

**支持的问句类型与示例:**

| 类型 | 示例问句 | 答案形态 |
|---|---|---|
| 属性问答(时间) | 遵义会议是哪一年召开的? | 单值:"1935 年 1 月" |
| 属性问答(地点) | 中共一大在哪里召开? | 单值 + 地点实体链接 |
| 内容/意义 | 八七会议的主要内容是什么? | 属性文本段落 |
| 关系列举 | 南昌起义的领导人有哪些? | 实体列表(可点击) |
| 反向关系 | 《论持久战》是谁写的? | 人物实体 |
| 时期列举 | 抗日战争时期有哪些重大事件? | 事件列表 |
| 简单多跳 | 参加遵义会议的人还领导过哪些起义? | 实体列表 |
| 实体介绍 | 介绍一下古田会议 | 内嵌百科卡片 |

**使用流程:** 进入问答页 → 冷启动区展示 6–8 条"你可以这样问"示例问句(点击即发送,兼顾新用户引导与答辩演示)→ 输入问句 → 对话流出现答案气泡 → 可展开"查看知识来源"显示局部子图 → 点击答案中的实体跳百科页 → 登录用户问句自动记入历史。

**输入/输出定义:** 输入为字符串(前端校验非空、≤100 字);输出 JSON:`{answer_text, intent, entities:[{id,name,type}], subgraph:{nodes,links}, fallback, log_id}`。

**后端处理逻辑(七步管道):** ① jieba 分词(挂载实体自定义词典)→ ② 实体链接:AC 自动机精确匹配,未中则 rapidfuzz 编辑距离 + pypinyin 同音纠错(容错"尊义会议"→"遵义会议")→ ③ 意图分类:关键词规则命中即定(如"哪一年/什么时候"→问时间),多规则冲突按优先级表裁决 → ④ 取该意图的 Cypher 模板,**参数化**填充实体名(防注入)→ ⑤ 查询 Neo4j → ⑥ 结果填入中文回答模板并组装子图 → ⑦ 任一环节未命中 → 转 F9 兜底,响应标记 fallback=true。

**接口/数据表:** `POST /api/qa`;写入 qa_log 表。

**异常与边界:** 未识别到实体 → 提示并给出模糊候选("你是不是想问:遵义会议?",点击重发);实体存在但图谱缺该属性 → 回答"该信息暂未收录",并附实体百科页入口;空/超长/纯符号输入由前端拦截。

**验证要点:** 200 条测试问句端到端准确率 ≥ 80%,八类问句分层抽样人工核对。

#### F2 知识图谱可视化

**功能描述:** 以 ECharts 力导向图交互呈现党史知识网络,支持检索定位、逐跳展开、详情速览,是图谱构建成果最直观的展示窗口(答辩必演示)。

**使用流程与界面要素:** 搜索框输入实体名(联想下拉)→ 画布以该实体为中心渲染 2 跳子图 → 单击节点:右侧抽屉显示属性摘要与"展开邻居"按钮(增量加载)→ 双击节点跳百科页。节点按 7 类实体着色并配图例,边上标注关系名;工具栏支持按类型筛选、缩放、重置。

**后端逻辑与接口:** `GET /api/graph/search?kw=` 前缀 + 模糊匹配返回候选;`GET /api/graph/subgraph?id=&hops=2&limit=100` 用带 LIMIT 的 Cypher 取子图;`GET /api/graph/neighbors?id=` 增量取一跳。单画布节点上限 100,超出提示筛选——保证任何机器上渲染流畅。

**异常:** 搜索无结果给模糊候选列表;孤立节点仅显示自身并提示"暂无关联知识"。

**验证要点:** 任选 20 个实体出图正确、着色与图例一致;万级三元组库下子图接口响应 < 300ms(name 字段建索引)。

#### F3 党史大事记时间轴

**功能描述:** 按"建党初期/土地革命时期/抗日战争时期/解放战争时期/社会主义革命和建设时期/改革开放时期/新时代"等时期分段,以时间轴纵览重大事件,提供"通史浏览"式学习路径,与问答的"点查"互补。

**使用流程:** 顶部时期选项卡切换 → Element Plus Timeline 按时间升序列出事件卡(时间、名称、一句话简介)→ 点击进入百科页;支持输入年份快速定位。

**后端逻辑:** `GET /api/timeline?period=` 查询该时期事件排序返回;入库时把时间预处理为可排序格式(如 1935-01-00),仅有年份的事件排当年末尾。

**异常与验证:** 时期为空显示占位提示(数据校验阶段即保证七时期均非空);验证:各时期顺序正确、跳转正常。

#### F4 实体百科页

**功能描述:** 每个实体的结构化"数字名片",聚合属性、简介、关联知识与局部关系图,是问答、图谱、时间轴、测验各功能的统一跳转落点。

**页面结构:** 头部(名称、类型徽标、别名);属性表(只渲染非空字段);简介段落(标注数据来源);关联实体分组标签区(如会议页分"出席人物 / 形成文献 / 召开地点",点击跳转);局部关系图(复用 F2 组件,1 跳);收藏按钮(登录可用)。

**后端逻辑:** `GET /api/entity/{id}` 一次返回属性 + 按"邻居类型 × 关系类型"分组的关联实体 + 局部子图。

**异常与验证:** 不存在的 id 返回友好 404;抽 20 个不同类型实体核查信息完整、无空字段、跳转正确。

#### F5 用户中心

**功能描述:** 注册登录与个人学习数据管理,支撑历史、收藏、测验记录等个性化功能,并承担全站权限控制。

**功能点:** 注册(用户名唯一性校验;密码用 werkzeug 加盐哈希存储,绝不存明文);登录签发 JWT(含 user_id/role,2 小时过期;前端 axios 拦截器自动携带、过期跳登录);提问历史(倒序列表,一键重问);收藏夹(实体/问答两页签,可取消);退出清 token。

**数据表(SQLite + SQLAlchemy,四张表):**

| 表 | 字段 |
|---|---|
| user | id, username, pwd_hash, role(user/admin), created_at |
| favorite | id, user_id, fav_type(entity/qa), ref_id, created_at |
| qa_log | id, user_id(游客为空), question, intent, matched_entity, answer, fallback, created_at |
| quiz_record | id, user_id, score, total, detail_json, created_at |

**异常与验证:** 重名注册/密码错误/token 过期均返回明确错误码并统一提示;验证:全流程走通、库中密码确为哈希、普通用户访问 /api/admin/* 被 403 拒绝。

#### F6 后台知识管理

**功能描述:** 管理员在线维护图谱知识(纠错、补充、删除),使系统具备"知识可持续运营"能力而非一次性静态数据;"后台修改、前台立即生效"是答辩演示的高光环节。

**功能点:** 实体管理(按名称/类型分页检索;新增实体表单按类型动态渲染属性字段;编辑属性;删除需二次确认并提示将级联删除 n 条关系);关系管理(头实体联想选择 + 关系类型下拉 + 尾实体联想选择,新增/删除);操作日志(who/when/what 落 SQLite,可追溯)。

**后端逻辑:** /api/admin/entity、/api/admin/triple 的 POST/PUT/DELETE,全部校验 role=admin,写操作使用参数化 Cypher(MERGE / SET / DETACH DELETE)。

**异常与验证:** 删除高连接度核心实体强提示;新增重名实体提示合并。验证:后台将某会议地点改错再改回,前台问答两次结果随之变化;日志留痕完整。

#### F7 党史知识测验

**功能描述:** 基于图谱三元组自动生成客观选择题,实现"学—练—测"闭环;**题目只从人工校验过的核心三元组池生成**,从源头保证零错题(党史领域出错题代价高,此为刚性设计)。

**出题模板(首批 5 类,后续可扩展):**

| 模板 | 题干示例 | 干扰项来源 |
|---|---|---|
| 会议→时间 | 遵义会议召开于____ | 其他会议的时间 |
| 会议→地点 | 中共七大的召开地是____ | 其他地点实体 |
| 事件→领导人 | ____领导了秋收起义 | 同时期其他人物 |
| 著作→作者 | 《论持久战》的作者是____ | 其他人物 |
| 事件→时期 | 百团大战发生于____ | 其他历史时期 |

**出题算法:** 随机选模板 → 从核心三元组池随机取一条 → **答案唯一性校验**(以 Cypher 计数确认该题干下正确答案只有 1 个,避免多解争议)→ 从同类型实体随机抽 3 个干扰项(排除正确答案及其别名)→ 选项洗牌输出。

**使用流程:** 选题量(5/10)→ 逐题作答即时判对错 → 显示解析(解析文本即对应图谱事实,如"遵义会议于 1935 年 1 月在贵州遵义召开")→ 交卷出分,错题附百科页链接复习 → 成绩写 quiz_record。

**接口:** `GET /api/quiz?n=5` 出题;`POST /api/quiz/submit` 判分存档。

**异常与验证:** 某模板可用三元组不足时自动换模板,保证任意时刻可出题;验证:连续生成 50 题人工审——题干通顺、答案唯一、干扰项无歧义。

#### F8 每日学习

**功能描述:** 首页轻量学习入口,解决"不知道问什么"的冷启动问题。

**功能点:** ① 今日推荐:以当天日期为随机种子从核心实体池选 1 个(全站当天一致,形成"每日一学"仪式感),展示卡片(名称 + 类型 + 两行简介 + 入口);② 历史上的今天:查询 month/day 与今日相同的事件,有则展示;**无匹配时自动隐藏该栏,只留推荐卡片**——以此消除"多数事件缺精确日期"的数据稀疏风险,功能恒有输出。

**接口与验证:** `GET /api/daily`;修改系统日期连测 10 天,每天均有合理输出、无报错。

#### F9 资料检索与 AI 增强回答(开关式)

**功能描述:** F1 未命中时的兜底与增强,保证"任何问题都有有价值的回应"。双路径:

- **路径 A(保底,零外部依赖,恒可用):** sklearn TF-IDF 对语料库(《简史》全文 + 官网文章分段)检索 top3 段落,按相关度展示**权威资料原文 + 出处**,界面提示"以下为权威资料原文,供参考";
- **路径 B(增强,config 中填入国产大模型 API key 才启用):** 将问句与 top3 段落拼入提示词("仅依据给定资料回答,资料未涉及请回答不知道"),生成式作答;答案上方固定标注"AI 生成,仅供参考",下方可展开所引原文;调用超时(5 秒)或报错**自动回落路径 A**。

**接口:** 复用 `/api/qa` 的 fallback 分支返回。

**验证要点:** 在断网 / 未配置 key 状态下提问未收录问题,路径 A 正常返回段落——以此证明功能不依赖任何外部服务,达成"高可行"。

#### F10 热点统计

**功能描述:** 管理端数据看板,量化系统使用情况;其中"兜底率"指标可反映图谱覆盖度、指导补数据方向,也为论文"系统运行分析"提供素材。

**指标与图表:** 高频问句 Top10(柱状)、高频实体 Top10(柱状)、意图类型分布(饼图)、近 30 天问答量趋势(折线)、兜底率(fallback 占比)。

**实现与接口:** 对 qa_log 做 SQL GROUP BY 聚合,ECharts 渲染;`GET /api/stats/overview` 一次返回全部数据。

**验证要点:** 脚本构造 200 条模拟日志,图表数值与手工 SQL 结果逐项一致。

### 3.4 管理员附属功能

用户管理(列表、禁用/启用、重置密码)与问答日志查看(分页检索、按是否兜底筛选、导出 CSV 供论文统计)。两者均为 SQLite 常规 CRUD + Element Plus 表格,合计 1–2 人日,不单独编号。

### 3.5 非功能性需求(论文"需求分析"章可直接引用)

| 类别 | 指标 | 实现手段 |
|---|---|---|
| 性能 | 问答响应 < 1s;图谱接口 < 300ms | Neo4j name 索引、子图 LIMIT、热点问句缓存 |
| 安全 | 密码哈希存储;接口鉴权;注入防护 | werkzeug 哈希、JWT + role、Cypher/SQL 全参数化 |
| 内容准确 | 核心知识零差错 | 权威来源 + 核心实体 100% 人工校验 + 测验只用校验池 + AI 输出受资料约束并显式标注 |
| 可维护性 | 知识可在线增改并即时生效 | F6 后台直写 Neo4j |
| 易用性 | 零基础用户可上手 | 示例问句引导、错误提示友好、Element Plus 栅格基本自适应 |

### 3.6 需要特别说明的三个关键设计决策

1. **F1 不承诺开放域自由问答。** 系统能力边界=意图模板库覆盖范围,超出即走 F9 兜底(检索原文段落)。在开题报告中即写明该边界,答辩不会被"问啥都要会"的期待反噬——这是问答类毕设最重要的自我保护。
2. **F7 出题只用"人工校验过的核心三元组"**(V1 中承诺 100% 校验的约 500 核心实体),从源头保证题目与答案不出错——党史领域出错题的代价远高于普通领域。
3. **F9 的保底路径(展示权威原文段落)本身就是合格的功能形态**,大模型改写只是体验增强。因此即使完全不接大模型,功能列表也不缺项。
