# 基于知识图谱的党史学习智能问答系统 —— 功能需求文档(FRS V1.0)

> **文档定位:** 本文档是《完整实施方案 V3.0(定稿执行版)》的配套需求文档,将 V3 的十个功能模块(F1–F10)细化为**按角色组织、具体到操作层面**的功能需求条目,并给出**经实际验证的数据采集目标站点**。全部功能均为定稿承诺项(无可选项);每条功能均定义操作流程、输入校验、异常处理、闭环路径与验收标准,保证功能完善、闭环正确、可快速开发。

---

## 一、文档说明

### 1.1 系统目的(需求背景)

系统面向高校学生与党员学习者,将权威党史知识组织为 Neo4j 知识图谱,提供可溯源、零编造的自然语言问答,并配套图谱可视化、时间轴、百科、测验、每日学习等功能,构成"问—学—练—测"闭环;管理员可在线维护知识并查看运行统计。系统零外部 API 依赖,断网单机可完整运行与演示。

### 1.2 阅读对象与配套文档

开发者本人(需求即开发依据)、指导教师(对照任务书检查)、论文"需求分析"章(可直接引用)。技术选型、本体模型、问答管道、周计划见 V3.0 方案,本文不重复,仅在需要处引用。

### 1.3 需求编号与优先级约定

- 编号:FR-G**(游客功能)、FR-U**(注册用户功能)、FR-A**(管理员功能)、DR-**(数据采集需求)。
- 优先级:P0 = 核心必备(中期/答辩必演示);P1 = 完整性功能。**两级均为定稿承诺交付项**,优先级仅决定开发顺序(P0 先行)。
- 每条功能需求含七要素:对应模块 / 前置条件 / 操作流程 / 输入与校验 / 异常与提示 / 闭环说明 / 验收标准。

### 1.4 与 V3.0 方案的增量差异(本文档新增,需同步回 V3)

1. 用户资料管理细化:新增昵称修改(FR-U01)、**头像图片上传(FR-U02)**、修改密码(FR-U03);user 表增加 `nickname`、`avatar_path` 两个字段。
2. 游客可**试做**知识测验(FR-G06):逐题判分在前端完成,"保存成绩"触发登录引导——既开放体验又形成注册转化闭环;正式记录成绩仍要求登录(与 V3 接口权限一致)。
3. 明确 SQLite 共五张表:user、favorite、qa_log、quiz_record、op_log(V3 的 F6 已提及 op_log,此处正式并入表清单)。

### 1.5 统一接口响应与提示规范(全部功能共用)

- 响应结构统一为 `{code, msg, data}`;code 约定:0 成功、401 未登录或登录过期、403 无权限、404 资源不存在、422 参数校验失败、500 服务异常。
- 前端对 401 统一跳转登录页并保留返回地址;403 提示"无权限访问";422 逐字段显示后端返回的中文校验信息;500 显示"服务暂时不可用,请稍后重试"。
- 所有列表接口统一分页参数 `page`(默认 1)、`size`(默认 10,上限 50);所有写接口做防重复提交(前端按钮置灰 + 后端幂等校验)。

## 二、系统角色定义与权限矩阵

### 2.1 角色定义

| 角色 | 编码 | 定义 | 获得方式 |
|---|---|---|---|
| 游客 | R1 | 未登录访问者,可浏览与提问,不可保存任何个人数据 | 直接访问 |
| 注册用户 | R2 | 完成注册并登录的学习者,拥有 R1 全部能力 + 个人数据功能 | 注册(FR-G07),role=user |

## 四、角色功能需求详述

### 4.1 游客(R1)功能

#### FR-G01 首页每日学习浏览(P1,对应 F8)

- **前置条件:** 无。
- **操作流程:** ① 访问系统首页 → ② 顶部展示"今日推荐"卡片(实体名称、类型徽标、两行简介、"查看详情"按钮),卡片以当天日期为随机种子从核心池选取,全站当日一致 → ③ 当日存在 `time_precision=day` 且月日相同的事件时,下方展示"历史上的今天"事件卡列表(时间、名称、一句话简介);无匹配时该栏整体隐藏,不出现空态 → ④ 点击任一卡片跳转对应实体百科页(FR-G05) → ⑤ 首页同时提供问答入口框与 8 条示例问句(点击直达 FR-G02 并自动发送)。
- **输入与校验:** 无用户输入;接口 `GET /api/daily`。
- **异常与提示:** 接口异常时首页降级显示固定引导语与示例问句,不白屏。
- **闭环说明:** 首页 → 百科页 → (页内关联实体/局部图) → 问答/图谱,构成"冷启动 → 学习"闭环起点。
- **验收标准:** 修改系统日期连测 10 天均有合理输出;7 月 1 日、8 月 1 日能命中对应纪念事件;卡片跳转全部正确。

#### FR-G02 智能问答(P0,对应 F1/F9)

- **前置条件:** 无(游客可用;登录用户额外触发 FR-U04 历史记录)。
- **操作流程:** ① 进入问答页,冷启动区显示 8 条示例问句(点击即发送) → ② 输入框键入问句,回车或点击"发送" → ③ 发送后按钮置灰、气泡区显示加载态 → ④ 返回答案气泡:答案文本中的实体渲染为可点击链接(跳百科页);气泡底部两个操作:"查看知识来源"(展开溯源局部子图,复用 F2 组件)与"收藏"(游客点击提示登录) → ⑤ 图谱未命中时,气泡显示固定提示"以下为权威资料原文节选,供学习参考",列出 top3 段落(每段附章节出处),无相关段落时显示引导语与 3 条示例问句 → ⑥ 每次问答后端写入 qa_log(游客 user_id 置空)。
- **输入与校验:** 非空;长度 ≤ 100 字;剔除纯符号/纯空白输入(前端拦截并提示"请输入有效问题");接口 `POST /api/qa`。
- **异常与提示:** 未识别实体 → 返回模糊候选("你是不是想问:遵义会议?",候选为按钮,点击即以纠正后的问句重发);实体存在但属性缺失 → "该信息暂未收录",附该实体百科页入口按钮;服务异常 → "服务暂时不可用",输入内容保留在输入框。
- **闭环说明:** 提问 → 答案 → 溯源子图/实体链接 → 百科页 → 继续提问;未命中 → 兜底段落 → 仍可继续提问;全部问答落 qa_log → FR-A06 日志、FR-A07 统计闭环。
- **验收标准:** 八大类问句各 3 条端到端人工核对正确;三类边界输入(未识别/属性缺失/超长)响应符合定义;fallback 问句返回段落且出处正确;qa_log 逐条落库。

#### FR-G03 知识图谱可视化浏览(P0,对应 F2)

- **前置条件:** 无。
- **操作流程:** ① 进入图谱页,搜索框输入实体名,即时显示联想下拉(前缀 + 模糊候选,`GET /api/graph/search?kw=`) → ② 选中候选,画布以该实体为中心渲染 2 跳力导向子图(`GET /api/graph/subgraph?name=&hops=2&limit=100`),七类实体分色并显示图例,边标注中文关系名 → ③ 单击节点:右侧抽屉显示属性摘要与"展开邻居"按钮,点击增量加载一跳邻居(`GET /api/graph/neighbors?name=`)并追加到画布 → ④ 双击节点跳转百科页 → ⑤ 工具栏:按实体类型勾选筛选、缩放、重置视图。
- **输入与校验:** 搜索词非空、≤ 30 字;单画布节点数上限 100,超出时顶部提示"节点较多,请使用类型筛选"。
- **异常与提示:** 搜索无结果 → 下拉显示模糊候选列表;孤立节点 → 画布仅显示自身并提示"暂无关联知识"。
- **闭环说明:** 搜索 → 出图 → 展开 → 双击进百科 → 百科局部图又可回到图谱页,浏览路径可无限延续。
- **验收标准:** 任选 20 个实体出图正确、着色与图例一致;展开、筛选、重置、双击跳转全部可用;子图接口响应 < 300ms。

#### FR-G04 大事记时间轴浏览(P0,对应 F3)

- **前置条件:** 无。
- **操作流程:** ① 进入时间轴页,顶部为七个历史时期选项卡(按 Period.order 排序) → ② 默认加载第一个时期,Timeline 组件按 time_sort 升序列出事件卡(时间原文、事件名、一句话简介),`GET /api/timeline?period=` → ③ 切换选项卡加载对应时期 → ④ 页内"年份定位"输入框:输入 4 位年份回车,自动切至该年所属时期并滚动定位到该年首条 → ⑤ 点击事件卡跳百科页。
- **输入与校验:** 年份输入仅接受 1921–2021 的 4 位数字,越界提示"请输入 1921–2021 之间的年份"。
- **异常与提示:** 时期数据为空在数据验收阶段已排除;接口异常显示重试按钮。
- **闭环说明:** 通史浏览 → 事件百科 → 关联人物/会议 → 问答点查,与 FR-G02 互补成环。
- **验收标准:** 七时期均有事件且排序正确(仅年条目排当年末尾);年份定位准确;20 次随机点击跳转全部正确。

#### FR-G05 实体百科页浏览(P0,对应 F4)

- **前置条件:** 无。
- **操作流程:** ① 由问答/图谱/时间轴/测验解析/收藏夹任一入口进入 `GET /api/entity/<name>` → ② 页面自上而下渲染:头部(名称、类型徽标、别名标签)→ 属性表(仅渲染非空字段,时间显示 time_text)→ 简介段落(段末标注"来源:xxx"并附 source 链接)→ 关联实体分组标签区(按"关系 × 邻居类型"分组,如会议页分"出席人物 / 形成文献 / 召开地点",标签可点击跳转)→ 局部 1 跳关系图(复用图谱组件)→ 右上角收藏按钮 → ③ 游客点击收藏弹出登录引导;登录用户走 FR-U05。
- **输入与校验:** URL 参数实体名做存在性校验。
- **异常与提示:** 实体不存在 → 友好 404 页("未找到该词条"),附搜索框与热门实体入口。
- **闭环说明:** 百科页是问答、图谱、时间轴、测验、收藏五个功能的统一落点与再出发点(页内标签与局部图均可继续跳转)。
- **验收标准:** 每类实体抽 3 个共 21 页信息完整、来源标注齐全、全部跳转正确;404 页可用。

#### FR-G06 知识测验试做(P1,对应 F7)

- **前置条件:** 无。
- **操作流程:** ① 进入测验页,选择题量(5 题 / 10 题),点击"开始测验",`GET /api/quiz?n=` 一次返回整卷(题干、四选项、正确项、解析——正确项与解析前端持有但不显示) → ② 逐题作答:点选即判分,选项即时标绿(对)/标红(错,同时标出正确项),下方展开解析文本(即对应图谱事实),并附"去百科页复习"链接 → ③ 答完显示成绩页:得分、用时、逐题回顾列表 → ④ 成绩页"保存成绩"按钮:游客点击弹出登录引导("登录后可保存成绩并查看历史错题");登录用户走 FR-U06 → ⑤ "再来一组"按钮重新出题。
- **输入与校验:** 题量仅 5/10 两档。
- **异常与提示:** 出题接口异常显示重试;题目不足由后端自动换模板保证(见 V3 F7)。
- **闭环说明:** 试做 → 解析 → 百科复习 → 再测;"保存成绩"作为注册转化入口接入 FR-G07/G08 → FR-U06,闭环完整。
- **验收标准:** 连续生成 50 题人工审零错题(题干通顺、答案唯一、干扰项不含正确答案及别名);判分与标色正确;登录引导路径可达。

#### FR-G07 账号注册(P0,对应 F5)

- **前置条件:** 未登录。
- **操作流程:** ① 点击导航栏"登录/注册"进入登录页,切换"注册"页签 → ② 填写:用户名、密码、确认密码 → ③ 用户名输入框失焦即调用唯一性预检(`GET /api/auth/check?username=`),重名即时红字提示 → ④ 点击"注册",`POST /api/auth/register` → ⑤ 成功后提示"注册成功"并自动登录(签发 JWT),跳转来源页或首页。
- **输入与校验:** 用户名 3–20 位,仅字母/数字/下划线,全局唯一;密码 8–20 位且同时含字母与数字;确认密码一致;后端重复全部校验;密码以 werkzeug 加盐哈希存储,任何环节不落明文、不写日志。
- **异常与提示:** 重名 → "该用户名已被占用";格式不符 → 逐字段红字提示;网络异常 → 保留已填内容。
- **闭环说明:** 注册 → 自动登录 → 个人中心可见 → 退出后可再登录,与 FR-G08/FR-U07 构成账号全生命周期闭环。
- **验收标准:** 正常注册、重名、弱密码、两次密码不一致四种用例结果符合定义;库中 pwd_hash 非明文;注册后无需再次登录即处于登录态。

#### FR-G08 登录(P0,对应 F5)

- **前置条件:** 已注册且账号未被禁用。
- **操作流程:** ① 登录页输入用户名、密码,点击"登录",`POST /api/auth/login` → ② 成功返回 JWT(载荷 user_id/role/nickname/avatar),前端存储并由 axios 拦截器为后续请求自动携带 → ③ 导航栏切换为头像 + 昵称,显示"个人中心"入口;role=admin 额外显示"后台管理"入口 → ④ token 过期(2 小时)后任一请求返回 401,前端清态跳登录页并保留返回地址。
- **输入与校验:** 两项非空;连续 5 次密码错误后该账号锁定 10 分钟(内存计数即可),提示"尝试次数过多,请稍后再试"。
- **异常与提示:** 密码错误 → "用户名或密码错误"(不区分具体项);账号被禁用 → "账号已被禁用,请联系管理员"。
- **闭环说明:** 登录 → 使用 → 过期/退出 → 再登录;禁用态与 FR-A05 用户管理闭环对接。
- **验收标准:** 正确/错误/锁定/禁用四类用例符合定义;过期跳转并成功回跳原页面;admin 与 user 的入口渲染差异正确。

### 4.2 注册用户(R2)功能(含 R1 全部功能,以下为增量)

#### FR-U01 个人资料查看与昵称修改(P1,对应 F5 细化)

- **前置条件:** 已登录。
- **操作流程:** ① 导航栏点击头像进入"个人中心 → 我的资料" → ② 显示头像、用户名(只读)、昵称、注册时间 → ③ 点击昵称旁"编辑"图标,昵称变为输入框,填写后点击"保存",`PUT /api/user/profile` → ④ 成功后页面与导航栏昵称即时更新。
- **输入与校验:** 昵称 1–16 个字符,过滤首尾空白;默认昵称 = 用户名。
- **异常与提示:** 超长/为空 → 红字提示;保存失败保留输入。
- **闭环说明:** 修改 → 全站显示位置(导航栏、个人中心)同步生效。
- **验收标准:** 修改后刷新页面与重新登录均显示新昵称;非法输入被拦截。

#### FR-U02 头像图片上传(P1,对应 F5 细化;操作层面示例功能)

- **前置条件:** 已登录。
- **操作流程:** ① "我的资料"页点击头像区域(悬停显示"更换头像"遮罩) → ② 触发系统文件选择框,`accept="image/jpeg,image/png"` → ③ 选择文件后前端校验:类型仅 JPG/PNG、大小 ≤ 2MB,不合规即弹提示并终止 → ④ 前端以 canvas 将图片中心裁剪为正方形并压缩至 256×256 JPEG(质量 0.85),页面显示圆形预览与"确认上传 / 取消"两按钮 → ⑤ 点击"确认上传",multipart 提交 `POST /api/user/avatar`,按钮转加载态 → ⑥ 后端二次校验(扩展名白名单 + 文件头魔数为 JPEG/PNG + 大小 ≤ 2MB),文件保存为 `backend/static/avatars/{user_id}.jpg`(同名覆盖,即每用户仅存一张,无清理负担),更新 user.avatar_path,返回带时间戳参数的头像 URL(破缓存) → ⑦ 页面头像、导航栏头像即时刷新;从未上传者显示系统默认头像。
- **输入与校验:** 前后端双重"类型 + 大小"校验;文件名不采用用户原始文件名(防路径注入),统一由 user_id 生成;上传接口校验登录态且只能修改本人头像。
- **异常与提示:** 类型不符 → "仅支持 JPG/PNG 格式";超 2MB → "图片不能超过 2MB";上传失败 → "上传失败,请重试",保留原头像。
- **闭环说明:** 选择 → 预览 → 上传 → 落盘 + 落库 → 全站显示刷新 → 可再次更换(覆盖旧图),闭环完整且存储恒为每用户一张。
- **验收标准:** JPG/PNG 正常上传并全站生效;GIF、超 2MB、伪造扩展名(改名的文本文件,魔数校验拦截)三类非法文件均被拒;更换头像后旧图被覆盖;未上传显示默认头像。

#### FR-U03 修改密码(P1,对应 F5 细化)

- **前置条件:** 已登录。
- **操作流程:** ① "个人中心 → 账号安全"点击"修改密码" → ② 填写原密码、新密码、确认新密码,`PUT /api/user/password` → ③ 后端验证原密码哈希匹配后更新为新哈希 → ④ 成功提示"密码已修改,请重新登录",清除登录态跳登录页。
- **输入与校验:** 新密码规则同注册;新旧密码不得相同。
- **异常与提示:** 原密码错误 → "原密码不正确";其余同注册校验提示。
- **闭环说明:** 改密 → 强制重登 → 新密码可登录、旧密码失效,安全闭环。
- **验收标准:** 四类用例(成功/原密错/新旧相同/弱密码)符合定义;改密后旧密码登录失败、新密码成功。

#### FR-U04 提问历史(P0,对应 F5)

- **前置条件:** 已登录(登录后的每次问答由后端自动写入本人 qa_log,无需用户操作)。
- **操作流程:** ① "个人中心 → 提问历史",倒序分页列表(问句、答案摘要 40 字、是否兜底标记、时间),`GET /api/user/history` → ② 每条两个操作:"重新提问"(携带原问句跳问答页并自动发送)、"删除"(二次确认后 `DELETE /api/user/history/<id>`) → ③ 列表顶部"清空历史"(二次确认,仅删除本人记录的个人可见性,统计用途的 qa_log 聚合不受影响——实现为逻辑删除标记 user_visible=0)。
- **输入与校验:** 分页参数;删除操作校验记录属于本人。
- **异常与提示:** 空态显示"暂无提问,去问一个?"并附问答页入口。
- **闭环说明:** 问答自动入史 → 一键重问回到问答 → 新问答再入史;删除仅影响个人视图,不破坏 FR-A07 统计口径。
- **验收标准:** 问答后历史即时可见;重问自动发送;删除/清空后个人列表消失而管理员日志与统计计数不变。

#### FR-U05 收藏夹(P1,对应 F5)

- **前置条件:** 已登录。
- **操作流程:** ① 收藏入口两处:百科页右上角收藏按钮(fav_type=entity)、问答答案气泡收藏按钮(fav_type=qa,ref 为该条 qa_log id) → ② 点击即收藏,按钮变实心;再次点击取消;`POST/DELETE /api/user/favorite` → ③ "个人中心 → 收藏夹"分"实体 / 问答"两页签,倒序分页;实体项点击进百科页,问答项点击展开完整问答并可"重新提问" → ④ 列表项右侧"取消收藏"。
- **输入与校验:** 同一对象重复收藏幂等(不产生重复记录);取消校验归属。
- **异常与提示:** 空态各页签分别给引导语与入口。
- **闭环说明:** 学习中随手收藏 → 收藏夹回访 → 跳回百科/问答继续学习 → 可取消;按钮状态与列表实时一致。
- **验收标准:** 两类收藏、取消、幂等、跳转全部正确;按钮状态刷新后仍正确。

#### FR-U06 测验成绩保存与错题复习(P1,对应 F7)

- **前置条件:** 已登录;完成一组测验(FR-G06 流程)。
- **操作流程:** ① 成绩页点击"保存成绩",`POST /api/quiz/submit`(题目、作答、得分、detail_json)写入 quiz_record → ② "个人中心 → 测验记录"倒序列表(日期、得分/总题数) → ③ 点击记录进详情:逐题回顾,错题标红并附"去百科页复习"链接 → ④ 详情页"针对错题再练"按钮:以错题涉及实体重新出一组题(不足 5 题自动补随机题)。
- **输入与校验:** submit 校验登录态与数据完整性。
- **异常与提示:** 保存失败提示重试,成绩暂存前端不丢失。
- **闭环说明:** 测 → 存 → 回顾 → 百科复习 → 再练 → 新纪录,"学练测"完整闭环。
- **验收标准:** 保存后记录可查、详情与作答一致;错题链接正确;"再练"可用。

#### FR-U07 退出登录(P0,对应 F5)

- **前置条件:** 已登录。
- **操作流程:** ① 导航栏头像下拉菜单点击"退出登录" → ② 前端清除 token 与用户态,跳转首页 → ③ 导航栏恢复"登录/注册"入口。
- **闭环说明:** 与 FR-G08 构成会话闭环;退出后访问个人接口返回 401 并引导登录。
- **验收标准:** 退出后个人中心不可达(401 跳登录);重新登录后个人数据完好。

### 4.3 管理员(R3)功能(含 R2 全部功能,以下为后台增量;接口统一前缀 /api/admin,服务端强制 role=admin)

#### FR-A01 后台入口与总览(P0)

- **前置条件:** 以 admin 账号登录(初始 admin 由建库脚本预置,密码首次登录后按 FR-U03 强制修改——首登检测标记字段,未改密前仅可访问改密页)。
- **操作流程:** ① 登录后导航栏出现"后台管理"入口,点击进入后台布局(左侧菜单:知识管理 / 操作日志 / 用户管理 / 问答日志 / 热点统计) → ② 后台首页显示四个概览数字卡:实体总数、关系总数、注册用户数、今日问答量(`GET /api/admin/overview`)。
- **异常与提示:** user 角色直接输入后台 URL → 服务端 403、前端提示无权限并跳首页。
- **闭环说明:** 总览数字与各管理页数据一致,是后台各闭环的入口。
- **验收标准:** admin 可达、user 被 403;四个数字与库内实际计数一致。

#### FR-A02 实体管理(P0,对应 F6)

- **前置条件:** FR-A01。
- **操作流程:** ① "知识管理 → 实体"页:顶部检索区(名称关键词输入框 + 实体类型下拉),下方分页表格(名称、类型、关系数、更新时间、操作列) → ② **新增:** 点击"新增实体"弹出表单,先选类型,表单按 V3 4.1 属性定义动态渲染该类型字段(必填项标星),提交 `POST /api/admin/entity`;若名称已存在,提示"实体已存在,是否前往编辑?" → ③ **编辑:** 行内"编辑"打开同款表单回填现值,提交 `PUT /api/admin/entity`(参数化 Cypher SET) → ④ **删除:** 行内"删除"弹二次确认框,明确显示"将级联删除该实体的 n 条关系"(n 实时查询);关系数 ≥ 20 的高连接度实体确认框追加红色强提示并要求输入实体名确认;确认后 `DELETE`(DETACH DELETE) → ⑤ 每次写操作同步写 op_log(操作人、时间、动作、对象、变更摘要)。
- **输入与校验:** 名称非空且类型内唯一;必填属性非空;时间字段格式校验(与三字段制一致);全部写操作参数化。
- **异常与提示:** 校验失败逐字段提示;删除不存在对象返回 404。
- **闭环说明:** **后台改 → 前台即时生效**:编辑某会议地点后,前台该问句答案与百科页随之变化(答辩演示项);删除实体后前台搜索不可见;全程 op_log 留痕对接 FR-A04。
- **验收标准:** "改错再改回"演示前台两次变化正确;级联删除计数准确;高连接度强提示触发;op_log 逐条对应。

#### FR-A03 关系管理(P0,对应 F6)

- **前置条件:** FR-A01。
- **操作流程:** ① "知识管理 → 关系"页:检索区(头/尾实体名、关系类型下拉)+ 分页表格(头实体、关系、尾实体、操作) → ② **新增:** "新增关系"弹窗内:头实体输入联想选择(实名下拉,须选中已有实体)→ 关系类型下拉(**仅列出与已选头实体类型匹配的关系**,按 V3 4.2 头尾约束过滤)→ 尾实体联想(仅列出该关系允许的尾实体类型),提交 `POST /api/admin/triple`(MERGE,重复新增幂等并提示"该关系已存在") → ③ **删除:** 行内删除,二次确认后执行。
- **输入与校验:** 头、尾必须为已存在实体;三元组符合本体头尾类型约束(前端过滤 + 后端复校);自指关系(头 = 尾)拒绝。
- **异常与提示:** 约束不符 → "该类型组合不允许此关系";实体不存在 → 提示先去新增实体。
- **闭环说明:** 新增(人物,参加,会议)后,前台该会议百科页"出席人物"标签区与图谱边即时出现;删除后消失;op_log 留痕。
- **验收标准:** 约束过滤正确(抽 5 组非法组合均被拦);新增/删除后前台三处(问答、百科、图谱)即时一致。

#### FR-A04 知识操作日志(P1,对应 F6)

- **前置条件:** FR-A01。
- **操作流程:** ① "操作日志"页倒序分页列表:时间、操作人、动作(新增/编辑/删除)、对象类型与名称、变更摘要 → ② 顶部按动作类型与日期范围筛选,`GET /api/admin/oplog`。
- **闭环说明:** FR-A02/A03 每次写操作 1:1 产生日志,知识变更可追溯;仅可查不可删(审计属性)。
- **验收标准:** 连续执行增改删各 2 次,日志 6 条齐全且摘要准确;筛选正确。

#### FR-A05 用户管理(P1,附属功能)

- **前置条件:** FR-A01。
- **操作流程:** ① "用户管理"页:用户名搜索 + 分页表格(用户名、昵称、角色、状态、注册时间、操作) → ② **禁用/启用:** 状态开关,二次确认;禁用后该用户下次请求即被拒(登录报"账号已被禁用",在线 token 于过期后失效) → ③ **重置密码:** 行内按钮,确认后系统生成 8 位随机密码(含字母数字),弹窗**仅显示一次**并提示"请复制发送给用户",库中存其哈希;该用户下次登录后引导改密 → ④ admin 不能禁用/重置自己(按钮置灰)。
- **输入与校验:** 操作均校验目标存在;自操作拦截。
- **异常与提示:** 弹窗关闭后随机密码不可再查(只能再次重置)。
- **闭环说明:** 禁用 ↔ FR-G08 登录拒绝;重置 → 用户新密码登录 → 引导改密,账号治理闭环。
- **验收标准:** 禁用后登录被拒、启用后恢复;重置后旧密码失效、随机密码可登录;自操作被拦。

#### FR-A06 问答日志查看与导出(P1,附属功能)

- **前置条件:** FR-A01。
- **操作流程:** ① "问答日志"页分页表格(时间、用户(游客显示"游客")、问句、意图、命中实体、是否兜底) → ② 筛选:是否兜底、日期范围、关键词 → ③ "导出 CSV"按当前筛选导出(utf-8-sig 编码,Excel 直接打开无乱码),`GET /api/admin/logs/export`。
- **闭环说明:** FR-G02 每次问答 → 日志可查可导 → 论文实验统计素材;兜底筛选直接支撑"图谱缺口 → FR-A02 补录"的运营闭环。
- **验收标准:** 构造 200 条模拟日志,筛选计数与 SQL 手工核对一致;导出文件 Excel 打开无乱码、行数与筛选一致。

#### FR-A07 热点统计看板(P1,对应 F10)

- **前置条件:** FR-A01。
- **操作流程:** ① "热点统计"页一次加载五图(`GET /api/stats/overview`):高频问句 Top10(柱状)、高频实体 Top10(柱状)、意图类型分布(饼图)、近 30 天问答量趋势(折线)、兜底率(数字卡 + 环形图) → ② 右上角"刷新"按钮重新聚合。
- **闭环说明:** 数据全部来自 qa_log 聚合,与 FR-A06 明细互为总分;兜底率指标反向指导知识补录(FR-A02/A03),形成"使用 → 度量 → 运营"闭环。
- **验收标准:** 用 FR-A06 的 200 条模拟日志核对:五项图表数值与手工 SQL 逐项一致;刷新生效。

## 六、界面与交互通用需求

1. **页面清单(定稿 7 + 1):** 首页、问答页、图谱页、时间轴页、百科页、登录注册页、个人中心(资料/安全/历史/收藏/测验记录五个子页签)、后台管理(admin 专属,五个菜单页)。全站中文。
2. **通用状态:** 所有异步区域具备加载态(骨架/转圈)、空态(引导语 + 行动入口)、错误态(提示 + 重试);列表统一分页组件。
3. **确认与防误:** 一切删除类操作二次确认;高危操作(高连接度实体删除)输入名称确认;写按钮提交期间置灰防重复。
4. **自适应:** 基于 Element Plus 栅格实现桌面优先的基本自适应(答辩以桌面演示为准)。
5. **一致性:** 实体类型徽标颜色在图谱、百科、搜索联想中全站统一(七色映射表为唯一来源)。
