# 党史学习智能问答系统 —— LLM 增强模块接入方案(LLM-Design V1.0)

> **文档定位:** 本文档是《完整实施方案 V3.0(定稿执行版)》与《功能需求文档 FRS V1.0》的**增量配套文档**,定义一个独立、用户可自主开启/关闭、任何时刻可完全降级的 LLM 增强模块。模块遵循"增量叠加"原则:**开关关闭时,系统的每一处行为与原方案逐字节一致**;开启时仅在原方案已定义的兜底区与多轮场景内提供增强。本文档给出模块的作用、功能、技术设计、评测方法,以及与两份基线文档的逐条融合修订清单(第七章),确保三份文档合一后无任何冲突。

> **与"无可选项"原则的关系(先行澄清):** V3 定稿原则中的"无可选项"指**开发交付层面**不存在待定选型——本模块同样是定稿承诺交付、有完整验收标准的功能,不是待定项。"用户可开启/关闭"属于**运行时的用户偏好**(性质等同于 F8"历史上的今天"无匹配自动隐藏、F1 未命中自动转兜底这类运行时逻辑),二者不矛盾。唯一需要修订的是 V3 中"删除大模型"的历史裁决与"零外部 API 依赖"的表述,修订措辞见第七章。

## 一、模块定位与作用

### 1.1 模块定位

模块名称:**AI 增强模块**(代号 M-LLM);功能编号系列:**FR-L**;优先级 P1(不进中期检查、不占图谱与问答主线);代码形态:独立 Python 包 `llm/`,与 `qa/` 包解耦,整目录移除后系统按原方案完整运行。

### 1.2 模块作用(为什么接、接在哪、不接在哪)

**作用一:提升兜底体验(FR-L02)。** 原 F9 对图谱外问题返回权威原文段落,用户需自行阅读提炼;开启本模块后,LLM 基于这些段落生成一段简洁的直接回答(附资料编号引用与"AI 生成"标注),段落原文仍可展开查证。回答从"给资料"升级为"给答案 + 给资料"。

**作用二:打通多轮追问(FR-L03)。** 原系统单轮问答,"遵义会议是哪一年召开的?"之后追问"在哪里开的?"识别不到实体只能兜底;开启后由 LLM 将追问改写为独立完整问句("遵义会议在哪里召开的?"),**改写结果送回原八步管道**,答案仍由知识图谱产出。LLM 的输出只是问句,零幻觉风险。

**作用三:增厚论文实验(FR-L05,离线)。** 在既有 900 条问句数据集上离线运行 LLM zero-shot 意图分类,使论文对比表升级为"规则 vs 朴素贝叶斯 vs SVM vs LLM"四方法对照;不进入运行链路。

**明确不接入的位置(三条红线,不可突破):**

1. **图谱优先:** F1 命中知识图谱的答案一律按原模板生成返回,不经 LLM 改写、润色或转述——核心问答"零编造、可溯源"的立意不因本模块稀释;
2. **受约束生成:** LLM 仅允许基于系统提供的权威语料段落作答,系统提示词禁止使用外部知识,并有程序化忠实度后校验(4.5 节)兜底;
3. **恒可降级:** 无 key、用户关闭、请求超时(5 秒)、接口报错、后校验不通过——五种情况一律自动回落为原方案行为,用户无感知失败,答辩断网演示与原方案完全一致。

### 1.3 与任务书的关系

导师任务书两大关键模块(图谱构建、问答核心三模块)均不涉及 LLM;本模块是任务书之外的**额外增强功能**,在论文中作为独立一节"基于检索增强生成的兜底优化"呈现,与正文"核心链路采用可控 KBQA 保证准确性"的论证互为支撑:边界内用图谱保准确,边界外用受约束 RAG 保覆盖。

## 二、开关体系与行为矩阵

### 2.1 双层开关设计

| 层级 | 开关 | 控制者 | 载体 | 默认值 |
|---|---|---|---|---|
| 系统层 | `LLM_ENABLED` + API 配置 | 管理员/部署者 | 后端 `.env` 文件(4.2 节) | false(未配置即关闭) |
| 用户层 | "AI 增强回答"拨动开关 | 每个用户(含游客) | 问答页右上角 toggle,状态持久化于浏览器 localStorage(键 `llm_pref`) | 关 |

系统层开关是用户层开关的前提:后端 `GET /api/config` 返回 `{llm_available: true/false}`(仅当 LLM_ENABLED=true 且 key 已配置时为 true);前端仅在 `llm_available=true` 时渲染用户开关,否则完全不出现该控件——未部署 LLM 的环境,界面与原方案一模一样。用户偏好选用 localStorage 而非入库:零表结构改动、游客同样可用、切换即时生效;跨设备同步不作为本期目标(记入展望)。

### 2.2 行为矩阵(定稿,穷举全部组合)

| 系统开关 | 用户开关 | 问句命中图谱 | 问句未命中(兜底) | 多轮追问补全 |
|---|---|---|---|---|
| 关(或无 key) | (控件不显示) | 原模板答案 | 原路径:展示权威段落 | 不启用(原行为) |
| 开 | 关 | 原模板答案 | 原路径:展示权威段落 | 不启用(原行为) |
| 开 | 开 | **原模板答案(不变)** | LLM 生成 + 段落可展开;失败降级为原路径 | 启用;改写失败按原句处理 |

矩阵第一、二行即原方案行为的完整拷贝;第三行的"命中图谱"列仍为原行为——这三处"不变"是"不影响原方案"的形式化表达,也是验收必测项(7.3 回归项)。

## 三、功能需求详述(沿用 FRS 七要素格式)

### FR-L01 AI 增强开关(P1,用户级运行时偏好)

- **前置条件:** 系统层 `llm_available=true`(否则控件不渲染)。
- **操作流程:** ① 问答页右上角显示"AI 增强回答"拨动开关,旁附信息图标,悬停显示说明气泡:"开启后,知识库未收录的问题将由 AI 基于权威资料生成参考回答,并明确标注;可随时关闭" → ② 用户点击切换,状态即时写入 localStorage,**无需刷新页面**,下一次提问即按新状态执行 → ③ 开关状态在会话与刷新间保持;游客与登录用户行为一致 → ④ 每次 `POST /api/qa` 请求体携带 `use_llm: true/false`(前端按开关状态填写);后端以"系统开 ∧ use_llm ∧ 触发兜底/追问场景"三条件共同判定是否调用 LLM。
- **输入与校验:** `use_llm` 缺省按 false 处理;后端不信任前端——系统层关闭时即便收到 `use_llm=true` 也不外呼。
- **异常与提示:** localStorage 不可用(极端浏览器设置)时开关按会话内内存状态工作,不报错。
- **闭环说明:** 开 → 提问体验变化 → 可随时关 → 行为立刻回到原方案;开关状态 ↔ 请求参数 ↔ 后端判定三者一致。
- **验收标准:** 系统层关闭时控件不出现;开/关切换后紧接的提问行为分别符合 2.2 矩阵;刷新后状态保持;后端在系统层关闭时收到 `use_llm=true` 不产生任何外部请求(抓包验证)。

### FR-L02 兜底生成式回答(P1,对应原 F9 的增强层)

- **前置条件:** FR-L01 三条件满足;F1 八步管道判定未命中(fallback 触发)。
- **操作流程:** ① 兜底触发后,后端先按原路径执行 TF-IDF 检索,取 top3 且相似度 ≥ 0.05 的段落(每段截断至 500 字) → ② 若有效段落数 ≥ 1,将段落带编号与问句填入定稿提示词(4.4 节),调用 `llm.chat()`(超时 5 秒) → ③ 生成成功且通过忠实度后校验(4.5 节):答案气泡顶部显示固定徽标"**AI 生成,仅供参考**",正文为生成回答(≤150 字,句末含资料编号如 [1][2]),下方"查看所引权威资料原文"折叠区列出编号段落与出处,编号与正文引用一一对应;前端等待期间显示"AI 生成中…"加载态 → ④ 生成失败/超时/未通过校验:**无感降级**为原路径 A 展示(界面即原方案的"以下为权威资料原文节选,供学习参考"),不弹错误 → ⑤ 无有效段落:与原方案一致,返回引导语与示例问句,不调用 LLM → ⑥ 本次问答写 qa_log,`answer_source` 记为 llm(成功)或 passage(降级),并记录 `llm_latency_ms`。
- **输入与校验:** 提示词中的段落文本做换行与提示注入清理(剔除"忽略以上指令"类模式属于语料侧不可能出现的防御性处理);生成结果长度上限 300 tokens。
- **异常与提示:** 全部异常收敛为降级,用户侧最多感知"这次是原文段落而不是 AI 回答"。
- **闭环说明:** 提问 → 生成回答 → 编号引用 → 展开原文查证 → 可继续提问;失败 → 段落 → 仍可继续提问;来源标记入日志 → FR-L04 审计与统计闭环。
- **验收标准:** 10 条图谱外问题在开启态获得带标注、带编号引用的生成回答,引用编号与所列段落一致;人为断网/填错 key/把超时调为 0.1 秒三种方式各验证一次无感降级;"AI 生成"徽标与折叠原文 100% 出现;qa_log 的 answer_source 与实际路径逐条一致。

### FR-L03 多轮追问补全(P1,问句改写,答案仍出自图谱)

- **前置条件:** FR-L01 三条件满足;当前会话存在上一轮问答(前端随请求携带 `prev_q`、`prev_a` 摘要,仅保留最近一轮,不建服务端会话)。
- **操作流程:** ① 触发判定(满足其一):a. 八步管道第③步实体识别三级全部未命中;b. 问句命中指代词表(它/他/她/这/那/这次/那次/该会议/此人 等)且未识别出实体 → ② 将上一轮问答与本轮问句填入改写提示词(4.4 节),调用 `llm.chat()`(超时 3 秒),要求只输出一句独立完整问句 → ③ 改写结果做安全校验:长度 ≤ 100 字、不含换行、非空;通过后以改写问句**重新走完整八步管道**,响应中附 `rewritten_from` 字段,前端在答案气泡上方以浅色小字显示"已按'{改写后问句}'为你查询",让改写透明可见 → ④ 改写后命中图谱 → 原模板答案(与直接输入该完整问句无异);仍未命中 → 进入 FR-L02/原兜底 → ⑤ 改写失败/超时/校验不过:按原始问句继续原流程(即原方案行为:未识别实体 → 模糊候选或兜底)。
- **输入与校验:** prev_a 截断至 200 字;改写输出如包含多句或解释性文字,取第一句并去除引号,仍不合规则视为失败。
- **异常与提示:** 无新增错误提示,失败路径 = 原方案路径。
- **闭环说明:** 追问 → 改写(透明展示)→ 图谱作答 → 可继续追问;LLM 全程不产出任何事实性内容,答案可溯源性与原方案等同。
- **验收标准:** 设计 10 组两轮对话(时间→地点、事件→领导人等),开启态第二轮正确率相对关闭态显著提升且答案与直接完整提问一致;"已按…查询"提示准确;关闭态 10 组行为与原方案逐条相同(回归)。

### FR-L04 管理端监控与审计(P1,对应 FR-A06/A07 的增量)

- **前置条件:** admin 登录(FR-A01)。
- **操作流程:** ① 问答日志页(FR-A06)筛选区新增"回答来源"下拉(kg / passage / llm),列表新增来源列与时延列;点击 llm 来源记录可展开查看:生成全文、所引段落编号与原文、是否经过降级 → ② 热点统计看板(FR-A07)新增一行三个指标卡:LLM 调用次数(近 30 天)、生成成功率(成功 ÷(成功+降级))、平均生成时延;数据全部由 qa_log 聚合,无新表 → ③ 导出 CSV 包含新增两列。
- **闭环说明:** 每次 LLM 生成全量留痕可审计 → 发现不当输出可定位问句与所引段落 → 管理员处置路径:修订提示词 / 关闭系统层开关(改 .env 重启,分钟级),治理闭环完整。
- **验收标准:** 构造含三种来源的 30 条模拟日志,筛选、展开、导出、三个指标卡与手工 SQL 逐项一致。

### FR-L05 LLM 意图分类离线对比实验(P1,论文实验,不进运行链路)

- **操作定义:** 以第 10 周 900 条标注问句的测试集(270 条),调用 LLM 按 15 类意图定义做 zero-shot 分类(提示词枚举意图与判据,要求只输出意图编号),脚本离线批跑并计算总准确率与宏 F1,并统计与规则法的差异样本做错例分析;结果并入论文对比表形成四方法对照。
- **验收标准:** 实验脚本与结果表入 `eval/`;对比表完成;运行链路代码零改动。

## 四、技术设计

### 4.1 模块架构与调用位置

```
qa/(原八步管道,不改动内部逻辑)                      llm/(新增独立包,可整体移除)
┌───────────────────────────────┐                  ┌──────────────────────────────┐
│ 第⓪步(仅开关全开时挂载):        │──追问改写请求──▶ │ rewrite.py    追问补全        │
│   触发判定→调 llm.rewrite       │◀──改写问句/None──│ generator.py  兜底受约束生成   │
│ ①分词…⑧答案生成(原样)          │                  │ checker.py    忠实度后校验     │
│ 兜底分支:                      │──段落+问句──────▶ │ client.py     chat() 统一外呼  │
│   TF-IDF检索(原样)→调 generator │◀─生成文本/None──│ (超时/异常一律返回 None)       │
└───────────────────────────────┘                  └──────────────┬───────────────┘
        任一处拿到 None ⇒ 走原方案路径                     requests → 国产大模型 API
                                                          (OpenAI 兼容 /chat/completions)
```

集成约定:`qa/` 只在两处以 `try: from llm import ...` 方式引用,导入失败(llm 目录被移除)自动视为系统层关闭——**删除 llm/ 目录 + 还原 .env 即物理回退到原方案**,这是"独立模块"的工程保证。

### 4.2 配置(.env,新增五项;key 不入 Git)

```
LLM_ENABLED=true
LLM_BASE_URL=<厂商 OpenAI 兼容端点>
LLM_API_KEY=<密钥>
LLM_MODEL=<模型名>
LLM_TIMEOUT=5        # 秒;FR-L03 改写调用固定取 min(3, LLM_TIMEOUT)
```

`GET /api/config` 响应:`{"llm_available": true}`(判定 = LLM_ENABLED ∧ KEY 非空;不回传任何配置明文)。

### 4.3 client.py 接口定义(模块唯一外呼出口)

```python
def chat(messages: list[dict], timeout: float, max_tokens: int = 300,
         temperature: float = 0.1) -> str | None
```

requests 直接 POST OpenAI 兼容格式,**不引入任何 SDK,零新增 pip 依赖**;网络异常、非 200、超时、响应解析失败全部捕获并返回 None,同时 logging 记录原因(供 FR-L04 时延与降级统计);降级判断收敛于"是否为 None"一处。

**厂商选型策略(定稿方法而非定稿厂商):** 候选为提供 OpenAI 兼容接口与免费额度的国产厂商(如智谱 GLM、通义千问、DeepSeek、Kimi 等);因免费额度政策变动频繁,**在接入当周(第 14 周)以当期官网政策实测 2 家**,按"免费额度充足、P95 时延 < 5 秒、内容稳定"三条择一定型,结论与测试记录登记 `data/sources.md`。更换厂商只改 .env 三行,不改代码。

### 4.4 提示词定稿(全文,随代码入库 llm/prompts.py)

**兜底生成(FR-L02)系统提示词:**

```
你是党史学习系统的辅助回答助手。严格遵守以下规则:
1. 只能依据下面给出的编号资料作答,不得使用资料之外的任何知识;
2. 资料未涉及或无法确定时,只输出:"根据现有资料无法回答该问题。";
3. 不得编造或推测任何年份、人物、地点、数字;
4. 用简体中文回答,不超过150字,语言平实准确;
5. 回答末尾用方括号标注所依据的资料编号,如[1][2]。
【资料】
[1] {段落1}(出处:{章节/来源1})
[2] {段落2}(出处:{章节/来源2})
[3] {段落3}(出处:{章节/来源3})
【问题】{用户问句}
```

**追问改写(FR-L03)系统提示词:**

```
你是问句改写助手。根据上一轮对话,把用户的新问题改写成一句不依赖上下文、
指代明确、语义完整的独立问句。只输出改写后的问句本身,不输出任何解释;
若新问题本身已完整或与上一轮无关,原样输出新问题。
【上一轮问题】{prev_q}
【上一轮回答】{prev_a(截断200字)}
【新问题】{cur_q}
```

### 4.5 忠实度后校验(checker.py,程序化闸门)

对生成文本执行三项检查,任一不过即整体降级(返回 None 语义):① **年份校验**——正则抽取文本中所有"三或四位数字+年"与日期,逐一验证该字符串出现在所引段落原文中;② **实体校验**——用系统实体词典(含别名)对生成文本做匹配,命中的每个实体名须出现在所引段落中;③ **引用校验**——文本末尾至少含一个 [n] 且 n 在 1–3 范围、对应段落存在;固定拒答句("根据现有资料无法回答该问题。")免于①②直接放行。校验将"提示词约束"升级为"可验证约束",保证**呈现给用户的生成内容中,年份与实体事实均有段落原文支撑**——这是党史领域接入生成式能力的合规底线,也是论文可写的设计点。

## 五、安全与合规设计

1. **密钥安全:** key 仅存 `.env`,已在 .gitignore;后台与任何接口不回显;演示机与开发机各自配置。
2. **内容安全(党史领域特别要求):** 生成仅限对已人工把关的权威语料段落的**受约束改写**,叠加 4.5 程序化后校验与"AI 生成,仅供参考"强制标注,三层控制;生成全文 + 所引段落全量留痕(FR-L04),逐条可审计、可追责;出现不当输出的处置路径明确(修提示词/关总开关),关闭后系统立即回到纯图谱+原文形态。
3. **提示注入面收敛:** 进入提示词的只有三类受控文本——本地权威语料段落、用户问句(限 100 字)、上一轮问答摘要;不拼接任何网页实时内容。
4. **可用性隔离:** LLM 外呼是全系统唯一网络依赖,且被超时与 None 语义完全隔离——外部服务任何故障最多损失"增强",不损失"功能"。
