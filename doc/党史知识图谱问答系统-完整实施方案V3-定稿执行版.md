# 基于知识图谱的党史学习智能问答系统 —— 完整实施方案 V3.0(定稿执行版)

> **文档定位:** 本方案整合 V2 / V2.1 全部内容与导师任务要求,是唯一执行依据。V2 中所有"可选项"均已做出最终决策并写入本文,全文不再保留任何待定选型;每个环节均给出操作步骤、验收标准与验证方法。开发环境为 Windows 10/11(64 位)零基础环境,全流程不依赖任何外部付费服务或境外网络。

## 一、项目概述

### 1.1 系统目的

本系统面向高校学生与党员学习者的党史学习教育场景,将分散于权威文献中的党史知识(重大事件、重要会议、党史人物、组织沿革、经典文献等)组织为结构化知识图谱,并在其上提供自然语言智能问答、图谱可视化浏览、时间轴通史学习、自动知识测验等功能,构成"问—学—练—测"的完整学习闭环。

系统的核心价值主张有三点:

1. **答案权威可靠。** 全部知识来自权威公开出版物与官方网站,核心知识经 100% 人工校验;系统不做生成式编造,图谱未收录的问题以权威资料原文段落回应并标注出处。
2. **答案可解释、可溯源。** 每条答案附带"知识溯源"局部子图与可点击的实体链接,用户可以看到答案在知识网络中的位置并继续探索——这是与"搜索引擎返回一堆网页"和"大模型可能编造"的本质区别,也是本课题的立意所在。
3. **知识可持续运营。** 管理员可在线维护图谱知识(增删改查、操作留痕),后台修改前台即时生效,系统不是一次性静态数据展示。

### 1.4 系统能力边界声明(写入开题报告)

本系统为**限定领域模板式知识图谱问答系统**,能力边界即"15 类意图模板 × 图谱收录知识"的覆盖范围:

1. 边界内:15 类意图(见 6.1.4)覆盖的党史事实性问题,含 2 类固定模式的两跳问题;
2. 边界外:开放域自由问答、观点评价类问题、多于两跳的复杂推理——此类输入统一由 F9 返回权威资料原文段落,并明确提示"以下为权威资料原文节选,供学习参考";
3. 系统不生成图谱与语料之外的任何内容。

该边界在开题报告中即行写明,是问答类课题最重要的预期管理。

## 三、党史数据收集与整理(第 2–6 周,课题关键环节)

1. 只采集上述权威官方来源的**公开静态页面**;不使用开放知识图谱数据,不采集需要登录或动态渲染的页面;

**Step A(第 1 周,试爬验证):** 对 D1–D4 各抓取 1 个样本页,完成"抓取 → 留档 → 解析出目标字段 → 打印"的最小链路。验收:4 个数据源均能稳定解析出预期字段(D1 解析出"日期 + 事件描述";D2 解析出会议名/时间/地点;D3 解析出人物名 + 生平正文;D4 解析出章节正文段落)。此步同时是对"Python + requests + 解析"工具链的首次实战验证。

**Step B(第 3 周,大事记全量):** 抓取 D1 全部页面并解析全部条目,输出 `data/clean/events_raw.csv`,字段:`原文日期文本, 条目正文, 来源URL`。断点续爬:已抓 URL 记录 `done.txt`,中断重启自动续传。验收:条目数量与原文逐年抽查 5 个年份完全一致;CSV 用 `utf-8-sig` 可在 Excel 正常打开无乱码。

### 3.3 数据清洗与标准化规则(定稿)

1. **文本清洗:** 去除 HTML 标签残留、全角/半角统一、连续空白归一;繁体统一转简体。
2. **时间标准化(三字段制):**
   - `time_text`:保留原文时间表述(如"1935 年 1 月 15 日至 17 日");
   - `time_sort`:8 位排序键,取起始日,格式 `YYYYMMDD`;仅到月的补 `99`(如 `19350199`),仅到年的补 `9999`(如 `19359999`),保证"仅年/仅月条目排在当年/当月末尾"且排序无歧义;
   - `time_precision`:取值 `day` / `month` / `year`,供 F8"历史上的今天"仅筛 `day` 精度条目。
3. **时期归属:** 按《简史》篇章划分定稿七个时期(建党初期与大革命时期、土地革命战争时期、全民族抗日战争时期、解放战争时期、社会主义革命和建设时期、改革开放和社会主义现代化建设新时期、中国特色社会主义新时代),依事件 `time_sort` 自动归入,边界年份条目在人工校验时逐条确认。
4. **实体名规范:** 以权威来源中的全称为实体主名;所有简称、俗称、旧称进入别名表(3.5)。

验收:清洗脚本对全量数据跑通无异常;随机抽 30 条核对清洗前后语义无损;时间三字段抽查 30 条全部正确。

### 3.4 三元组抽取与半自动整理流程(定稿)

采用"**规则自动抽取 + Excel 半自动整理**"混合路线——核心实体本就要求 100% 人工校验,直接以 Excel 表为校验载体,一步到位,同时消除"网页解析规则脆弱"这一最大数据风险:

1. **自动抽取(脚本):** 对 D1 事件条目跑规则抽取:日期 → 事件时间三字段;条目内地名词典匹配 → 候选"发生于"关系;条目内人物词典匹配 + 触发词("领导""指挥""发动")→ 候选"领导"关系。输出候选三元组 CSV,置信度分列。
2. **Excel 整理(人工,以脚本产出为底稿):** 在 `data/excel/` 建立六张工作表(人物、组织、事件、会议、地点、文献),列 = 第四章属性定义 + `source` 列;关系单独一张表(`头实体, 关系类型, 尾实体, 属性, source`);候选三元组经人工确认后誊入,属性依据留档原文补全。
3. **抽样评估(论文数据):** 对自动抽取的候选三元组随机抽 200 条人工判对错,报告抽取准确率;该数值写入论文"数据处理"章。

验收:六张实体表 + 一张关系表字段齐全、无空主键、`source` 列 100% 填写;自动抽取准确率完成统计。

### 3.5 别名表构建(定稿)

建立 `data/excel/alias.xlsx`:`别名 → 实体主名` 映射(如"一大 / 中共一大 / 党的一大 → 中国共产党第一次全国代表大会","毛主席 → 毛泽东")。来源:采集文本中出现的变体 + 常识性简称人工补录。该表同时用于:① 生成 jieba 自定义词典;② 问句实体链接;③ 测验干扰项排除。
验收:核心 500 实体每个至少检查一遍是否需要别名;别名无一对多歧义(同一别名只指向一个主名;确有歧义的别名弃用并记录)。

### 3.6 核心实体人工校验规程(第 6 周,质量红线)

验收:500 实体 `checked` 全为 1;交叉复核零错误;校验记录留存(论文可引用)。

## 六、问答系统核心模块设计与实现(第 8–10 周)

问答引擎为独立 Python 包 `qa/`,先以命令行版跑通并通过中期检查,再由 Flask 封装为接口。处理流程为**八步管道**,其中第①–④步构成任务书要求的**问句理解模块**(分词 → 词性标注 → 命名实体识别 → 意图分类),第⑤–⑥步为**查询构建模块**,第⑦–⑧步为**答案生成模块**。

### 6.1 问句理解模块

**① 分词。** jieba 加载自定义词典 `userdict.txt`(由实体表 + 别名表脚本生成,每行 `词条 频次 nz`),确保"八七会议""三湾改编"等专名不被切碎。验证:20 条含专名问句分词结果专名完整。

**② 词性标注。** `jieba.posseg.cut` 输出词/词性序列。用途:(a)识别疑问词(代词 r:"哪、谁、什么")与时间疑问模式,作为意图分类的特征之一;(b)识别动词触发词("领导、参加、召开、写")辅助关系类意图判定;(c)为 6.1 对比实验提供"词 + 词性"组合特征。验证:抽 20 条问句,疑问词与触发词的词性标注符合预期。

**③ 命名实体识别与链接(基于领域词典)。** 三级策略,逐级降级:
1. 精确匹配:分词结果查实体词典(主名 + 别名哈希表,别名回链主名),直接命中;
2. 模糊纠错:未命中时,对问句子串用 rapidfuzz 与词典计算相似度,`ratio ≥ 85` 取最高者(容错"尊义会议 → 遵义会议");
3. 同音纠错:仍未中时,pypinyin 将问句串与词典词条转拼音后精确比对(容错同音错字)。
输出:`[{实体主名, 实体类型, 匹配方式}]`;三级全部未中 → 直接转 F9 兜底并返回引导提示。
论文表述定稿:本模块为"基于领域词典的命名实体识别与实体链接",选型理由为实体集封闭、结果可控可解释;并在论文中与序列标注方法(BiLSTM-CRF)做原理性对比讨论。
验证:构造 60 条测试问句(精确/错字/同音各 20)链接准确率 ≥ 95%。

**④ 意图分类。** 主线为"关键词 + 词性 + 实体类型"三特征联合规则表,按优先级顺序匹配,命中即定;全部未中判为 `UNKNOWN` 转 F9。意图体系定稿 **15 类**:

| 编号 | 意图 | 触发特征(关键词 ∧ 实体类型) | 答案来源 |
|---|---|---|---|
| I1 | 问时间 | 哪一年/什么时候/何时 ∧ 会议/事件/组织/文献 | time_text / found_time_text / pub_time_text |
| I2 | 问地点 | 在哪/哪里/何地/地点 ∧ 会议/事件 | HELD_IN / OCCURRED_IN |
| I3 | 问内容 | 主要内容/内容 ∧ 会议/事件 | content 属性 |
| I4 | 问意义 | 意义/影响 ∧ 会议/事件 | meaning 属性 |
| I5 | 问领导人 | 谁领导/领导人/由谁发动 ∧ 事件 | LED 反向 |
| I6 | 问参会者 | 谁参加/出席/参加者 ∧ 会议 | PARTICIPATED_IN 反向 |
| I7 | 问作者 | 谁写/作者 ∧ 文献 | AUTHORED 反向 |
| I8 | 问作品 | 写了哪些/著作/作品 ∧ 人物 | AUTHORED 正向 |
| I9 | 问人物事迹 | 领导过哪些/参与过哪些 ∧ 人物 | LED 正向 |
| I10 | 时期事件列举 | 有哪些大事/重大事件 ∧ 时期 | BELONGS_TO 反向 |

### 6.2 查询构建模块

将(意图, 实体, 实体类型)映射为参数化 Cypher。**15 个模板与 15 类意图一一对应**,存于配置字典 `INTENT_CYPHER`,实体名一律以参数 `$name` 传入(杜绝字符串拼接,防注入)。I1 类按实体类型分流到对应属性。代表性模板:

```
-- I1 问时间(会议):
MATCH (m:Meeting {name:$name}) RETURN m.time_text AS answer, m.name AS src
-- I2 问地点(会议):
MATCH (m:Meeting {name:$name})-[:HELD_IN]->(l:Location)
RETURN l.name AS answer
-- I5 问领导人(事件):
MATCH (p:Person)-[:LED]->(e:Event {name:$name})
RETURN collect(p.name) AS answer
-- I10 时期事件列举:
MATCH (e)-[:BELONGS_TO]->(t:Period {name:$name})
RETURN e.name AS name, e.time_sort AS ts ORDER BY ts
-- I14 两跳(参加 X 会议的人还领导过哪些事件):
MATCH (p:Person)-[:PARTICIPATED_IN]->(m:Meeting {name:$name}),
      (p)-[:LED]->(e:Event)
RETURN p.name AS person, collect(e.name) AS events
```

槽位校验:意图所需实体类型与③输出不符时(如 I6 配了人物实体),返回澄清提示并给出该实体支持的问法示例,不强行查询。
验证:15 模板各构造 2 条问句在 Neo4j 实测返回正确;注入样例("遵义会议'}) DETACH DELETE (n) //")作为参数传入不产生任何破坏。

### 6.3 答案生成模块

1. **回答模板:** 每意图配中文模板,如 I1:"{name}召开于{time_text}。";I5:"{name}的领导人有:{人物列表}。";列表类答案 ≤ 10 项,超出显示前 10 并注明总数。空值属性(如 content 缺失)回答"该信息暂未收录",附实体百科页入口。
2. **溯源子图:** 将答案涉及的节点与边组装为 `subgraph:{nodes,links}` 随答案返回,前端渲染"查看知识来源";答案中的实体带 `{id,name,type}` 供跳转百科页。
3. **兜底衔接:** 管道任一环节未命中(无实体 / UNKNOWN 意图 / 查询空且无该属性),响应标记 `fallback=true` 并携带 F9 检索结果(见 7.9)。
4. **输出结构定稿:** `{answer_text, intent, entities:[{id,name,type}], subgraph:{nodes,links}, fallback, log_id}`。

验证:八大类问句(时间/地点/内容意义/关系列举/反向关系/时期列举/两跳/实体介绍)各 3 条,命令行版端到端人工核对全部正确;中期检查以此演示。

### 7.1 F1 智能问答(核心功能)

**描述:** 用户自然语言提问,系统经六章八步管道理解、查询并返回答案;答案附溯源子图与实体链接。
**流程:** 问答页冷启动区展示 8 条示例问句(点击即发送)→ 输入问句(前端校验非空、≤100 字、非纯符号)→ 答案气泡 → 可展开"查看知识来源"子图 → 点击实体跳百科页 → 登录用户问句自动入历史。
**接口:** `POST /api/qa`,请求 `{question}`,响应即 6.3 输出结构;每次问答写 `qa_log`(游客 user_id 为空)。
**边界处理:** 未识别实体 → 返回模糊候选("你是不是想问:遵义会议?"点击重发);实体存在但属性缺失 → "该信息暂未收录" + 百科页入口;UNKNOWN 意图 → F9 兜底。
**验证:** 第九章 200 条评测集端到端准确率 ≥ 80%;三类边界输入各 5 条,响应符合上述定义。

### 7.2 F2 知识图谱可视化

**描述:** ECharts 力导向图交互呈现知识网络,答辩必演示项,亦是导师"知识可视化展示"要求的直接落实。
**流程:** 搜索框输入实体名(联想下拉)→ 以该实体为中心渲染 2 跳子图 → 单击节点右侧抽屉显示属性摘要与"展开邻居"按钮(增量加载)→ 双击节点跳百科页。七类实体分色 + 图例,边标注中文关系名;工具栏支持按类型筛选、缩放、重置。单画布节点上限 100,超出提示筛选。
**接口:** `GET /api/graph/search?kw=`(前缀 + 模糊候选);`GET /api/graph/subgraph?name=&hops=2&limit=100`;`GET /api/graph/neighbors?name=`。
**验证:** 任选 20 个实体出图正确、着色与图例一致;孤立节点提示"暂无关联知识";子图接口响应 < 300ms。

### 7.3 F3 党史大事记时间轴

**描述:** 按七个时期分段纵览重大事件,提供"通史式"学习路径,与问答"点查"互补。
**流程:** 顶部时期选项卡 → Element Plus Timeline 按 `time_sort` 升序列出事件卡(time_text、名称、一句话简介)→ 点击进百科页;支持输入年份快速定位。
**接口:** `GET /api/timeline?period=`。
**验证:** 七个时期均非空(数据验收已保证)、排序正确、跳转正常;仅有年份的条目排当年末尾(time_sort 补位规则保证)。

### 7.4 F4 实体百科页

**描述:** 实体的结构化"数字名片":属性、简介(标注来源)、分组关联实体、局部关系图,是各功能统一跳转落点。
**结构:** 头部(名称/类型徽标/别名)→ 属性表(只渲染非空字段)→ 简介(附 source 出处)→ 关联实体分组标签(按"关系类型 × 邻居类型"分组,如会议页分"出席人物/形成文献/召开地点")→ 局部 1 跳关系图(复用 F2 组件)→ 收藏按钮(登录可用)。
**接口:** `GET /api/entity/<name>` 一次返回全部;不存在返回友好 404。
**验证:** 每类实体各抽 3 个共 21 页,信息完整、来源标注齐全、跳转正确。

### 7.5 F5 用户中心

**描述:** 注册登录与个人学习数据管理,承担全站权限控制。
**功能点:** 注册(用户名唯一性校验;密码 werkzeug 加盐哈希,绝不存明文)→ 登录签发 JWT(含 user_id/role,2 小时过期;axios 拦截器自动携带,过期跳登录)→ 提问历史(倒序、一键重问)→ 收藏夹(实体/问答两页签,可取消)→ 退出清 token。
**数据表(SQLite + SQLAlchemy,四张,建表脚本 `backend/models.py`):**

| 表 | 字段 |
|---|---|
| user | id, username(唯一), pwd_hash, role(user/admin), status(启用/禁用), created_at |
| favorite | id, user_id, fav_type(entity/qa), ref_id, created_at |
| qa_log | id, user_id(游客为空), question, intent, matched_entity, answer, fallback, created_at |
| quiz_record | id, user_id, score, total, detail_json, created_at |

**验证:** 注册→登录→提问入日志→收藏→退出全流程走通;库中密码为哈希;普通用户访问 `/api/admin/*` 返回 403;token 过期返回 401 且前端正确跳转。

### 7.6 F6 后台知识管理

**描述:** 管理员在线维护图谱,系统具备"知识可持续运营"能力;"后台修改、前台立即生效"为答辩演示高光环节。
**功能点:** 实体管理(按名称/类型分页检索;新增表单按类型动态渲染 4.1 属性字段;编辑;删除二次确认并提示将级联删除 n 条关系)→ 关系管理(头实体联想 + 关系类型下拉(按 4.2 头尾类型约束过滤)+ 尾实体联想;新增/删除)→ 操作日志(who/when/what 落 SQLite 表 op_log)。
**接口:** `/api/admin/entity`、`/api/admin/triple` 的 GET/POST/PUT/DELETE,全部校验 role=admin,写操作参数化 Cypher(MERGE/SET/DETACH DELETE)。
**验证:** 后台将某会议地点改错再改回,前台问答与百科页两次结果随之变化;删除高连接度实体出现强提示;操作日志完整可查。

### 7.7 F7 党史知识测验

**描述:** 基于图谱三元组自动生成客观选择题;题目只从核心校验池(3.6)生成,源头保证零错题。
**出题模板(定稿 6 类,覆盖组织类实体):**

| 模板 | 题干示例 | 干扰项来源 |
|---|---|---|
| 会议→时间 | 遵义会议召开于____ | 其他会议的 time_text |
| 会议→地点 | 中共七大的召开地是____ | 其他地点实体 |
| 事件→领导人 | ____领导了秋收起义 | 同时期其他人物 |
| 文献→作者 | 《论持久战》的作者是____ | 其他人物 |
| 事件→时期 | 百团大战发生于____ | 其他 Period 实体 |
| 组织→沿革/创建 | 八路军由____改编而来 | 其他组织实体 |

**出题算法:** 随机选模板 → 核心池随机取三元组 → **答案唯一性校验**(Cypher 计数该题干正确答案 = 1,否则弃用重取)→ 同类型实体抽 3 个干扰项(排除正确答案及其全部别名)→ 选项洗牌。某模板可用三元组不足时自动切换其余模板,保证任意时刻可出题。
**流程与接口:** 选题量(5/10)→ 逐题即时判分 → 解析文本 = 对应图谱事实 + 错题附百科页链接 → 交卷记 quiz_record。`GET /api/quiz?n=5`;`POST /api/quiz/submit`。
**验证:** 连续生成 50 题人工审:题干通顺、答案唯一、干扰项不含正确答案与别名,不合格数为 0。

### 7.8 F8 每日学习

**描述:** 首页轻量学习入口,解决"不知道问什么"的冷启动。
**逻辑(自适应,恒有输出):** ① 今日推荐:以当天日期为随机种子从核心池选 1 个实体卡片(全站当天一致,"每日一学"仪式感),该栏必然有内容;② 历史上的今天:查询 `time_precision='day'` 且月日与今日相同的事件,有则展示,无匹配时该栏自动隐藏——以运行时逻辑消除"多数事件缺精确日期"的数据稀疏风险。
**接口:** `GET /api/daily`。
**验证:** 修改系统日期连测 10 天,每天均有合理输出、无报错;含已知纪念日(如 7 月 1 日、8 月 1 日)的日期能正确命中对应事件。

### 7.9 F9 权威资料检索兜底

**描述:** F1 未命中时的兜底,保证"任何问题都有有价值的回应";实现为纯本地检索,零外部依赖,断网可演示。
**实现:** 服务启动时对 `data/corpus/paragraphs.csv`(≥2000 段,3.2 Step D 产出)构建 TF-IDF 矩阵(jieba 分词,词 1–2 元)常驻内存;兜底触发时计算问句与全部段落余弦相似度,取 top3 且相似度 ≥ 0.05 的段落,按相关度展示"权威资料原文节选 + 章节出处",界面固定提示"以下为权威资料原文节选,供学习参考";top3 均低于阈值时返回引导语与示例问句。
**接口:** 复用 `POST /api/qa` 的 fallback 分支(响应含 `fallback_passages:[{text,chapter,source}]`)。
**验证:** 断网状态下输入 10 条图谱外问题(如"延安整风运动的背景是什么"),均返回相关段落或引导语,无报错;返回段落与出处一致。

### 7.10 F10 热点统计

**实现与接口:** qa_log 表 SQL GROUP BY 聚合,ECharts 渲染;`GET /api/stats/overview` 一次返回全部。
**验证:** 脚本构造 200 条模拟日志,五项图表数值与手工 SQL 结果逐项一致。

用户管理(列表、禁用/启用、重置密码)与问答日志(分页检索、按 fallback 筛选、导出 CSV 供论文统计)。SQLite 常规 CRUD + Element Plus 表格。验证:禁用用户后其登录被拒;导出 CSV 在 Excel 打开无乱码(utf-8-sig)。
